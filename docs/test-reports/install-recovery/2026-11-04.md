## 2. 测试范围与计划

覆盖正常安装、升级、重复执行、写入失败与恢复、进程终止、恢复冲突、并发锁、退役命令拒绝、历史文件保护及分发完整性。先执行恢复定向测试，再执行仓库回归与构建产物验证；用户级完整性校验增补后，仅重跑受影响的用户安装测试。

完成标准为上述已确认行为的相应用例通过，现行安装及文档检查入口保持可用。未安排跨平台兼容、网络文件系统、断电模拟或完整业务验收；本报告不生成 Test／Review Gate。

## 3. 测试环境

- Windows 11（10.0.26300），Python 3.14.6，真实本地文件系统及 Python 子进程。
- 基线提交：`c64045efbd6f1496140446339f93faaa767ee8ac`，叠加本轮未提交实现与测试。最终文件哈希见[快照](2026-11-04-snapshot.json)；集成日志包含当次被测源码哈希。
- 写入／恢复 I/O 故障通过测试内 monkeypatch 注入；生产代码不含故障开关。进程中断实际使用子进程 `os._exit`／终止进程，并由新进程重试。并发测试实际启动两个进程，第二个进程使用不同 TEMP／TMP。

## 4. 测试准备与数据

每项使用临时项目与构建目录，构造 AGENTS 定制正文、既有 Skill、历史 Spec／Status、外部修改与损坏恢复记录。用户级安装使用隔离的 skills-dir，未修改真实用户级安装或其他项目。

测试结束清理临时目录；项目锁为持久元数据，但随隔离测试目录一并清理。历史文件按字节比较，安装事务只恢复自身触及文件；测试明确区分锁元数据与目标资源。准备无阻塞。

## 5. 执行与覆盖汇总

最终验证共 74 个不同的 unittest 方法：仓库 49 个、构建产物 25 个，全部通过、失败 0、未测 0、阻塞 0。执行方式为仓库回归 48／48，通过新增完整性测试后用户安装定向 6／6（其中 5 项为重跑，不重复计数）；构建产物 25／25。

另有 validator 的隔离链路检查，包括用户安装／重复安装、项目初始化／升级、只读盘点、两份工具共 12 次旧命令调用、外部修改窗口及不同 TEMP 的并发探针，全部达到预期；这些步骤不计入 unittest 方法数量。

开发期间先后修正临时目录导致锁分离、预检后编辑被重新采样覆盖的两个实现问题，并将其加入测试。一次中间定向运行因测试读取 Windows 正在加锁的字节而报 PermissionError；测试调整为持锁期间检查文件存在、释放后核对字节，最终回归通过。上述中间结果不作为最终通过证据。
