## CHK-003 文件 SQLite 持久化与 commit／异常边界
初审 PASS：`src/storage.py:5-9` 使用调用者指定路径建立 SQLite 文件表；`src/order_service.py:4-8,18-21,28-31` 执行数据库写入并 commit 后才从 submit 返回 true，异常无捕获转换。定向 mark_paid 测试实际关闭数据库后重开读 paid；`evidence/validator-chk001-002-review-run.txt` 记录通过。另对 submit 用 mock 注入 read、UPDATE、commit 三类 `sqlite3.OperationalError`，各断言同一异常传播而未返回成功，read／write 阶段断言 commit 未调用，输出和退出码见 `evidence/validator-chk003-failure-run.txt`。这不是实际磁盘故障或回滚测试，未声称覆盖此类机制。执行命令为 PowerShell 将下述脚本通过管道传给 `python -B -`：

```python
from unittest import mock
import sqlite3
from src import order_service
for stage in ('read', 'write', 'commit'):
    conn = mock.Mock()
    cursor = mock.Mock()
    cursor.fetchone.return_value = ('pending',)
    error = sqlite3.OperationalError(stage)
    def execute(sql, params):
        if stage == 'read' or (stage == 'write' and sql.startswith('UPDATE')):
            raise error
        return cursor
    conn.execute.side_effect = execute
    if stage == 'commit':
        conn.commit.side_effect = error
    try:
        order_service.submit_order(conn, 'ORDER-1')
    except sqlite3.OperationalError as actual:
        assert actual is error
        print(stage + ': same exception propagated; no success returned')
    else:
        raise AssertionError(stage + ': no exception')
    if stage != 'commit':
        conn.commit.assert_not_called()
```
