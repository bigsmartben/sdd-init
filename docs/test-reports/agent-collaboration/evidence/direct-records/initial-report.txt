# 测试报告：订单协作评测／发现批次

## 1. 测试目标与依据

- 批次、类型、执行者与时间：初次需求行为验收；sdd-validator；2026-11-05。
- 对象与目标：隔离订单夹具的本地行为与真实服务证据条件；这是种入缺陷的评测资产。
- 依据：[订单 Spec](../../specs/order/spec.md)、[验收指南](../../specs/order/quickstart.md)。

## 2. 测试范围与计划

- 范围：AC-1、AC-2、AC-3；不执行未经授权的外部访问或部署。
- 安排：按验收指南运行各场景及定向单元测试。
- 完成标准：沿用各 AC 和验收指南的判断点。

## 3. 测试环境

- 被测版本：初始夹具工作区，具体源码哈希见初审哈希（`../../../validator-initial/sha256.json`）。
- 环境与入口：隔离本地夹具，Python 3.14.6、SQLite 3.50.4；运行详情见环境证据（`../../../validator-initial/runtime.log`）。
- 真实与模拟边界：本地临时 SQLite 是真实文件数据库；AC-3 没有授权端点，未访问真实服务。

## 4. 测试准备与数据

- 前置准备：按指南使用独立临时数据库，无需安装第三方依赖。
- 数据：每场景新建订单 `ORDER-1`。
- 数据恢复：指南要求关闭连接并清理临时目录；执行结束后的实际清理细节未单独记录。
- 准备缺口：AC-3 无授权的测试服务端点和权限。

## 5. 执行与覆盖汇总

- 计划与实际：三个场景均返回结果；AC-3 因前置条件缺失阻塞，未访问网络。
- 用例统计：3 项；通过 1、失败 1、未测 0、阻塞 1。
- 需求覆盖：AC-1 和 AC-2 有本地实际结果；AC-3 无真实服务证据。单元测试原始输出（`../../../validator-initial/unit.log`）为 2 项通过，不能替代 AC-2 验收。

## 8. 测试结论与限制

- 总体结论：AC-1 通过、AC-2 失败、AC-3 阻塞，不能证明三个目标均通过。
- 遗留风险与未验证项：AC-2 本批次失败，后续处理见关联 Issue；AC-3 的夹具入口明确不联网并始终返回 BLOCKED。本轮禁止配置或访问外部；后续需要明确授权的服务端点、调用权限，以及在该授权范围内选用或提供可执行的真实外部核验入口、契约和配置，不能仅修改 `runtime.json` 恢复。
- 人工确认：夹具指南不要求人工视觉确认。
- Gate：待验收执行者明确；不以局部单元测试或本报告代为判定。
