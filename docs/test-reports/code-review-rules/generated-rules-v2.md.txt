# Code Review Rules

## CRR-001 · 订单状态写入职责

- 设计依据：[Blueprint ARC-1](blueprint.md#架构边界)、[订单函数契约](contracts/order.md)。
- 项目约束：订单状态由 `order_service.write_status` 写入，`ui` 调用服务，不直接执行状态写入 SQL。`storage` 负责连接和建表；`mark_paid` 经 `write_status` 写入 paid。
- 适用条件：修改订单状态写入、`mark_paid`、服务接口、数据库访问或可能改变其调用路径的装配。
- 取证路径：从 `mark_paid` 等状态操作入口追踪至服务写入及数据库调用，核对所有可达状态写入分支及 `storage` 的职责。
- 违反条件：UI 或其他非服务入口直接写订单状态，或 `mark_paid` 绕过 `write_status`。

## CRR-002 · 订单持久化与失败边界

- 设计依据：[Blueprint ARC-2](blueprint.md#架构边界)、[订单函数契约](contracts/order.md)。
- 项目约束：订单持久化到文件 SQLite；写入并 commit 后才能视为提交完成，数据库异常向上传播。
- 适用条件：修改数据库连接、订单状态写入、提交或异常处理。
- 取证路径：从服务提交入口追踪数据库连接、写入、commit 和异常返回分支，结合可检查的数据库结果。
- 违反条件：只使用内存或普通文件代替文件 SQLite，写入或 commit 未完成即返回提交成功，或数据库异常被转为成功。

## CRR-003 · 正式与验证资产依赖

- 设计依据：[Blueprint ARC-3](blueprint.md#架构边界)。
- 项目约束：`checks` 与 `tests` 调用 `src`；`src` 不依赖测试运行器、测试身份或夹具配置。
- 适用条件：修改正式模块、测试装配、导入或运行配置。
- 取证路径：检查 `src` 正式入口及模块的静态引用、动态加载和配置装配，再核对验证资产的调用方向。
- 违反条件：正式运行依赖或启用测试运行器、测试身份或夹具配置。

## CRR-004 · 本地调用边界

- 设计依据：[Blueprint ARC-4](blueprint.md#架构边界)、[订单函数契约](contracts/order.md)。
- 项目约束：本地订单函数不进行外部调用；真实外部服务的证据依赖单独授权和配置。
- 适用条件：修改订单函数、依赖装配或外部连接配置。
- 取证路径：检查本地入口、传递依赖及可达调用分支，追踪网络访问和相关配置。
- 违反条件：本地订单行为调用外部服务，或改写本地逻辑模拟真实外部服务证据。
