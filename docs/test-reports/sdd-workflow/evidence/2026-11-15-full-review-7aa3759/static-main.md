## Main、阶段与调用

治理“职责与交接”“选择工作流”“直接执行局部操作”“直接委派专业角色”按交付终点选入口，允许合格直派而保留确认与验证，未要求机械逐层进入。阶段授权明确多阶段显式授权可接续，仅暂停关联依赖。委派“技能 Agent 的启动与接续”要求独立上下文、实际调用者和原阶段接续，同层事项由共同上层组织；“角色独立执行”禁止角色加载 Skill 或调度同层，合格输入可来自任意来源。各 Skill 的跨阶段发现交 Main，与共享回执契约一致。静态符合 RW-01/02/04/07/08/09/10/11/12；实际调用与接续须另看行为证据。

## 权威与证据

治理“权威实体”“证据与复用”“验收计划与方案”“Issue 关单”及 document-writing 的取证/归并/同步和对象表，区分业务/架构、设计/运行、局部/集成、原型/正式；保留前提例外、编号和历史。缺必需人工反馈保持待验。Code Review Rules 维护须用户发起，设计归并不强制架构门禁。静态符合 RW-03/05/06/07/08/10/12。

## 模板逐一核对

- Blueprint：高位 PUC/PAC、职责/不变量、待决及内部一致性，详细行为和结果引用 Spec/报告。
- Spec：可用已确认工单，不强制完整蓝图；FR/AC、异常边界、可观察质量指标及原型确认有承接。
- Plan：同一Task清单、依赖无环、原工单判据、局部验证和待验项，不替代上层验收。
- Test Report：局部可简记、集成用完整结构，计数/覆盖/版本/失败/人工反馈与Gate分开。
- Architecture Review Record：原检查项、独立判据与改前事实、Task引用、架构复核及行为保持分别取证。
- Status：引用实际报告与候选，不迁移历史；接续状态按治理维护。
- Issue：原编号、归因、方案引用、历史及关单依据；平台动作仍需授权。
- Quickstart：范围内全部已确认功能的操作、预期、环境、数据和必要复位，实际结果归报告。
- Delivery Record：授权终点、源/制品/运行关联、实际回读及恢复缺口。
- Research：候选、证据、建议和确认分开，已确认决定归 Blueprint/ADR。
- Interface Contract：调用双方、状态/副作用归属、受理/完成、失败恢复按适用性记录。
- Scenario Sequence：只画实际保证的顺序/等待、未知不作成功，结果归报告。
- Prototype Reference：预览和源码固定版本、模拟范围、确认来源、替代关系。
- Code Review Rules：项目确认依据、对象条件、检查入口、通过/违规及时机，推荐策略不自动成门禁。

## 实际入口与评审 Skill

README、项目文档索引及初始化器 agents-fragment/communication-fragment 提供阶段与角色的导航引用。分发正文目录只有六份实际工作流 SKILL.md；遗留空目录无加载正文。安装/注册生成机制在排除范围，源码导航可定位不证明目标环境已安装。

评审 Skill 仅显式启动，审查不授权修复；静态先行、最小隔离场景、A/B触发、同批归并、版本及成本边界与 FR/AC-033/034 一致。36子项与 S1-S8/I1-I3、Spec引用可追溯，模板不把成本缺项变为实跑理由。评审自身行为选择 workflow_review_targeted；review-prompt 新模型配置另作一例只读工单，未以旧模型通过替代当前配置。

## 结论与限制

本工单范围静态符合，无确证源码缺陷。静态和机械检查不证明实际执行、角色只读权限或真实系统验收。行为结论按新单例和经过适用性核对的历史原始记录限定。
