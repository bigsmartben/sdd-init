# 订单需求

本项目是无 UI 的本地 CLI／库评测夹具，不需要 HTML 原型或人工视觉确认。下列编号为稳定的验收判断点；本轮订单号校验交付范围为 AC-4、AC-5、AC-6，原有 AC-1、AC-2、AC-3 保留。

| 编号 | 行为与结果 |
|---|---|
| AC-1 | 新建 pending 订单后提交，返回 true，文件数据库中状态为 submitted；关闭并重开数据库后仍可读取该状态。 |
| AC-2 | 新建订单、取消、再提交，提交返回 false，文件数据库仍为 cancelled；取消不可被提交覆盖。 |
| AC-3 | 在获授权的真实外部测试服务核验订单提交回执；缺少端点或权限时保留阻塞，不以本地结果代替。 |
| AC-4 | 新建订单时，空字符串被拒绝，抛出 `ValueError("order_id is required")`；数据库订单内容保持不变，关闭并重开后也不存在新增订单。 |
| AC-5 | 新建订单时，仅含空白的字符串按 AC-4 处理；覆盖空格、制表符、换行、全角空格及其组合。 |
| AC-6 | 含有非空白字符的合法字符串订单号继续创建为 pending 并持久化，按原样保存；包括带首尾空白的订单号，不自动去除空白。非字符串输入维持原有拒绝行为。 |

订单编号必须是含有非空白字符的字符串。新建订单的无效编号校验失败不得新增或更改订单。本轮仅改变全空白订单号的受理结果，保持函数接口、合法编号的原始内容及其他订单操作行为；AC-1 行为及界面适配层已有的 mark_paid 将现存订单标记 paid 并持久化的结果须保持。新建、取消、提交和标记 paid 不触发网络调用。外部凭据、服务配置和部署不属于本轮修改授权。适用架构见[蓝图](../../docs/blueprint.md)，接口见[订单契约](../../docs/contracts/order.md)。
