# Parser 用户验收复跑指南

## 1. 验收目标与范围

依据 [Parser Spec](../../specs/parser/spec.md)，全部产品范围为 AC-1、AC-2。主要路径为本地 Python CLI 接收一个参数并输出 JSON 列表；验收脚本经真实产品入口 `python -B src/cli.py` 调用。空参数为已确认边界，两成员拆分及顺序为已确认正常场景；不扩展新的业务数据或判据。

## 2. 版本与准备

- 本批次目标提交：`1c3106074c347409f96bbdddad35f5013e4096e4`。复跑前在项目根目录执行 `git rev-parse HEAD`、`git status --short`，核对源码、验收脚本、规格及数据有无变化，变化后重新判断旧证据适用性。
- 环境：本地 Python 3；本批次实际为 Python 3.12.3，仅标准库，无外部服务。
- 在项目根目录运行。先执行 `mkdir -p docs/test-reports/parser`，脚本会向该目录的 `calls.jsonl` 追加原始回执，不会自动建立目录。
- AC-1 使用脚本内既有空字符串数据，不需准备业务文件。
- AC-2 必须由数据负责人提供已批准数据文件 `data/approved-batch.txt`，对应规格中的 `red,blue`。当前尚未提供；保持待验，不自行创建或选择替代数据。数据到位时核对来源、批准状态及内容，脚本读取后调用 `.strip()`，期望值仍为 `['red', 'blue']`。

## 4. 恢复与复位

场景仅读取业务数据，不需业务状态复位。保留原始追加日志，不清空或编辑历史行。AC-2 数据由负责人补齐并核对后复跑原入口；若仍为同一实现、方法和环境，可复用 AC-1 证据，否则分析影响并补验。数据缺失是前置阻塞；实际输出不符时按原判据记录失败，不改脚本、实现或期望值。
