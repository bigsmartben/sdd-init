# BUG-001 — 取消订单后仍被提交

## 事实与恢复工单

- 类型：已证实实现缺陷。依据：[Spec AC-2](../../specs/order/spec.md)、[函数契约](../contracts/order.md)。原场景入口为 `order_service` 公开函数；文件 SQLite 实测。
- 2026-11-15，Bugfix 技能 Agent `/root/bugfix` 初次取证；现有索引和项目文档无原 Issue，故登记本编号。
- 前置：临时文件数据库，新建 `ORDER-1`，取消，再提交，关闭并重开数据库。预期返回 false、状态 cancelled；实际 true、submitted。直接影响取消不可覆盖保证。
- 已验证根因：`src/order_service.py` 的 `submit_order` 调用 `read_status` 后忽略结果，无条件调用 `set_status(..., "submitted")`。若为持久化读写错误，则关闭重开可能无法复现写入；实际重开为 submitted，与无条件写入一致。
- 初始版本：`src/order_service.py` SHA-256 `96844b5faba169a28c5f4cfb877a9644b83e81f0e63f5b726de525294a69f6de`。Python 3.12.3 / SQLite 3.45.1。原始失败命令：`python -B checks/acceptance.py --scenario AC-2`，退出 1。
- 授权：用户要求修复取消后仍提交；保持已确认接口、AC-1 和现有 paid 行为。产品改动仅限该缺陷；不做 Git、外部调用或部署。实现方案与任务归 [Plan](BUG-001-plan.md)。

## 验收计划与方案

实施者局部自验后，由 `/root/bugfix` 在实际修复版本定向复验，使用真实临时文件 SQLite，按下列步骤判定：

| 检查 | 步骤与观察 | 通过判据 |
| --- | --- | --- |
| 原故障 AC-2 | 新建、取消、提交，关闭重开后读取状态 | 返回 false，重开后 cancelled；取消分支没有数据库写入 |
| AC-1 回归 | 新建 pending 后提交，关闭重开读取 | 返回 true，重开后 submitted |
| 保持行为 | 运行现有 paid 持久化测试；检查公开函数签名及不存在订单的异常 | paid 持久化仍成立，函数签名不变，不存在订单抛 ValueError |

AC-3 不属于本缺陷关闭判据；本地未配置授权外部端点，不能用本地复验代替外部回执。整产品 Test Gate 和架构 Review 由 Main 独立安排。
