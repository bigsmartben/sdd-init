# BUG-002 — mark_paid 对不存在订单未抛 ValueError

## 1. 问题事实

- 类型：已实测的产品实现缺陷，沿用[订单契约](../contracts/order.md)“不存在的订单抛出 ValueError”，不增加业务语义。
- 初次正式发现：2026-11-15，独立集成执行者 `/root/integration`，批次 order-integration-01，[报告 I05](../test-reports/order/integration.md)。
- 实际候选：`sha256:7d4083da88ed6593bc2039b890b0026681f522ac7b53d7aa8c8dcde4cb269fea`；`src/ui.py` SHA-256 `89ef1238b40556d5a7b3dc93daeeb1a04b68a600c7c985d648a80a66f84cb25b`。环境 Python 3.12.3、SQLite 3.45.1、真实临时文件数据库。
- 复现：从项目根运行 `python -B -m unittest discover -s tests -p test_order_integration.py -v`，I05 的 mark_paid 子场景 FAIL。新建空文件数据库后调用 `ui.mark_paid(connection, "missing")`，预期抛 ValueError，实际无异常并返回 None，数据库仍不存在该订单。
- 影响：调用方不能通过契约规定的异常识别该适配入口操作不存在的订单；现存订单 paid 持久化不受此发现否定（I04 PASS）。这属于可观察功能偏差；内部写入职责的架构偏差由独立 Review 判定。
- 证据：[测试原始输出](../test-reports/order/integration-integration.json)、[针对性公开入口观察](../test-reports/order/integration-bug002.json)、[候选前后哈希](../test-reports/order/integration-identity.json)。
