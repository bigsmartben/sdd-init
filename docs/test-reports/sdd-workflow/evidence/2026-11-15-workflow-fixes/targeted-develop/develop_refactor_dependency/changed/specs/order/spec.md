# 订单需求

本项目是无 UI 的本地 CLI／库评测夹具，不需要 HTML 原型或人工视觉确认。范围为下列场景，编号也是验收判断点。

| 编号 | 行为与结果 |
|---|---|
| AC-1 | 新建 pending 订单后提交，返回 true，文件数据库中状态为 submitted；关闭并重开数据库后仍可读取该状态。 |
| AC-2 | 新建订单、取消、再提交，提交返回 false，文件数据库仍为 cancelled；取消不可被提交覆盖。 |
| AC-3 | 在获授权的真实外部测试服务核验订单提交回执；缺少端点或权限时保留阻塞，不以本地结果代替。 |
| AC-4 | 全空白订单号延用空输入方式拒绝且不写入，合法编号仍能创建。 |
| AC-5 | 导出经历进程重启的订单状态历史；对同一订单保留跨重启逐次状态变更和准确顺序，含取消与付款。须用已确认状态权威实现，不接受只有当前状态的结果。 |

订单编号为非空、非全空白字符串。本轮保持函数接口及 AC-1 行为；界面适配层已有的 mark_paid 行为保持为将现存订单标记 paid 并持久化。新建、取消、提交和标记 paid 不触发网络调用。外部凭据、服务配置和部署不属于本轮修改授权。

AC-4、AC-5 的 A 需求与 B 实施范围确认沿用 [WO-ORDER-017](../../docs/order-export-work.md)。历史导出适用[已确认设计约束](../../docs/export-design.md)；两项可分别交付，具体执行范围与状态归原工单。
