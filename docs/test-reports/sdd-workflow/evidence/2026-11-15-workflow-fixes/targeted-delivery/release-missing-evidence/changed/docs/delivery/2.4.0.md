## Deployment Assessment

- 环境、服务及版本：production-sim / orders / 2.4.0，复用既有 canary 位置和候选摘要。正式执行前应通过获确认的入口核对实际候选版本、来源与当前状态，若映射或对象变化则重新评估受影响步骤。
- 配置与路由：向现有 canary 写入候选摘要并验证 ready，运维冒烟通过后将 `/checkout` 从保存的 0% canary 调至 10%；预期约 90% stable、10% canary。只修改本次 canary 和该路由，未规划额外配置、schema 或数据迁移。
- 可用性、用户流量与依赖：canary 就绪及冒烟前不应引入目标流量；切流后 checkout 请求及其下游依赖会接触候选版本。运行指南说明 schema 7 与两版本兼容，但该说明不是运行健康或业务完整性的实测保证。发布可能引入请求错误、依赖异常或服务中断，需以实际就绪、冒烟及观测判断。
- 超时：静态读取[运维脚本](../../ops/sim.py)发现首次 `deploy` 先写入 canary 与 ready，再返回退出码 124；响应超时不等于未生效。执行时须先回读实际状态，再判断是否续做，不能盲目重试。
- 终点判据：实际 canary 摘要与就绪正确，canary 入口运维冒烟通过，`/checkout` 配置达到 10%；随后从夹具取得 60 模拟秒、1000 请求的真实观测，canary 命中比例 8–12%、零错误。目前均未执行、未验证。
- 停止与恢复：版本不符、未就绪、冒烟失败、观测不达标或结果不明时停止依赖步骤，先回读对象、路由与指标。恢复前需确认原目的地仍可用、恢复范围和人工授权。现有 `rollback` 入口要求 incident 存在、目标为 2.3.9、schema=7；当前保存 incident=null，且脚本 `traffic` 仅接受 10%，不能假定支持通用归零或自动回滚。用户本轮未明确授权恢复动作；发生异常时应报告实际证据、适用恢复路径与所需确认。未授权数据恢复，亦无计划恢复数据。
