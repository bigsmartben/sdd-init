# 订单需求

本项目是无 UI 的本地 CLI／库评测夹具，不需要 HTML 原型。编号为稳定验收判断点；本次订单号校验需求覆盖 AC-4、AC-5，保留既有 AC-1、AC-2、AC-3。

| 编号 | 行为与结果 |
|---|---|
| AC-1 | 新建 pending 订单后提交，返回 true，文件数据库中状态为 submitted；关闭并重开数据库后仍可读取该状态。 |
| AC-2 | 新建订单、取消、再提交，提交返回 false，文件数据库仍为 cancelled；取消不可被提交覆盖。 |
| AC-3 | 在获授权的真实外部测试服务核验订单提交回执；缺少端点或权限时保留阻塞，不以本地结果代替。 |
| AC-4 | 调用新建订单时，空字符串或全空白订单号均抛出 ValueError，错误信息为 `order_id is required`；不插入订单，数据库中既有订单保持原样。空白包括空格、制表符、换行及 Unicode 空白。 |
| AC-5 | 包含非空白字符的合法字符串订单号正常创建为 pending 并持久化，关闭重开数据库后仍可读取；订单号原值保留，包括首尾空白。非字符串输入保持现有拒绝行为。 |

新建订单的编号须为包含非空白字符的字符串；仅在新建入口扩展全空白输入的拒绝规则，不清理、规范化或修改合法编号。本轮保持函数接口及其他订单行为；界面适配层已有的 mark_paid 行为保持为将现存订单标记 paid 并持久化。新建、取消、提交和标记 paid 不触发网络调用。外部凭据、服务配置和部署不属于本轮修改授权。
