# BUG-001 — 空输入解析返回 None

## 1. 缺陷事实与归因

- 类型：已证实的实现缺陷。依据为 [用户工单](../../TASK.txt) 中已确认的契约：空输入返回空列表，非空字符串继续按逗号拆分。本轮仅恢复这一行为，不提交或推送。
- 初始版本：`eb59588acc9c3e152904c2ecb96c29983c726f3a`，初始工作区干净；环境为本隔离项目、Python 3.12.3。
- 复现入口：`from src.parser import parse; parse('')`。预期 `[]`，实际 `None`；影响空输入调用方获得的返回值。
- 已验证原因：[解析实现](../../src/parser.py) 的 `if not value` 分支显式返回 `None`。空字符串进入该分支；非空字符串进入 `value.split(',')`。这一直接执行路径及下述实际观测相互吻合，无环境故障证据。
- 修复前取证（2026-11-15，Bugfix 技能 Agent）：公开调用 `parse('')` 得到 `None`；`parse('a,b')` 得到 `['a', 'b']`；`parse('one')` 得到 `['one']`；`parse('a,,b')` 得到 `['a', '', 'b']`。

## 2. 修复工单与验收

- 负责人：Bugfix 技能 Agent 调度 sdd-coder 实施；技能 Agent 在修复版本独立复验。
- 修复边界：只修正空输入返回值，保持现有非空字符串按逗号拆分路径。实现方案、任务和局部证据见 [修复计划](BUG-001-plan.md)。
- 验收计划：coder 修复后通过公开函数入口自验；技能 Agent 核对实际未提交版本后独立执行同一组判据。
- 验收方案：在项目根目录使用 Python 3，导入真实 `src.parser.parse`；断言 `parse('') == []`，且结果类型为 `list`；断言 `parse('a,b') == ['a', 'b']`、`parse('one') == ['one']`、`parse('a,,b') == ['a', '', 'b']`。前三项覆盖原故障、逗号拆分和无逗号字符串，末项验证空分段保持。无需外部服务或人工反馈。
- 当前状态：复验后关闭。阻塞：无。修复版本为上述 HEAD 加未提交的 `src/parser.py` 单行修复，其 SHA256 为 `3e0d14ca1979f8a546363180e6b36e5c2264897a6cac66e72ab75fbf0c9f49f9`。
