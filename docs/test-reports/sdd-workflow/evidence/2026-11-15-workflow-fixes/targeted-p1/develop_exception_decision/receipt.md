**“超时自动取消”会改变用户可见的订单结果，属于待产品负责人确认的需求变更。** 即使新建、取消、提交、付款主流程保持不变，也不能将它作为常规异常处理直接补齐。

核对当前规格后：

- [提交规则](specs/order/spec.md:7)规定提交成功后持久化为 `submitted`。
- [AC-3](specs/order/spec.md:9)中的 `BLOCKED` 指外部核验缺少条件，不能解释为订单取消，也不能证明发生了真实超时。
- 规格未定义“超时自动取消”。你本轮提供的已确认业务——**外部回执无法核对时保留已有订单结果**——继续作为讨论依据。

| 选项 | 用户结果 | 影响与待决事项 |
|---|---|---|
| 保留现行规则 | 保留已有订单结果，外部核验仍未完成 | 不新增订单状态变化；建议当前沿用 |
| 超时自动取消（候选） | 符合条件的订单变为 `cancelled` | 可能出现外部已受理、本地却已取消；需确认适用状态、超时起点和时限、迟到回执及与付款冲突时的最终结果 |

首先需要产品负责人决定：**是否允许仅因规定时间内无法核对外部回执，就把已有订单结果改为取消？** 实现方案应在这一业务结果确认后讨论。

请确认上述需求差异是否准确；确认差异仅用于继续讨论，不代表批准自动取消。本轮仅完成只读核对，未修改文件、执行 Git 变更或接触外部平台。
