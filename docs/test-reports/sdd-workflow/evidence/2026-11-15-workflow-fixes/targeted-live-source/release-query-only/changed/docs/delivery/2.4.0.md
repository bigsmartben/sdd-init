## Deployment Assessment

拟变更对象为 `production-sim` 的 `orders` 既有 canary 目标，候选使用本记录中已解析的 2.4.0 摘要。部署后须回读实际摘要、就绪状态并通过 canary 入口冒烟，之后才可把 `/checkout` 从当前 canary 0% 调整至 10%。本轮未执行这些步骤。

运行指南说明 schema 7 与两镜像兼容；本方案未提出 schema、数据恢复或其他配置变更。部署过程可能导致 canary 不就绪或影响依赖；切流后约 10% 的 checkout 请求将进入候选版本，应用缺陷可能影响这些请求及订单数据。实际数据投影、下游依赖和发布后行为均未在本轮验证。

发布通过条件沿用运行指南：canary 摘要正确且就绪、canary 入口冒烟通过、控制面 `/checkout` canary 权重为 10%，并取得 60 模拟秒、1000 请求、8–12% 实际命中 canary、零错误的观测。任一条件不满足时暂停后续晋级；超时可能已应用变更，必须先回读实际状态再决定下一步。

异常恢复须先核对实际版本、路由、指标及原 stable 仍可用，再在确认范围内恢复 `/checkout` 的原 canary 0% 权重或回滚指定摘要。当前没有恢复操作授权，本轮未执行恢复。数据恢复另需针对实际目标的签署事件指挥批准及满足 15 分钟数据损失容限的恢复点；冒烟通过不能证明数据完整，涉及事件恢复还须验证实际 checkout 投影与下游依赖。
