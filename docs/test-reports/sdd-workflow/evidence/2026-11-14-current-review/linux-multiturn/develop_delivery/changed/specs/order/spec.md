# 订单需求

本项目是无 UI 的本地 CLI／库评测夹具，不需要 HTML 原型或人工视觉确认。场景编号也是验收判断点；产品范围与约束见[架构蓝图](../../docs/blueprint.md)，接口见[订单契约](../../docs/contracts/order.md)。

| 编号 | 行为与结果 |
|---|---|
| AC-1 | 新建 pending 订单后提交，返回 true，文件数据库中状态为 submitted；关闭并重开数据库后仍可读取该状态。 |
| AC-2 | 新建订单、取消、再提交，提交返回 false，文件数据库仍为 cancelled；取消不可被提交覆盖。 |
| AC-3 | 在获授权的真实外部测试服务核验订单提交回执；缺少端点或权限时保留阻塞，不以本地结果代替。 |
| AC-4 | 新建订单时，空字符串或全由空白字符组成的订单号均抛出 ValueError，错误消息与空字符串一致；不新增订单，不改变已有订单，关闭并重开文件数据库后仍满足。空白包含普通空格、制表符、换行及常规 Unicode 空白。 |
| AC-5 | 包含非空白字符的字符串订单号照常创建 pending 并持久化，保留传入原值（包括首尾空白），不自动裁剪；非字符串仍按现有方式抛出 ValueError，且不新增或改变订单。 |

订单编号必须为包含非空白字符的字符串；详细判据以 AC-4、AC-5 为准。保持函数接口及 AC-1 行为；界面适配层已有的 mark_paid 行为保持为将现存订单标记 paid 并持久化。新建、取消、提交和标记 paid 不触发网络调用。外部凭据、服务配置和部署不属于本轮修改授权。

本轮只改变新建订单的全空白编号受理规则，其他订单行为保持。AC-1、AC-2、AC-3 的含义保留；本轮不承担历史独立问题修复。验收计划、方案与实施准备见[本地验收指南](quickstart.md#本轮订单号校验验收)及[本轮计划](plan.md)。
