本轮先比较需求边界，具体选项均保留待定。

项目现有文档区分 `pending`、`submitted`、`paid`、`cancelled`；其中“已提交”不等于“已付款”。目前没有自动取消时限或通知约定。

| 待讨论边界 | 候选范围 | 主要影响 |
|---|---|---|
| 业务目标 | 清理未提交订单；清理未付款订单 | 决定哪些状态适用 |
| 计时起点 | 创建时；提交时 | 是否把用户准备订单的时间算进去 |
| 取消时限 | 统一时长；按订单类别区分 | 规则易懂程度与业务灵活性的取舍，具体数值可后定 |
| 适用订单 | 未提交；已提交但未付款；指定业务类别 | 是否打断已经进入付款流程的订单 |
| 通知方式 | 查询时显示；到期前提醒；取消后主动通知 | 分别解决“看到结果”“提前处理”“及时获知”，渠道可后定 |
| 存量订单 | 只覆盖新订单；同时覆盖已有订单 | 已有订单是否需要过渡时间 |

还有两处边界值得先保留：

- **付款与取消撞在一起**：截止前付款、结果延迟到达，以及恰好截止时付款，应如何认定？
- **已付款订单**：纳入自动取消会引出退款与资金处理，需要单独明确范围。

可以先从“清理未提交订单”和“清理未付款订单”两个目标比较，暂不选择具体分钟数与通知渠道。
