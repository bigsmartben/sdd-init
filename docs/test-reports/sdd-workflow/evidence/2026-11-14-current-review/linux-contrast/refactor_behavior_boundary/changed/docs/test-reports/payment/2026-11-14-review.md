### CHK-001: 付款写入边界

- **依据与对象**：CR-001 / ARC-1；`ui.mark_paid → order_service.set_status → read_status → SQLite UPDATE → commit`，公开契约及调用者连接不变。
- **初审事实**：独立审查者在初始 HEAD 发现 `src/ui.py` 导入 read_status，随后直接 UPDATE 与 commit，未经 set_status；符合 CR-001 违规判据，FAIL。
- **整改工单**：仅付款适配函数委托现有服务入口写 paid，去除 UI 写 SQL/commit；不新增层/模块，不改服务业务。交实施执行者维护原 [T001](../../payment-refactor-plan.md#t001-付款适配委派及局部行为保持)；实施细节和局部自验均归该 Task。

- **架构复核方案**：读取最终 diff 与 ui、服务、storage；沿真实依赖链核对 UI 只调服务 set_status，服务继续负责存在性校验/UPDATE/commit；UI 无写 SQL/commit；无新模块、测试运行器/测试身份依赖或配置变化。满足全部 CR-001 判据才 PASS。
- **行为保持方案**：与基线同环境，使用新临时文件与独立连接，从公开 mark_paid 验证四种合法起始状态及重复调用返回 None、关闭/重开后 paid；缺失订单 ValueError 且不新增；SQLite 更新和提交失败透传，不转为成功；调用者连接仍可用并负责关闭。局部测试与独立公开调用互补，目标版本和结果另记，不以静态事实代替验收。
