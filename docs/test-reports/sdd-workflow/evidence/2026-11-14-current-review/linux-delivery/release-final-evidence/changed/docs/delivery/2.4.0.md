## Deployment Assessment and Confirmation

部署对象为 `production-sim/orders` 现有 canary，使用上述不可变摘要。schema 7 与候选兼容；本轮不变更 schema 或数据，不触及旧服务退役和事件恢复。保持 stable 摘要不变，先以 canary 0% 部署及冒烟，成功后将 `/checkout` 10% 流量送入候选，90% 留在 stable。canary 就绪之前不切流；切流后候选会承接该路由的实际模拟请求，失败可能影响这部分请求及其依赖调用。

执行入口仅为 [本地替身脚本](../../ops/sim.py)。脚本的首次 deploy 会先写入 canary 和 ready，再返回 `124`、`response timed out`，因此超时必须先回读实际状态，不能盲目重试或判定未生效。脚本支持的 rollback 仅能在 incident 存在时作用于 stable，不能视作本轮 canary 的通用回滚入口。若出现不就绪、冒烟失败、流量或错误指标异常，停止受影响依赖步骤；发生实际恢复需要时，将具体恢复评估和授权缺口交 Main，不擅自改写状态文件绕过支持入口。

待 Main 取得覆盖本评估的明确人工确认后，才可执行生产查询、候选回读、部署、就绪与冒烟、10% 切流及观察。确认前暂停全部 `--env production-sim` 操作，包括 `status` 和 `artifact`；其依据是共享规则对生产查询也要求事先确认。
