## 发现与整改建议

P1 优先处理可能改变用户决定、授权范围或验收结论的问题。P2 处理影响执行路径、交接或规范一致性的问题。P3 清理已有提示但易被误用的历史内容。下列触发场景用于说明源码偏差的可能影响，实测事实见后文。

### F01 · P1 · 开工前缺少集中、可传递的执行约定

**关联 RW-02.1、RW-02.3。** Main 的共用职责要求明确目标、终点和授权，委派要求补充写入边界、必要输入、版本环境与完成条件。需求阶段 A 前核对主流程、体验、范围及须保持行为，B 前固化验收。已知排除项、实质约束和待决事项没有共同的前置核对点。Plan 有排除项和待查假设，但正式实施的 Plan 可在 B 后才建立。规范规定发现缺项后如何回报，未把可在开工前识别的缺项和探索中新发现的约束分开处理。[仓库治理](../../../source/project/.agents/sdd/references/sdd-repository-governance.md) 21、49–51 行 · [执行协作](../../../source/project/.agents/sdd/references/delegation.md) 34–36、63–65 行 · [需求到实现](../../../source/project/.agents/skills/sdd-develop/SKILL.md) 12–18 行 · [Plan 模板](../../../source/project/.agents/sdd/assets/plan_template.md) 9、21 行

**影响与建议。** 用户确认交付后仍可能陆续收到本可前置的范围或验收问题，接续者也难判断某项是已知排除还是尚待决定。由 Main 在现有任务载体集中固化目标、范围与排除、约束、验收、授权终点及已知待决，按阶段引用适用部分。已确认内容直接带入，条件未成熟但可自主调查的事项单列，触及关键约束时带影响和可行选择回报。需求阶段继续保留 FR-029 的 A／B 节点，实施细节在授权内推进。

**关联 RW-03.3、RW-01.1。** 需求 Skill 允许实施者决定结构细节，要求将范围外改进和需要决策的架构冲突交 Main。共享规则描述了已授权的组合和未授权后续阶段，却未要求说明「为交付当前需求，为什么必须先做独立重构」以及替代选项。实施规则提醒架构冲突或跨职责取舍要回报，未提供判断局部调整、无关改进和真实前置依赖的依据。重构 Skill 已另设架构与行为保持判据，这两类判据可以沿用。[需求到实现](../../../source/project/.agents/skills/sdd-develop/SKILL.md) 12、18、33–37 行 · [仓库治理](../../../source/project/.agents/sdd/references/sdd-repository-governance.md) 47–51、86 行 · [实施与局部自验](../../../source/project/.agents/sdd/references/implementation.md) 12、14 行 · [重构](../../../source/project/.agents/skills/sdd-refactor/SKILL.md) 14、19–24 行

**影响与建议。** 同一处结构问题可能被扩大为默认重构，也可能只当建议登记，导致需求一直无法满足原判据。按任务目的、受影响边界和验收结果区分三类情况。为满足本需求且符合现有架构的局部调整并入本工单。与交付无关的发现随依据回报。确实需要独立重构时，指出被阻塞的 AC、依赖和影响，由 Main 集中呈现先重构、调整交付方案或推迟相应范围等可行选择。确认后分别维护两套目标和判据，继续不受影响的需求工作。

## 整改后优先复验

1. **前置决定和两个交付目标。** 使用已有确认的独立需求工单，对照常规边界值、有实质行为变化的异常、可局部调整、无关技术债、必须独立重构五类情形。检查 Main 在开工前集中准备的内容、实际用户回传、Spec 和产品文件的首次写入、未阻塞项的接续，以及两个阶段各自的证据和终点。再以「付款整改完成、Review 部分待证、业务已有失败、外部场景待权」跑组合用例，检查可执行集成场景、Test Gate 和发布状态。
2. **两种直接路径与实际回报方向。** 对照明确的本地配置修改、已就绪且止于专业产物的直派工单，以及要求完整验收的小缺陷。记录实际调用者、载入规则、执行者、写入和完成判据。以隔离替身对照非生产告知、生产人工确认、原确认影响变化、人工反馈缺失，验证时点、回传及待验状态。
3. **长程执行与恢复。** 在多个独立工作项中注入一个实质阻塞，核对用户可见的消息、主动状态查询及内部恢复点。让原 Agent 无法接续，用新 Agent 在版本或环境局部变化后恢复，检查有效决定无须重述、已证覆盖无需重做、受影响场景按原判据补验。
