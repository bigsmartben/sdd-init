# Plan：DevOps 职责与托管迁移

## 1. 目标与依据

- 目标与范围：保留 sdd-deliver 用户入口，将 sdd-delivery 改为 sdd-devops，统一 Git、仓库集成、发布环境和流量运维；安全迁移已接入项目的受管角色引用。designer 不在本轮范围，角色总数仍为五个。
- 上游任务：[Spec](../../specs/platform-independent-sdd/spec.md) FR-003／AC-003、FR-011／AC-011、FR-022／AC-022、FR-027／AC-027；上述 AC 是本轮验收计划与通过判据。分别检查独立仓库、环境、流量和 SHA → 部署健康 → 切流组合，以及升级迁移和碰撞保护。
- 当前入口：[sdd-deliver](../../source/project/.agents/skills/sdd-deliver/SKILL.md)、[执行协作](../../source/project/.agents/sdd/references/delegation.md)、初始化器和角色配置。

## 2. Task 清单

### T001：统一规则与角色

- 依据：FR-003、FR-011、FR-022 及对应 AC。
- 改动范围：工作流角色、sdd-deliver 入口及相关指引、治理和导航。
- 实施内容：统一 sdd-devops 职责，保留 Main 授权与调度，支持独立与组合任务，明确回读证据及故障边界。
- 依赖：无。
- 完成条件与局部自验：核对角色、入口与引用，验证独立仓库、环境、流量及组合判据，失败不得报告后续步骤完成。
- 状态：完成。
- 结果与证据：新角色配置和交接规则可达，已安装 Skill 的独立与组合操作经场景对照和命令替身验证。[实施证据](../workflow-evidence.md#2026-11-14-devops-角色与托管迁移)

### T002：迁移受管角色引用

- 依据：FR-027／AC-027。
- 改动范围：初始化器、分发清单及相关测试。
- 实施内容：共享资源升级后一次 init 安全替换旧受管引用，保留项目自有旧角色及其他配置，碰撞时写前停止。
- 依赖：无；角色目标名称以 T001 的已确认契约为依据。
- 完成条件与局部自验：覆盖新装、升级、重跑、项目自有角色及碰撞保护，并核对恢复行为。
- 状态：完成。
- 结果与证据：已验证新装、旧角色升级、重跑、用户自有旧角色保留、冲突保护和事务恢复。[实施证据](../workflow-evidence.md#2026-11-14-devops-角色与托管迁移)

### T003：合并验收

- 依据：上述全部 AC。
- 改动范围：本轮关联文档、分发和测试结果。
- 实施内容：合并核对两项实现及证据，检查文档、链接、分发与角色引用一致，并区分真实平台操作与模拟覆盖。
- 依赖：T001 和 T002 均完成局部自验。
- 完成条件与局部自验：按对应 AC 逐项核对并记录实际版本、命令、结果及未覆盖项；组合链路须核验 SHA、部署健康、切流回读及失败边界。
- 状态：完成。
- 结果与证据：仓库回归、构建后初始化器、wheel 安装、隔离客户端发现与场景替身验证通过。成功路径先验证目标版本健康再切流，失败路径无路由写入。[实施证据](../workflow-evidence.md#2026-11-14-devops-角色与托管迁移)

执行 DAG：T001 ∥ T002 → T003；并行以各自写入范围及共享状态不冲突为前提。
