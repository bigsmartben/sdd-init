# SDD 工程协作职责

## 范围与需求

工作流的预期、取舍及设计策略见 [sdd-workflow 白皮书](../../docs/sdd-workflow-whitepaper.md)。本 Spec 承接具体产品行为承诺与验收条件，保留 FR／AC 的稳定编号；设计目标正文不在此重复维护。

本 Spec 记录 sdd-init 的产品承诺、本仓维护要求及验收条件。产品用例见[产品与架构蓝图](../../docs/blueprint.md#3-用户用例)，执行细则见各条关联的源码入口，实测结果见[实施证据](../../docs/workflow-evidence.md)。

- FR-001：接入后的工作流支持从 Blueprint 用例追溯到具体需求、AC、实施及验证证据，实施方案与任务可在同一份 Plan 中跟踪。[产物权威](../../source/project/.agents/sdd/references/sdd-repository-governance.md#权威实体)
- FR-002：按受管清单交付工作流、角色、治理、模板与工具，并能校验新载荷完整性。安装与更新强制覆盖指定安装目标中的旧版、定制、缺失、额外文件或无清单内容，不请求用户裁决；同版重装保持幂等。损坏的新载荷不得发布。
- FR-003：sdd-deliver 支持独立或组合的 Git 与仓库平台交付，包括分支、提交、推送、Issue、PR／MR、仓库集成及流水线操作。按实际仓库、实例和授权终点执行，可核对源／目标版本与实际平台状态，并保护任务范围外的改动。[Git 与平台交付](../../source/project/.agents/sdd/references/git-delivery.md)
- FR-004：分发和迁移可追溯至原始来源及版本，保留历史证据、来源链接及第三方依赖地址的原义。
- FR-005：已授权且就绪的工单可独立交付一份 Plan／Task、实际改动、版本、局部自验证据及待验项。输入缺口先回报调用者，局部阻塞时可继续其他已就绪且获授权的工作。[实施交接](../../source/project/.agents/sdd/references/delegation.md#实施交接) · [实施与局部自验](../../source/project/.agents/sdd/references/implementation.md)
- FR-006：获授权的执行者可将已确认结论或实际证据原位归并到权威文档，保留仍适用的条件、例外和历史，并核对受影响的引用与语义。[文档写入规则](../../source/project/.agents/sdd/references/document-writing.md)
- FR-007：分发的产物模板采用统一的英文结构及 `*_template.md` 命名，能从使用入口找到对应模板。正式时序有唯一模板，模板升级沿用项目已有产物路径。
- FR-008：实施局部自验、需求点对点验收、用户功能集成验证、缺陷定向复验和架构复核各自交付与判据、实际版本相符的证据。验证者的工作范围由对应工单和授权决定。[实施和独立审查](../../source/project/.agents/sdd/references/sdd-repository-governance.md#实施和独立审查)
- FR-009：测试报告可追溯每一批次的目标、实测范围、版本、结果、缺口和证据。架构遵循使用专用审查记录，指南、状态和工单通过引用复用结果。[Test Report](../../source/project/.agents/sdd/assets/test_report_template.md)
- FR-010：需要实际界面操作来确认体验时，提供可操作的中保真 HTML、对应源码版本、实测证据及需求引用。正式实现复用时可追溯已确认原型，并在实际运行中验证。[原型规则](../../source/project/.agents/sdd/references/prototype.md)
- FR-011：六个随包注册的专业角色可独立受理合格工单，依靠适用的项目资料和共享资源完成本职产物，向调用者交付结果、证据及接续条件。[角色独立执行](../../source/project/.agents/sdd/references/delegation.md#角色独立执行)
- FR-012：提供统一的仓库治理入口，能从本轮工作定位适用的职责、授权、产物和交接。需求与架构纯讨论可直接交付候选与待决事项。已确认 Blueprint 的归并、项目规则的按需维护和实现的架构复核可分别执行。[仓库治理](../../source/project/.agents/sdd/references/sdd-repository-governance.md)
- FR-013：随项目提供只读文档校验 CLI，可对指定文件或目录检查结构、编码、编号和本地引用，输出带位置和规则码的文本或 JSON 诊断及稳定退出码。[文档校验 CLI](../../source/project/.agents/sdd/references/doc-check.md)
- FR-014：分发三类架构范式、八项规范指导及带稳定编号的通用 checklist，明确适用条件、取证方法与判定要求。依据已确认项目决定形成具体规则，并由重构技能按子系统、模块、组件及协作边界生成、更新独立 Review 矩阵，关联设计、规则、适用条件及检查判据。首次内容及受影响增删改向用户展示确认后归并，在蓝图中保留固定链接；结构、关系或适用规范变化时由 Main 组织同步。批次任务及结果另归审查记录，安装升级保护项目资产。未确认推荐不能成为项目门禁。[架构规范](../../source/project/.agents/sdd/references/architecture-rules.md) · [矩阵维护](../../source/project/.agents/sdd/references/sdd-repository-governance.md#目标仓库的-code-review-rules)
- FR-015：可行性验证、Demo、算法对比及候选路径探索按测试资产维护，版本与结果可追溯。采用其中的代码时，正式运行仍满足正式与测试的装配隔离。[工程资产边界](../../source/project/.agents/sdd/references/sdd-repository-governance.md#工程资产边界) · [运行隔离](../../source/project/.agents/sdd/references/architecture-rules.md#正式实现与测试实现隔离)
- FR-016：架构规范指导目标项目确认业务与运行保障的职责分工，以及观测数据用途、同步或异步、隔离程度、开销预算和故障策略。固定模块归属、强制非阻塞或记录失败时一律放行不作为通用预设；业务权威、接口权限及副作用遵循已确认契约。[业务与运行保障分工](../../source/project/.agents/sdd/references/architecture-rules.md#业务与运行保障分工) · [可观测性架构规范](../../source/project/.agents/sdd/references/observability-baseline.md)
- FR-017：工作流按用途区分正式实现、测试和运维资产。探索验证可从假设、候选路径和判断指标追溯到实际证据。[工程资产边界](../../source/project/.agents/sdd/references/sdd-repository-governance.md#工程资产边界) · [测试工程规范](../../source/project/.agents/sdd/references/architecture-rules.md#测试工程与自动化规范)
- FR-018：持久化业务实体的权威存储、写入职责、完成判据、失败和恢复可从项目设计追溯到实际运行路径。[业务实体持久化](../../source/project/.agents/sdd/references/architecture-rules.md#业务实体持久化)
- FR-020：sdd-refactor 启动或接续以已有蓝图为硬前置，缺失时说明缺项并直接结束，不生成项目资产或派发执行。有蓝图时核对、初始化或更新规范与矩阵，按本次目标派生 Review Task，确认任务范围、版本、排除项及授权终点后初审，已有确认沿用。初审后有整改依据的原检查项形成重构工单，按授权停在资产维护、审查、工单准备或完成保持业务行为的重构。用户可追溯矩阵与规则快照、初审、同一 Plan／Task、整改版本的架构复核和行为保持验收，以及 Review Gate、偏差和集成准备条件；缺蓝图门槛不扩展到独立开发工单。[架构对齐与技术重构](../../source/project/.agents/skills/sdd-refactor/SKILL.md)
- FR-021：sdd-bugfix 对指定缺陷可完成归因、修复和实际修复版本的定向复验，也支持仅诊断、准备工单或复验。原 Issue 保有稳定编号、处理历史与关闭依据，按原判据和授权更新。[缺陷修复与定向复验](../../source/project/.agents/skills/sdd-bugfix/SKILL.md) · [Issue 关单](../../source/project/.agents/sdd/references/sdd-repository-governance.md#issue-关单)
- FR-022：sdd-deliver 结合个人／团队协作约定、可组合的 CI／CD／Ops／DevOps 任务、授权终点及环境风险识别场景，区分建立／调整工作流与执行既有流程。由加载技能的 Agent 将完整专业场景委托给 sdd-devops，自主调查、制定方案、配置／执行并复验；角色不可用时沿共享替代规则承接，不强制新增技能 Agent。优先沿用适用入口，独立请求不扩展成固定全链路；通用技能与角色不绑定平台，平台事件、云端执行器、权限及流水线实现归目标项目配置。技能核对实际场景结果，不重复角色实施过程。支持构建发布、部署、服务与流量运维、排障、回滚、备份恢复和退役及其授权组合。执行或触发部署前告知资源和影响评估，直接或间接生产操作须有覆盖本轮的人工确认。正式发布可追溯至实际候选、制品及适用验证证据。[交付与运行](../../source/project/.agents/sdd/references/delivery.md) · [交付与运维交接](../../source/project/.agents/sdd/references/delegation.md#交付与运维交接) · [正式发布依据](../../source/project/.agents/sdd/references/release-evidence.md)
- FR-023：同一项目、共享目标或用户角色目标的安装写入互斥。安装失败和中断可恢复，恢复保护外部改动和未触及内容。无法安全恢复时保留记录并阻止继续覆盖。[安装与恢复](../../docs/installation.md#用户级安装恢复)
- FR-024：旧治理入口的 `start`、`record`、`attest`、`check`、`finish`、`commit` 退役。保留现行安装、恢复、只读盘点及独立文档校验能力，既有历史记录可追溯。[旧治理命令退役边界](../../docs/blueprint.md#旧治理命令退役边界)
- FR-025：Main 向用户呈现对意图的理解并请求确认，沿用适用的既有确认。需由用户决定的需求与方案分别确认，均待定时先确认需求；专业执行者将待决事项、依据及影响交 Main，由 Main 面向用户确认并回传决定。[意图对齐](../../source/project/.agents/sdd/references/visual-confirmation.md#意图对齐)
- FR-026：sdd-test-loop 按明确请求对指定版本和环境执行范围内全功能点集成回归，交付可复跑指南、逐项证据、缺陷与恢复条件和 Test Gate。按能力选择执行者；项目或用户要求独立验收时须满足实际独立性，无法满足时标明受影响场景与恢复条件。Gate PASS 须有全部适用判据及必要人工反馈的证据。[集成测试](../../source/project/.agents/skills/sdd-test-loop/SKILL.md)
- FR-027：支持用户级共享更新、指定项目首次接入、升级、克隆重连、只读检查及恢复。安装和更新直接替换受管目标及同名入口，不请求用户裁决；项目角色按 FR-039 核验归属，不以同名认领非受管角色，不覆盖安装范围外的项目正文、配置或链接目标。已链接项目可复用同一共享版本。仅更新共享包后，旧项目的现行 Codex 角色引用仍可读取新载荷的角色正文和配套资源。项目受管技能以 `.agents/skills/<技能名>/SKILL.md` 标准入口提供，各技能目录必须链接到用户级共享资源，不复制正文、不依赖递归发现；共享包入口位于技能扫描目录之外。接入后可发现受管技能和角色。[初始化入口](../../source/initializer/SKILL.md) · [安装说明](../../docs/installation.md)
- FR-028：`review-prompt` 是 sdd-workflow 预置项目自定义角色，与其他专业角色统一分发到共享资产并由项目配置注册，不另装用户级角色或新增 Skill，不承诺未接入项目的全局可用性。独立承担通用仓库提示词审查、候选比较、授权修订及专项复验，覆盖 AGENTS.md、自定义技能、角色、业务提示词及影响判断的引用；依据实际加载关系和仓库专项规则，不预设 SDD 结构。先提取可追溯的“目标＋验证”共同契约，按契约完整、执行可行、语义一致、必要性与成本、改写保持五类规则发现问题，保留必要授权、例外及验收边界。默认冻结当前生效版本为基线，包含相关未提交内容与装配；需补齐或纠正契约时保留原版，按已确认依据建立合格基线，区分规则修正与效率优化。已授权且结论明确的优化可直接落地，A/B 不是前置。A/B 执行前经调用者向用户同步规模、用例、token 成本预算上限、预计耗时、停止与采纳条件，用户确认后才推进；这是本流程唯一的用户确认节点，已有覆盖确认沿用，超预算或实质扩围暂停并回到同一节点。成本仅指 token 消耗，执行时间作为独立效率指标。相同输入及可比执行条件下，结果满足共同契约后比较完整执行时间和实际 token，而非 Plan 一致或提示词长度；两项更优或一优一相当时可推荐，交叉取舍按实验前确定的优先级或预算决定，缺证保留待验。规则、策略、核对节点与统计口径见角色专属配套的[提示词审查与优化](../../source/project/.codex/agents/review-prompt/prompt-review.md)，相对路径以实际承载角色职责正文的文件为基准，而不是引用正文的 Harness 适配配置，配套资源随正文一同迁移，不依赖固定 SDD 安装路径。角色不可用时合格执行者可按同一契约承接。原地升级直接迁出旧清单登记路径上的用户级 review-prompt，即使文件已修改也不另请求确认，文件缺失时继续；不扫描清理未登记角色，不修改用户配置。事务记录操作前实际状态，失败或中断时可恢复，事务开始后的外部编辑仍受保护。指定项目刷新时将原五角色托管注册更新为六角色，受管注册和文件按 FR-039 更新，非受管项目角色冲突在写入前报告并保留。[角色](../../source/project/.codex/agents/review-prompt.toml) · [安装说明](../../docs/installation.md#更新与冲突)
- FR-029：sdd-develop 可按约定推进单个需求从规格到实施和点对点验收，或停在讨论、规格等授权终点。新需求或需求变更在正式写入和交付实施前各有对应确认，最终交付版本、逐项验收证据与集成准备条件。[需求到实现](../../source/project/.agents/skills/sdd-develop/SKILL.md)
- FR-030：sdd-doc-consistency 可在实际只读权限下审查指定项目文档，交付冲突、重复、失效或错位引用的证据及处理建议。运行时提示词及指令排除在该角色职责之外。[文档交接](../../source/project/.agents/sdd/references/delegation.md#文档交接)
- FR-031：Main 定位为意图对齐的目标驱动探索与调度 Agent，承担 Align、Explore & Orchestrate、Evaluate 的逻辑闭环，不固定为三个步骤、Agent 或模型调用。沿用有效目标、约束、授权、决定和完成条件，根据证据与目标差距增量发现行动、问题和依赖，支持下钻、回溯、纠偏及剪枝；达成目标即结束，无须预先构造完整 Plan／DAG 或遍历全部分支。Main 能直接完成就直接完成，单个专业能力可完成就直接调用，仅真实依赖或协作需要才展开多任务调度。保留原生 Plan、Skill 触发、专业职责、确认和验证边界，不强制每个 Skill 创建子 Agent、独立 Review、L0／L1／L2 调度模式、分类 Agent、状态文件或总结回执。Goal／Frontier／Evidence／Gap 是逻辑信息，简单任务仅留当前上下文，复杂任务按需使用 Harness 原生机制及既有记录恢复，不另建图数据库或任务框架。专业执行者自主探索、规划、实施与验证；Main 提供语义工单、采纳适用证据、协调新增依赖，不重复专业源码追踪、推理或审查。用户变更目标时更新有效上下文，停止不再获授权的行动并保留仍适用结果。按用户完成条件及证据交付 Completed、Blocked 或 Partial；路径不可行则调整或明确缺口、恢复条件，不无限重试，不由讨论、设计或规格自动进入实施。术语及运行契约见[职责与交接](../../source/project/.agents/sdd/references/sdd-repository-governance.md#职责与交接)，验收按 AC-031、AC-035～AC-041。
- FR-032：sdd-architecture 可建立、补齐和演化仓库级 Blueprint，交付经用户确认的内部一致设计、适用的取舍与契约以及关键假设的验证依据。架构分解遵循“系统 ⊃ 子系统 ⊃ 组件 ⊃ 模块”，Blueprint 的最小架构颗粒度为组件，模块及内部实现细节归关联工程文档。先定义逻辑结构与组件职责，再显式映射部署单元、运行位置、实例与隔离及跨边界接口；两者是同一架构的互补视图，不强制组件与进程一一对应。部署视图沿用逻辑组件及接口引用，不重定义职责、状态权威归属或依赖限制，并以运行约束反向核对逻辑设计可行性。技能负责设计、取舍、关键假设验证及设计内部一致性核对，按需下钻模块或实现细节；模块详细设计、正式产品实现、部署运行操作、实现符合性 Review 及矩阵维护按职责经 Main 交接。纯讨论或专项评估按授权终点交付。[架构蓝图设计与演化](../../source/project/.agents/skills/sdd-architecture/SKILL.md)

- FR-035：Main 重构直接采用 FR-031 的当前行为，不提供旧版 Main 固定阶段、三层调度或固定规划职责的兼容模式、专用迁移或升级路径。历史记录仅作为版本化事实，不作为当前执行依据。此要求不撤销 FR-027 的通用安装、更新和恢复能力，也不授权修改现有用户安装。

- FR-036：sdd-init Skill 的唯一职责是完成目标项目 sdd-workflow 的环境落地，包含相关资产的落地准备和目标 AGENTS.md 的注入两项动作。缺少目标项目本地链接时直接运行 sdd-init 接入；用户明确禁止写入或运行环境不允许写入时说明阻塞，不绕过限制。资产准备使所需 Skills、专业角色、Main 详细规则、专业执行规则、模板和工具可用，建立相应链接与角色配置；统一组装、写入和核验单一 Main 托管片段，其中包含 Align、Explore & Orchestrate、Evaluate、能力入口及详细条款引用，不再分发或注入独立沟通片段。资产接入和 Main 规则注入均完成且重复执行无待写项，才报告项目环境落地完成；仅更新用户级资产不等同项目环境落地。意图对齐、探索调度、授权边界、任务交接和目标验收统一归 Main 规则，直接承载或按需引用不改变职责归属；专业执行规则归对应执行者，不转为 Main 的专业工作。检查、版本核验和恢复是环境落地手段，不另列职责；接入后的项目调度与业务交付不属于 sdd-init。Harness 加载项目指令，不创建额外 Main 角色。强制替换旧双块、状态和定制托管内容；保留托管范围外正文、换行和 BOM，失败与中断按 FR-023 恢复。

- FR-033：本仓白皮书按专属 Skill 提供的结构模板维护已确认设计；审查流程、RW-01～RW-12 及子项、对象矩阵、取证和统计口径归 Skill 及其参考文件，保留设计条款和 Spec 追溯。各批次 Review 报告按执行阶段增量记录受审范围与版本、依据、逐对象及逐子项覆盖、结论、证据、发现、修复复验、未验范围和质量成本。静态与行为证据分别呈现，源码体积、实际加载量和运行消耗分别记录，review 与 testcase 的 token、时长分别统计。成本统计使用可取得的实测，缺实测标为未测，不为填报另跑用例。已有报告及原始证据保留原版本语境。[模板与执行入口](../../.agents/skills/sdd-workflow-review/SKILL.md#资源与产物)
- FR-034：`sdd-workflow-review` 仅在本仓由用户显式启动，按绑定版本的设计依据、Spec 和 Skill 判据开展全面评审。先静态核对受审对象和全部 RW 子项，形成发现和待验清单。适合并行时按能独立交付的结果分派子 Agent，静态审查复用对象矩阵，回归按待验证问题或共用夹具分组。每单由同一负责人取证和初判，主 Agent 按任务选择负责人配置、决定实跑范围并统一归并。优先复用适用证据，在授权内为关键疑点或必要验收隔离执行最小场景，按风险和整版结论所需证据扩大回归。A/B 仅用于已有证据无法回答的明确比较目标，同一负责人隔离运行两侧并初判，保持受测配置一致和实验条件可比。评审可新增本轮报告和证据，审查请求本身不授权修复源码。获对应授权后沿原判据复验修复版本和关联影响，保留改前及复验证据、失败和未验范围。修改已确认设计仍须有相应决定。[本仓全面评审](../../.agents/skills/sdd-workflow-review/SKILL.md)

- FR-037：本仓个人开发的云端交付以本地显式创建或更新 PR 为入口，不因任意非 `main` 分支推送自动创建 PR。GitHub 原生审查与云端执行器接入、有限修复／复审、检查、合并和 GitHub Release 由本仓平台配置实现，不成为通用交付技能或角色的固定流程。仅 CI 通过不足以合并；适用审查、检查和授权须对应实际候选，变更后旧证据失效。套餐、凭据、接口或审批策略不满足时明确阻塞，不虚构无人值守能力、不绕过平台限制；草稿 PR 不自动合并。通过 GitHub PR 合并接口而非直推 `main` 完成集成，发布对应已验证的实际合并版本。默认从 `main` 版本递增补丁号，已指定更高稳定版本时沿用；版本变更纳入候选验证。保留 Ubuntu／Windows Python 3.13 与 Ubuntu Python 3.11 的完整检查，测试、构建、初始化器回归及唯一 wheel 的隔离安装失败均阻止后续交付。GitHub Release 包含对应版本通过检查的 wheel、源码包与哈希，不发布到包索引。合并后仅安全清理没有新增提交的对应远端分支，不操作本地分支。未完成的云端配置和实际运行范围须如实报告，不能以配置落盘代替端到端成功；自动化不能代替分支保护。
- FR-038：项目工作流共享载荷统一由 `.agents/sdd-workflow/` 项目入口访问，并按 `roles/`、`skills/`、`sdd/` 分类；`roles/` 分离共享角色正文与 Codex、Copilot harness 适配配置，`skills/` 保持 Agent Skills 标准目录结构，`sdd/` 承载共享治理、模板和观测资源。客户端发现入口仍遵循各自标准：受管 Skill 链接到 `.agents/skills/<技能名>/`，角色配置由对应 harness 原生入口注册。兼容已有注册的 `agents/<角色>.toml` 入口仍读取同一份共享角色正文。唯一源码仍位于 `source/` 的维护目录，构建输出和项目共享链接均非编辑入口。
- FR-039：项目 `inspect` 和 `init` 识别并报告目标仓库中可核验的 Codex 与 VS Code Copilot harness 配置，不以当前执行 CLI、用户级安装或单个通用 `AGENTS.md` 推断项目已配置某 harness。因同一项目可由多个 harness 使用且项目文件不能可靠表明当前使用端，`init` 的默认 `auto` 明确为同时准备 Codex 与 Copilot 适配；可用 `--harness codex`、`--harness copilot` 或 `--harness both` 显式选择。`inspect` 只读报告识别依据、适配计划和双端实际落盘的 SDD 角色，列明 Codex 中已注册但文件不可达的角色。单端接入按 Codex 配置文件所在位置解析相对及绝对角色路径，并核对未选 Copilot 项目角色的显式文件引用。迁移会使未选端的引用失效，或其 Codex 注册仍依赖待迁移的旧共享入口时，在写入前报告并停止，给出适用迁移入口。接入不探测或修改用户级客户端配置，不覆盖非受管项目角色、设置和链接目标。Codex 按托管注册块和已知共享纯引用核验归属，块外同名注册不自动覆盖，本地角色文件须由托管块引用且未被块外角色共用才可迁出。Copilot 原生文件通过 `target: vscode` 限定为支持的本地 VS Code 会话，并携带绑定角色名与内容哈希的托管标记，项目元数据记录本机实际路径和哈希，刷新另一端时保留归属。克隆或本机状态缺失后，可依据当前分发、可校验的托管标记或已知旧版文件哈希识别原受管适配。校验容许 Git 的换行转换；无法证明归属的同名文件在写入前报告冲突并保留。重复接入幂等，失败和中断按 FR-023 恢复。

- FR-040：sdd-workflow 分发的自定义角色定义、Harness 适配及调度规则均不预设模型 ID 或推理档位。Main 按每次角色工单的复杂度和实际运行时能力决定模型与推理强度，用户明确指定的设置优先。由实际派单者通过 Harness 支持的接口应用 Main 的决定。运行时无法指定时，由 Main 判断会话或 Harness 默认能否满足工单。[角色的模型与推理强度](../../source/project/.agents/sdd/references/delegation.md#角色的模型与推理强度)
- FR-041：`sdd-coder` 保持唯一实施角色，按调用者明确选择的 `investigate`、`prepare`、`implement`、`fix`、`refactor` 模式执行；每种模式明确输入前提、允许与禁止动作、停止及交付条件，调查和准备不得自动升级。实施工单以目标、范围与排除、原工单编号、通过判据、授权终点、写入边界和完成条件作为最小就绪契约，按场景补齐 Spec／AC、Issue 归因、Review CHK、验收入口及环境，缺项以 `needs-input`、`blocked` 或 `partial` 回报。Plan 按轻量、完整、长程分档；回执记录模式、状态、产物、版本与工作树指纹、检查、覆盖、失败／待验及缺口承接。证据按版本、环境、工作树和判据核对后续变更影响，局部自验不替代需求验收、集成 Test Gate、架构复核或发布通过。[Coder 契约](../../source/project/.codex/agents/sdd-coder.toml) · [实施模式与分档](../../source/project/.agents/sdd/references/implementation.md) · [工单与回执](../../source/project/.agents/sdd/references/delegation.md#实施交接)
