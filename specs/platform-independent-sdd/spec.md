# Agent 工程协作接入

## 产品范围

本文统一使用“Main Agent 治理规则”（Agent Rule）指代 Main 的对齐、沟通语言和路由规则。模板源码为 `agentsmd_template.md`，用于更新目标仓库根目录的 `AGENTS.md`。

用户通过 UVX 初始化用户级 sdd-init Skill，并在 Codex Desktop 或 GitHub Copilot App 的目标仓库中调用。Skill 提供接入工单、Main 模板、六个垂直角色的宿主适配资源与验证方法。CLI 执行配置预览、写入和检查。用户决定未标记仓库规则的升级方式和目标 CI 的接入。接入后的工程任务由 Main 路由，各垂直角色在自身职责内交付。

## 验收用例

1. 模板直接指导目标仓库的 Main。Main 用场景、使用者、操作、可观察结果、交付终点和验收条件理解任务，只表达待确认的部分。信息充分时直接推进，歧义影响结果、验收或授权时请用户决定。异常需核对实际与预期。沟通沿用目标项目术语，项目尚无对应术语时沿用用户称呼。
2. 已定位且最多涉及三个文件的局部任务可由 Main 独立完成。预计需要第四个文件，或连续两次测试失败仍无法定位根因时，说明情况并转调度路径。
3. 场景决定路由，本步须验收的结果决定角色。六个角色按需协作；工具或语言相同也可对应不同交付物。architect 只读给出边界、接口、兼容取舍与可独立验证的步骤。analyst 只读提供链路、根因、证据及影响面。implementer 在已确认范围内选择实现细节并交付基础单测。新增产品或非功能要求由 Main 确认。
4. 普通验证请求按双路径处理。开始陪测后，当前用例的反馈接续本轮。Main 跨轮维护环境记录、操作反馈与人工验收结果。uat-observer 按次接收 BOOT、INSPECT 或 TEARDOWN。修复后确认服务已重载，再请用户复验。结束或取消时只清理本轮拥有的资源。任一步返回 ERROR 时，Main 核对原因及剩余资源并说明恢复步骤。
5. 安装包可通过 UVX 在临时用户目录初始化 sdd-init Skill。Skill 入口、内置工单、Main 模板、两端角色适配和命令可达。相同内容重复初始化成功，异内容冲突保留现有内容并报告位置。
6. 显式调用 `/speckit.*` 时遵循目标项目现有的命令与宪法，按任务标签调度专家；缺少所需契约时说明阻塞。
7. 六个角色各自声明所需输入、缺失拒止、执行边界与结果字段。架构设计只读，按依赖顺序提供可独立验证的改动步骤。Main 检查输出后只转交下一任务所需的字段；缺项、失败和缺乏证据的结论不能作为完成依据。
8. tester 根据变更风险开展集成阶段的用户质量评估，可自主扩展自动化和探索性场景，并维护项目约定的测试资产。逐项依据标准记录 PASS 或 FAIL；缺少口径时记录 NEEDS_DECISION、实测与用户影响，可继续其余取证；执行受阻记 BLOCKED。缺少范围或评估目标才退回输入。探索发现须经确认才能形成修复任务。
9. devops 交付可复跑的依赖、构建、流水线和工程脚本，可接入已有质量验证。按操作报告实际结果、待授权项和其他未执行原因。uat-observer 提供陪测现场记录，领域问题由所属角色复核，跨域或归属不明时由 analyst 核验因果，用户确认体验。
10. 历史或外部 [Coder] 标签和当前 [Implementer] 标签均路由至 implementer，安装包只分发当前角色名。
11. 消息开头的单个【热词】选择场景，同义入口交付同类结果。入口、角色或路径及对应交付物集中在 [Main 路由](../../source/project/.codex/agentsmd_template.md#路由)。正文引用和语法讨论走普通对话。
12. 一对括号内以 `->` 串联的阶段从左到右执行，相邻括号各自独立。输入和授权就绪时自动前进，影响结果的取舍在交接点确认。计划阶段只交付计划，单独请求计划时到此结束。architect 的蓝图覆盖整体结构、组件职责、关键接口和实施约束。后续实现阶段按授权交付实现与基础单测。
13. 各领域在阶段授权内闭环。架构可只读还原边界与契约冲突，链路分析可核验跨域因果。实现角色可自行复现并修复局部实现及单测失败；测试角色可缩减复现、修正测试资产并复跑；工程角色可定位并修正环境与流水线；现场观测可按资源归属恢复或清理。超出范围或授权的事项交回 Main。
14. 安装后的六份角色指令分别声明正向交付、逆向定位与验证、交回条件。已知归属的工作直接派给所属角色；只读结论、复跑证据或最小补证需求可作为本步产物。交回调用方时说明证据与需要的决定。
15. 对同一项验收产物明确一个主责角色，既有证据可复用。按架构决策与链路归因、基础单测与独立质量评估、评测内容与流水线接入、可复用环境与本轮实例区分相邻职责。仅交接下一项产物所需的证据、约束和待决事项。
16. 每个角色附一条本领域的可选工具参考，提示从哪些已有项目入口取证或复跑。角色可按环境换用等效手段；工具选择不构成接单、交付或验收条件。

## 仓库接入验收

17. Skill 在写入前说明目标仓库、当前宿主和版本、接入模式、本次改动、用户选择点和验证方式。宿主或目标无法确定时保持只读并澄清。
18. 根目录 `AGENTS.md` 缺失时按模板创建，内容已满足时复用。使用当前标记的 Main 管理块按预览原地更新，保留块外项目指令。未标记的现有规则需要更新时，展示差异后按用户选择合并或替换。替换明确列出将覆盖的内容。预览后配置发生变化时重新核对并确认。
19. Codex 使用 `.codex/agents/*.toml`，Copilot 使用 `.github/agents/*.agent.md`。每端提供同样的六个逻辑角色，保留经核对的定制配置。重复接入或补接另一端时，复用当前规则并保留另一端现有适配。
20. 本地与 CI 使用同一配置检查入口。检查当前规则、角色格式与路由名，按已接入能力核对必要引用。注册目标仓库 CI 需要用户选定并审阅改动。缺失或不匹配的配置以非零退出码报告。
21. 接入回执分别记录规则写入、角色配置、原生发现和最小只读调用、检查命令、CI 选择及恢复条件。与当前桌面宿主约定的规则和角色验收通过后，记录为完整接入。需要新会话或现场操作时，逐项保留为待验证。
