# SDD 工程协作职责

## 范围与需求

工作流的预期、取舍及设计策略见 [sdd-workflow 白皮书](../../docs/sdd-workflow-whitepaper.md)。本 Spec 承接具体产品行为承诺与验收条件，保留 FR／AC 的稳定编号；设计目标正文不在此重复维护。

本 Spec 记录 sdd-init 的产品承诺、本仓维护要求及验收条件。产品用例见[产品与架构蓝图](../../docs/blueprint.md#3-用户用例)，执行细则见各条关联的源码入口，实测结果见[实施证据](../../docs/workflow-evidence.md)。

- FR-001：接入后的工作流支持从 Blueprint 用例追溯到具体需求、AC、实施及验证证据，实施方案与任务可在同一份 Plan 中跟踪。[产物权威](../../source/project/.agents/sdd/references/sdd-repository-governance.md#权威实体)
- FR-002：按受管清单交付工作流、角色、治理、模板与工具，并能校验载荷完整性。已安装的受管 Python 源文件生成的字节码允许保留，同版重装及升级仍可执行。新载荷和其他额外文件按完整性与安装保护判定。
- FR-003：sdd-deliver 支持独立或组合的 Git 与仓库平台交付，包括分支、提交、推送、Issue、PR／MR、仓库集成及流水线操作。按实际仓库、实例和授权终点执行，可核对源／目标版本与实际平台状态，并保护任务范围外的改动。[Git 与平台交付](../../source/project/.agents/sdd/references/git-delivery.md)
- FR-004：分发和迁移可追溯至原始来源及版本，保留历史证据、来源链接及第三方依赖地址的原义。
- FR-005：已授权且就绪的工单可独立交付一份 Plan／Task、实际改动、版本、局部自验证据及待验项。输入缺口先回报调用者，局部阻塞时可继续其他已就绪且获授权的工作。[实施交接](../../source/project/.agents/sdd/references/delegation.md#实施交接) · [实施与局部自验](../../source/project/.agents/sdd/references/implementation.md)
- FR-006：获授权的执行者可将已确认结论或实际证据原位归并到权威文档，保留仍适用的条件、例外和历史，并核对受影响的引用与语义。[文档写入规则](../../source/project/.agents/sdd/references/document-writing.md)
- FR-007：分发的产物模板采用统一的英文结构及 `*_template.md` 命名，能从使用入口找到对应模板。正式时序有唯一模板，模板升级沿用项目已有产物路径。
- FR-008：实施局部自验、需求点对点验收、用户功能集成验证、缺陷定向复验和架构复核各自交付与判据、实际版本相符的证据。验证者的工作范围由对应工单和授权决定。[实施和独立审查](../../source/project/.agents/sdd/references/sdd-repository-governance.md#实施和独立审查)
- FR-009：测试报告可追溯每一批次的目标、实测范围、版本、结果、缺口和证据。架构遵循使用专用审查记录，指南、状态和工单通过引用复用结果。[Test Report](../../source/project/.agents/sdd/assets/test_report_template.md)
- FR-010：需要实际界面操作来确认体验时，提供可操作的中保真 HTML、对应源码版本、实测证据及需求引用。正式实现复用时可追溯已确认原型，并在实际运行中验证。[原型规则](../../source/project/.agents/sdd/references/prototype.md)
- FR-011：五个随包注册的专业角色可独立受理合格工单，依靠适用的项目资料和共享资源完成本职产物，向调用者交付结果、证据及接续条件。[角色独立执行](../../source/project/.agents/sdd/references/delegation.md#角色独立执行)
- FR-012：提供统一的仓库治理入口，能从本轮工作定位适用的职责、授权、产物和交接。需求与架构纯讨论可直接交付候选与待决事项。已确认 Blueprint 的归并、项目规则的按需维护和实现的架构复核可分别执行。[仓库治理](../../source/project/.agents/sdd/references/sdd-repository-governance.md)
- FR-013：随项目提供只读文档校验 CLI，可对指定文件或目录检查结构、编码、编号和本地引用，输出带位置和规则码的文本或 JSON 诊断及稳定退出码。[文档校验 CLI](../../source/project/.agents/sdd/references/doc-check.md)
- FR-014：分发可复用的架构规范，按职责与权威明确、契约驱动协作、隔离与受控影响三类范式组织八项规范指导。依据已确认项目决定形成具体规则，明确适用对象与条件、确认依据、检查方法、通过条件和检查时机，架构 Review 可沿实际路径判定；未确认的推荐策略不能直接成为门禁。[架构规范](../../source/project/.agents/sdd/references/architecture-rules.md)
- FR-015：可行性验证、Demo、算法对比及候选路径探索按测试资产维护，版本与结果可追溯。采用其中的代码时，正式运行仍满足正式与测试的装配隔离。[工程资产边界](../../source/project/.agents/sdd/references/sdd-repository-governance.md#工程资产边界) · [运行隔离](../../source/project/.agents/sdd/references/architecture-rules.md#正式实现与测试实现隔离)
- FR-016：架构规范指导目标项目确认业务与运行保障的职责分工，以及观测数据用途、同步或异步、隔离程度、开销预算和故障策略。固定模块归属、强制非阻塞或记录失败时一律放行不作为通用预设；业务权威、接口权限及副作用遵循已确认契约。[业务与运行保障分工](../../source/project/.agents/sdd/references/architecture-rules.md#业务与运行保障分工) · [可观测性架构规范](../../source/project/.agents/sdd/references/observability-baseline.md)
- FR-017：工作流按用途区分正式实现、测试和运维资产。探索验证可从假设、候选路径和判断指标追溯到实际证据。[工程资产边界](../../source/project/.agents/sdd/references/sdd-repository-governance.md#工程资产边界) · [测试工程规范](../../source/project/.agents/sdd/references/architecture-rules.md#测试工程与自动化规范)
- FR-018：持久化业务实体的权威存储、写入职责、完成判据、失败和恢复可从项目设计追溯到实际运行路径。[业务实体持久化](../../source/project/.agents/sdd/references/architecture-rules.md#业务实体持久化)
- FR-020：sdd-refactor 按授权交付架构审查，或完成保持已确认业务需求和行为的技术重构。用户可从原检查项追溯实施记录、整改版本的架构复核和行为保持验收，以及 Review Gate、已知偏差和集成准备条件。[架构对齐与技术重构](../../source/project/.agents/skills/sdd-refactor/SKILL.md)
- FR-021：sdd-bugfix 对指定缺陷可完成归因、修复和实际修复版本的定向复验，也支持仅诊断、准备工单或复验。原 Issue 保有稳定编号、处理历史与关闭依据，按原判据和授权更新。[缺陷修复与定向复验](../../source/project/.agents/skills/sdd-bugfix/SKILL.md) · [Issue 关单](../../source/project/.agents/sdd/references/sdd-repository-governance.md#issue-关单)
- FR-022：sdd-deliver 按授权终点完成构建发布、部署、服务与流量运维、排障、回滚、备份恢复和退役，可按依赖组合。执行或触发部署前向用户告知资源和影响评估。直接或间接生产操作须有覆盖本轮的人工确认。正式发布可追溯至实际候选、制品及适用验证证据。[交付与运行](../../source/project/.agents/sdd/references/delivery.md) · [正式发布依据](../../source/project/.agents/sdd/references/release-evidence.md)
- FR-023：同一项目、共享目标或用户角色目标的安装写入互斥。安装失败和中断可恢复，恢复保护外部改动和未触及内容。无法安全恢复时保留记录并阻止继续覆盖。[安装与恢复](../../docs/installation.md#用户级安装恢复)
- FR-024：旧治理入口的 `start`、`record`、`attest`、`check`、`finish`、`commit` 退役。保留现行安装、恢复、只读盘点及独立文档校验能力，既有历史记录可追溯。[旧治理命令退役边界](../../docs/blueprint.md#旧治理命令退役边界)
- FR-025：Agent 向用户呈现对意图的理解并请求确认，沿用适用的既有确认。需由用户决定的需求与方案分别确认，均待定时先确认需求。[意图对齐](../../source/project/.agents/sdd/references/visual-confirmation.md#意图对齐)
- FR-026：sdd-test-loop 按明确请求对指定版本和环境执行范围内全功能点集成回归，交付可复跑指南、逐项证据、缺陷与恢复条件和 Test Gate。Gate PASS 须有全部适用判据及必要人工反馈的证据。[集成测试](../../source/project/.agents/skills/sdd-test-loop/SKILL.md)
- FR-027：支持用户级共享更新、指定项目首次接入、升级、克隆重连、只读检查及恢复。已链接项目可复用同一共享版本，接入后可发现受管技能和角色。标准旧载荷与引用可迁移，项目自有内容和配置受到保护。[初始化入口](../../source/initializer/SKILL.md) · [安装说明](../../docs/installation.md)
- FR-028：`review-prompt` 随 sdd-init 安装为用户级自定义角色，可在任意项目按工单审查运行时提示词、比较候选、按授权修订及专项复验。角色按实际加载路径和已确认依据交付发现、影响、建议或改动，区分静态结果、实跑证据和未验事项。安装按受管清单和实际角色路径校验，保护同名自有角色、用户定制及配置。[角色](../../source/initializer/assets/user-agents/review-prompt.toml) · [安装说明](../../docs/installation.md#更新与冲突)
- FR-029：sdd-develop 可按约定推进单个需求从规格到实施和点对点验收，或停在讨论、规格等授权终点。新需求或需求变更在正式写入和交付实施前各有对应确认，最终交付版本、逐项验收证据与集成准备条件。[需求到实现](../../source/project/.agents/skills/sdd-develop/SKILL.md)
- FR-030：sdd-doc-consistency 可在实际只读权限下审查指定项目文档，交付冲突、重复、失效或错位引用的证据及处理建议。运行时提示词及指令排除在该角色职责之外。[文档交接](../../source/project/.agents/sdd/references/delegation.md#文档交接)
- FR-031：Main 按用户授权调度独立技能 Agent，接收回执并在适用前置满足时接续获授权的阶段。单阶段交付可停在指定终点；符合直接执行条件的局部操作和技能未覆盖事项可由 Main 承接。[职责与交接](../../source/project/.agents/sdd/references/sdd-repository-governance.md#职责与交接) · [技能 Agent 的启动与接续](../../source/project/.agents/sdd/references/delegation.md#技能-agent-的启动与接续)
- FR-032：sdd-architecture 可建立、补齐和演化仓库级 Blueprint，交付经用户确认的内部一致设计、适用的取舍与契约以及关键假设的验证依据。纯讨论或专项评估按授权终点交付。[架构蓝图设计与演化](../../source/project/.agents/skills/sdd-architecture/SKILL.md)

- FR-033：本仓白皮书按专属 Skill 提供的结构模板维护已确认设计；审查流程、RW-01～RW-12 及子项、对象矩阵、取证和统计口径归 Skill 及其参考文件，保留设计条款和 Spec 追溯。各批次 Review 报告按执行阶段增量记录受审范围与版本、依据、逐对象及逐子项覆盖、结论、证据、发现、修复复验、未验范围和质量成本。静态与行为证据分别呈现，源码体积、实际加载量和运行消耗分别记录，review 与 testcase 的 token、时长分别统计。成本统计使用可取得的实测，缺实测标为未测，不为填报另跑用例。已有报告及原始证据保留原版本语境。[模板与执行入口](../../.agents/skills/sdd-workflow-review/SKILL.md#资源与产物)
- FR-034：`sdd-workflow-review` 仅在本仓由用户显式启动，按绑定版本的设计依据、Spec 和 Skill 判据开展全面评审。先静态核对受审对象和全部 RW 子项，形成发现和待验清单。适合并行时按能独立交付的结果分派子 Agent，静态审查复用对象矩阵，回归按待验证问题或共用夹具分组。每单由同一负责人取证和初判，主 Agent 按任务选择负责人配置、决定实跑范围并统一归并。优先复用适用证据，在授权内为关键疑点或必要验收隔离执行最小场景，按风险和整版结论所需证据扩大回归。A/B 仅用于已有证据无法回答的明确比较目标，同一负责人隔离运行两侧并初判，保持受测配置一致和实验条件可比。评审可新增本轮报告和证据，审查请求本身不授权修复源码。获对应授权后沿原判据复验修复版本和关联影响，保留改前及复验证据、失败和未验范围。修改已确认设计仍须有相应决定。[本仓全面评审](../../.agents/skills/sdd-workflow-review/SKILL.md)

## 验收条件

| ID | 对应需求 | 条件与预期 |
|---|---|---|
| AC-001 | FR-001 | 在接入项目中，从已确认需求可定位对应工单、同一份 Plan／Task 和适用验收证据，各产物可由对应职责交付。 |
| AC-002 | FR-002、FR-004 | 构建物、分发清单及来源可核对，新装可用，受管引用可解析。运行已安装脚本生成字节码后，同版重装与升级成功。载荷或受管文件缺失、已安装内容有定制或其他额外文件、新载荷含未登记字节码时，报告冲突并保护现有内容。迁移后的历史来源和原版本证据仍可定位。 |
| AC-003 | FR-003 | 核对只提交、未指定后续路径、独立平台操作及提交／合并后部署等组合。只提交返回分支及 SHA，路径未定时先提交再交选项。核对平台与实例、fork 源／目标、远端基线、范围外改动保护、对象复用及实际平台状态；同步或合并条件未满足时不推进依赖步骤。部署可回溯已核验的提交或制品，切流以实际版本就绪为前置。 |
| AC-004 | FR-005 | 给出单项、多项依赖或可分批验证的已授权工单，实施者用同一份 Plan／Task 交付实际改动、局部证据及待验判据。工单可追溯适用的验收计划、方案和证据，业务与架构判据分别关联。对照阶段内可补齐及需跨阶段、决策或补授权的缺项，核对回执先到调用者，由调用者按职责接续，其他已授权且就绪的项继续。无 Blueprint 或工单未直接引用时，明确工单仍可依自身判据执行。 |
| AC-005 | FR-001、FR-006 | 从 Blueprint 用例及验收维度能定位细化 Spec／AC，已确认内容在唯一正文可查。修改语义而不改文档结构时仍能追溯上游依据和直接影响。 |
| AC-006 | FR-006 | 用已确认的阈值变更验证原位归并，保留仍适用的例外与编号并更新直接引用。用讨论、设计归并、调研及实际验证分别核对授权和产物归属；关联 Code Review Rules 可能过时时提示用户。 |
| AC-007 | FR-007 | 校验英文模板、名称、入口引用、清单和安装检查一致。正式时序模板唯一，模板变更不改变已有项目产物路径，测试报告可按需建档。 |
| AC-008 | FR-008 | 给定同一改动，局部自验仅证明实际局部覆盖，后续验收或审查按自身判据取证。实测回执带场景、版本、覆盖和缺口。执行验证或审查的前后，被测实现内容一致。 |
| AC-009 | FR-009 | 对一轮测试及后续复验分别查到相应版本、逐项证据和覆盖。简单批次可用现有记录并引用依据，必备字段、未执行项及历史失败均可查询，指南和状态指回实际报告。 |
| AC-010 | FR-010 | 对需要界面的需求，用浏览器复跑拟交付的同一份 HTML，核对入口、交互、业务状态、模拟边界、版本及确认记录。复用后能追溯确认版本，模拟与正式运行分别取证。 |
| AC-011 | FR-011 | 在隔离项目逐个只注册受验角色，保留适用资料和共享资源，工作流 Skill 不可用。用产品原型、正式设计归并、独立实施、运维结果回读及只读一致性审查核对实际角色、动作、产物和回执。 |
| AC-012 | FR-012 | 从一个治理入口可定位适用阶段、产物和规则。仅讨论需求或架构时，能在无固定流程、模板填报和架构符合性门禁的情况下交付讨论结论。正式写入 Blueprint 时核对设计内部一致性。按用户要求依据两个设计版本生成及更新项目规则，在 Review 中核对映射、缺失或过时提示、实际违规及复核，升级保留项目规则。 |
| AC-013 | FR-013 | 新装可使用 CLI 及说明，缺失载荷按 AC-027 拒绝。覆盖 UTF-8、结构、重复编号、本地和中文锚点、越界输入及文本／JSON 退出行为。前后文件字节一致，结果仅表示机械检查覆盖。 |
| AC-014 | FR-014 | 可从三类范式定位八项规范指导及实际落实对象；项目规则包含适用对象与条件、确认依据、检查方法、通过条件和检查时机。用项目设计、契约及实际路径核对适用规则，覆盖工程结构符合与偏差、观测数据保存、环境装配、测试隔离、不适用、证据不足及契约冲突。未确认策略保留待决，未执行或证据不足不判通过。 |
| AC-015 | FR-015 | 用 Demo、算法对比和已选实验验证资产归属。沿实际依赖、动态加载与运行配置核对正式装配隔离，覆盖只改配置的情况及测试调用正式模块。 |
