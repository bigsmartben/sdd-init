# Agent 工程协作接入

## 产品范围

本文统一使用“Main Agent 治理规则”（Agent Rule）指代 Main 的对齐、沟通语言和路由规则。规则由 `agentsmd_template.md` 分发到目标仓库，根目录的 `AGENTS.md` 提供主会话入口。

用户通过 UVX 初始化用户级 sdd-init Skill，并在 Codex Desktop 或 GitHub Copilot App 的目标仓库中调用。Skill 提供接入工单、Main 模板、六个垂直角色的宿主适配资源与验证方法。CLI 执行配置预览、写入和检查。用户决定未标记仓库规则的升级方式和目标 CI 的接入。接入后的工程任务由 Main 路由，各垂直角色在自身职责内交付。

## 验收用例

1. Main 用场景、使用者、操作、可观察结果、交付终点和验收条件理解任务，只表达待确认的部分。异常核对实际与预期。沟通沿用项目术语，项目暂无术语时沿用用户称呼。
2. 直接交付和调度交付是同一主任务的两条路径，均由主会话对用户负责。意图确认前，主会话走 Fast Path 直接沟通并按需只读取证。首次确认同时对齐目标、交付终点、验收条件和执行路径，结合任务说明两条路径和推荐理由，由用户选择。已有明确选择时沿用。文件数、失败次数和跨模块等信息只用于确认前的路径判断。确认后沿选定路径执行并处理阻塞，无法继续时报告阻塞原因和恢复条件。
3. 直接交付由主会话执行、验证并交付。调度交付由主会话通过宿主原生子 Agent 调度，接回产物、验收并交付。Main 按产物选择主责角色，派单写明授权范围和验收条件。角色在本单内闭环并自验，跨职责事项带证据和待决项交回主会话。跨角色交接及角色目录、热词和路由归 Main。
4. 普通验证请求按双路径处理。Main 跨轮维护陪测记录，当前用例的反馈接续本轮。uat-observer 每单完成启动、观测、重载核对或清理，以入口可用、对应时段证据、实际请求命中新代码或本轮资源状态为验收依据。修复后先验证重载，再由用户复验并确认体验。结束或取消时仅清理本轮拥有的资源。失败返回 ERROR、原因、剩余资源和恢复条件。
5. 安装包可通过 UVX 在临时用户目录初始化 sdd-init Skill。Skill 入口、内置工单、Main 模板、两端角色适配和命令可达。相同内容重复初始化成功，异内容冲突保留现有内容并报告位置。
6. 显式调用 `/speckit.*` 时遵循目标项目现有的命令与宪法，按任务标签调度专家；缺少所需契约时说明阻塞。
7. 六个角色的正文与元数据各自描述本职。Main 按工单交接所需材料，关闭父会话历史继承，省去角色目录、其他角色身份及调度历史。Main 以产物和证据核对验收条件。
8. tester 根据变更风险开展集成阶段的用户质量评估，可自主扩展自动化和探索性场景，并维护项目约定的测试资产。逐项依据标准记录 PASS 或 FAIL；缺少口径时记录 NEEDS_DECISION、实测与用户影响，可继续其余取证；执行受阻记 BLOCKED。缺少范围或评估目标才退回输入。探索发现须经确认才能形成修复任务。
9. devops 按计划、检查、构建或发布终点交付。在授权内处理工程故障并从失败点继续。构建核对制品，发布核对目标端版本及制品。结果不明时先查实态再决定是否重试。逐项报告实际结果、失败证据、待授权项与其他未执行原因。
10. 历史或外部 [Coder] 标签和当前 [Implementer] 标签均路由至 implementer，安装包只分发当前角色名。
11. 消息开头的单个【热词】选择场景，同义入口交付同类结果。入口、角色或路径及对应交付物集中在 [Main 路由](../../source/project/.codex/agentsmd_template.md#路由)。正文引用和语法讨论走普通对话。
12. 一对括号内以 `->` 串联的阶段从左到右执行，相邻括号各自独立。按确认的路径、输入和授权推进，影响结果的取舍在交接点确认。调度计划时按主题派单，本阶段交付步骤、依赖、风险和验证方法，单独请求计划时到此结束。
13. architect 只读完成蓝图，按系统、子系统和组件划分职责，覆盖边界、依赖方向、关键接口与实施约束。用关键业务用例走查，冲突自行修订并复核。架构重构以现有业务行为为基线，交付可独立实施的工单，逐单列改动范围、前置依赖、须保持的业务行为和回归方法。明确获得实施授权后才进入业务源码修改。
14. 安装后的六份角色指令分别声明正向交付、逆向定位与验证、交回条件。调度交付时，已知归属的工作派给所属角色。只读结论、复跑证据或最小补证需求可作为本步产物。交回调用方时说明证据与需要的决定。
15. analyst 只读完成问题描述、预期与实际、复现、诊断及因果验证，报告根因与影响面。完成授权范围内可行的取证仍未定位时，交回已排除项、剩余假设和最小补证需求。implementer 实施已确认的功能、缺陷或重构工单，自主选择实现细节，按单验证约定行为、原复现用例或结构目标与业务行为保持。实施授权覆盖本轮实现与基础单测失败的修正及复跑，业务和非功能需求扩围由 Main 确认。
16. 每个角色附一条本领域的可选工具参考，提示从哪些已有项目入口取证或复跑。角色可按环境换用等效手段；工具选择不构成接单、交付或验收条件。

## 仓库接入验收

17. Skill 在写入前说明目标仓库、当前宿主和版本、接入模式、本次改动、用户选择点和验证方式。宿主或目标无法确定时保持只读并澄清。
18. 根目录 `AGENTS.md` 提供主会话入口，完整 Main 规则由主会话按需读取，存于 `.agents/sdd-init/main.md`。使用当前标记的管理块按预览原地更新，保留块外项目指令。未标记的现有规则按用户选择合并或替换。替换列出将覆盖的内容。配置或规则预览后变更时重新核对并确认。
19. Codex 使用 `.codex/agents/*.toml`，Copilot 使用 `.github/agents/*.agent.md`。每端提供同样的六个逻辑角色，保留经核对的定制配置。重复接入或补接另一端时，复用当前规则并保留另一端现有适配。
20. 本地与 CI 使用同一配置检查入口。检查当前规则、角色格式与路由名，按已接入能力核对必要引用。注册目标仓库 CI 需要用户选定并审阅改动。缺失或不匹配的配置以非零退出码报告。
21. 接入回执分别记录规则写入、角色配置、原生发现和最小只读调用、检查命令、CI 选择及恢复条件。与当前桌面宿主约定的规则和角色验收通过后，记录为完整接入。需要新会话或现场操作时，逐项保留为待验证。
22. 各宿主分别验收分发文本、Main 具名派发、子角色实际继承内容、同级角色发现与委派入口、共享仓库文件可见性。按宿主支持的上下文隔离和本职工具权限配置。缺少对应宿主强制能力时，记录暴露面和待决条件。
