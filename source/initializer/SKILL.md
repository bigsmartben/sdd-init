# SDD 初始化与升级

明确自然语言安装或升级意图即可使用，无需精确口令。仅安装资源与导航，不启动设计、实施、部署验收或 Git 交付。

1. 核对目标仓库、现有 AGENTS、Spec／架构／计划入口及实际安装范围。仅维护本 Skill 时不初始化当前仓库。
2. 使用构建产物中的脚本，路径以实际安装位置为准：

   `python <sdd-init>/scripts/govern.py --root <repo> init`

   首次接入和更新项目托管导航、角色引用均使用 `init`。需要只读盘点时使用 `inspect`。共享资源由用户级安装命令统一更新。
3. 在 `.agents/skills/sdd-workflow` 创建指向用户级共享目录的本地链接。独立沟通原则托管块置于 AGENTS 首部，流程导航单独合并。项目 `.codex/config.toml` 用相对路径引用五个共享角色，`.gitignore` 排除链接和安装元数据。保留管理块外正文、原有换行、模型及其他既有配置。
4. 项目自行处理遗留文件和文档链接。同名资源、遮蔽入口和冲突的链接会在预检中定位，处理冲突后重新运行 `init`。
5. 同一项目安装互斥；普通写入失败恢复本次文件和新建链接，异常终止后的下次 init 先恢复未完成操作。恢复记录位于目标仓库 `.sdd-init-recovery/`；遇到外部修改或恢复失败时保留记录并报告路径，解除冲突后重新执行同一安装命令，不删除记录后强制覆盖。核对安装内容、导航、重复执行与保护行为；报告新增、更新、保留和阻塞。

初始化器只提供 inspect／init。旧 start、record、attest、check、finish、commit 命令已退役，不保留兼容入口；历史文档不迁移，项目工作由现行 Skills 承担，文档机械检查使用 doc_check.py。

通过项目 AGENTS 中的导航读取共享治理规则、角色分工及模板。已有项目文档索引、治理定制、Spec、Status 和架构正文由项目维护。新工作区缺少链接时重新执行 init。

未初始化的仓库只发现 sdd-init。六个工作流 Skill 随项目链接进入发现范围。核对安装入口时读取[独立沟通原则片段](assets/communication-fragment.md)与[流程导航片段](assets/agents-fragment.md)。已有文档只在明确的文档任务中按实际来源归并，不用模板覆盖。

业务确有模型提示词需求时可参考 [prompting](assets/prompting.md)，沿用项目已有规范；仅开发工具使用 AI 不构成创建业务规范的理由。观测样例按实际项目需要使用，不由初始化确认架构选型。

例：对空项目执行 init 后，核对六个 Skill、五个角色和导航，再次执行应无新增变更；同名资源存在冲突时报告路径并停止。
