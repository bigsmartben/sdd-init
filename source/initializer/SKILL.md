# SDD 工作流环境落地

唯一职责是完成目标项目 sdd-workflow 的环境落地：

1. **资产准备**：接入 Skills、专业角色、规则、模板和工具，建立链接与角色配置。
2. **目标 AGENTS.md 注入**：以 [Main 规则与能力入口](assets/agents-fragment.md)为唯一注入源，组装、写入和核验单个托管块；不另设沟通块或 Main 角色。

检查与恢复是落地手段；接入后的调度和业务交付不属本 Skill。Main 与专业执行者各按注入入口及其引用规则履职。

## 执行

用户发起或目标项目缺少本地链接时，Main 按原生机制直接执行；明确禁止写入或环境不允许时报告阻塞。仅需隔离上下文或协作时委派初始化技能 Agent，不向自己派单或回执。沿用已明确的目标、范围和授权，核对项目、操作、分发来源、版本及影响范围，区分用户级更新、指定项目接入或两者。具体命令、旧角色迁出策略及恢复路径见[安装与恢复](assets/install.md)。

1. `inspect` 检查来源与版本、载荷完整性、链接、托管块、角色配置和未完成事务。只检查则返回实际状态、路径及建议，不写入。
2. 按记录恢复未完成操作并重做预检。旧独立沟通块或双块状态不自动迁移；同名自有资源、遮蔽入口、定制内容或归属不明时保留并交用户裁决。已登记旧 review-prompt 的直接迁出按安装规则执行。常规迁移与配置写入直接做，扩围或新增权限另确认。
3. 调用安装工具。两种操作均获授权时先更新用户级共享资产，再对指定项目执行 `init`（首次、升级、重连共用），刷新链接、Main 托管块、角色注册和元数据。保护项目正文、历史、模型、MCP 及其他配置；正文归并、业务迁移和内容补齐交 Main。
4. 用回执和 `inspect` 核对本轮版本、入口、配置、迁移与事务结果，确认再次执行无待写项。客户端可查时核对已接入项目的实际发现和信任配置。失败先查状态，只恢复本次触及的文件与链接；事务后外部编辑或损坏记录保全并报告恢复入口。

待安装的 Skill 与角色仅作载荷核验。环境排障需协作时，只用已可用执行者，交接目标、授权、文件边界、输入和完成判据，回收事实与验证结果。工具源码有缺陷时先完成可行恢复，附诊断交 Main 决定源码维护。源码验证只用隔离 Skill、共享目录、临时项目及必要的历史角色目录。

## 完成

资产接入与 Main 注入均正确且重复执行无待写项，才报告环境落地完成；仅更新用户级资产不算项目落地。返回版本与影响范围、项目增改保留项、可用入口、适用旧角色迁出结果、核验、缺口及恢复条件，结束安装，不自动进入后续业务阶段。
