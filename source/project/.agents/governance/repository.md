# 后续任务的工程资产与协作

适用于规则生效后新增或修改的产物。开工时用一句话说明目标、产物归属和完成条件。已有项目先查 `docs/index.md` 的实际映射；目录在产生产物时创建，每项约定只有一个权威正文。

| 工程资产 | 默认根目录及用途 | 运行边界 |
|---|---|---|
| 开发 | `src/`；真实业务、契约实现、正式提示词和运行配置 | 依据已确认的需求或工程目标。正式入口不得引用、装配或通过配置启用实验实现、夹具或测试运行器。 |
| 测试 | `tests/`；按需使用 `experiments/`、`cases/`、`fixtures/`、`datasets/` | 可行性验证和方案验证全部归测试代码资产，即使使用真实服务。测试可以调用正式模块；用例身份不授予业务权限，不产生正式路由、数据库字段或运行开关。 |
| 运维 | `ops/`；按需使用 `deploy/`、`diagnostics/`、`recovery/` | 通过授权接口部署、诊断、恢复。检查结果标明环境、版本和副作用范围，与产品验收分别取证。 |

实验通过只说明假设在已测条件下得到支持。正式采用时，开发在当前任务中关联已确认目标，说明选定行为、契约、需剔除的实验装配及验收条件，再实现和验证。允许复用已选代码。设计确认、实验通过、局部自验、部署成功和产品验收分别记录。

## 文档与产物落点

项目文档放在 `docs/` 下，直接按用途命名。研发规则位于 `.agents/governance/`（repository.md、coding.md、test-data.md、environment.md 等按需建立），Skills 位于 `.agents/skills/`。根 AGENTS 只导航，`docs/index.md` 维护项目实际映射。已有权威需求、蓝图、时序或契约沿用映射，新文档按以下默认位置创建。

| 产物 | 默认落点 |
|---|---|
| 能力规格或权威正文引用 | `docs/capabilities/<能力>/requirements.md` |
| 中、高保真产品原型及静态资源 | `docs/capabilities/<能力>/prototypes/<用例>/index.html`，旁设 `assets/` |
| 实验记录与复现代码 | `docs/capabilities/<能力>/experiments/<验证主题>/README.md` ↔ `tests/experiments/<能力>/<验证主题>/`，能力和主题同名 |
| 架构边界与不变量 | `docs/blueprint.md` |
| 场景时序、接口契约 | `docs/sequences/<场景>.md`、`docs/contracts/<接口或协议>.md` |
| 测试计划、验收报告、运维手册 | `docs/test-plans/`、`docs/reports/`、`docs/runbooks/` |

产品 HTML 用于确认用户操作和预期体验；技术验证 HTML 随实验代码保存。产品设计沟通物不是第四类工程代码。模板位于 `.agents/sdd/assets/`，按当前任务选用。

## 需要人类判断时

产品负责用例、运行环境、非功能指标与集成后的可视化验收；架构负责系统设计、模块职责边界与不变量；测试决策负责测试范围与数据集选择。项目协作约定指定各决策人。Agent 在已确认边界内负责契约、实现、修复、测试执行、部署及排障，仅在产生实质决策变化时对齐。讨论或验收本身不扩大执行授权。

用终端用户理解的语言说清谁在什么情况下做了什么、期望看到或听到什么。需要用户决策时，Preview 必须可视化展示选项与可观察后果；需要用户 Review 或验收时，沿同一场景可视化展示实际结果、差异、证据和未验证项。

| 决策 | Preview | Review |
|---|---|---|
| 产品 | 中保真 HTML 可操作地走通用例及异常路径 | 在约定环境操作实际集成版本，对照原型和指标 |
| 架构 | 时序图展示决策者、执行者、失败处理与体验后果 | 将实际证据标到同一时序步骤，区分符合、偏差、未验证 |
| 测试 | 测试计划覆盖矩阵展示场景、边界和候选数据集 | 同一矩阵标出通过、失败、未测、阻塞与证据 |

例如：后台暂时记不下这一轮时，用户仍能听到回复并继续说下一句。Review 分别展示回复是否听到、下一句是否继续；技术事件附在对应步骤供追溯。
