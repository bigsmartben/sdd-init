# 实施与局部自验

按明确工单、必要代码上下文和任务授权实施，也承接明确的缺失测试及已授权探索。疑似缺陷如缺少可执行的修复依据，先按当前授权调查，在回执中记录事实、假设和缺口。已确认的架构变更工单提供对应决定、可执行目标及完成条件。复用已确认的 HTML 原型时读取[原型规则](prototype.md#正式实现中的复用)。

## 实施依据

用工单目标、适用判据及相关代码和测试确定读取范围。项目索引只用于定位所需材料。涉及 Blueprint 或 ARC 时，只读取工单直接引用且本轮适用的已确认条款，索引及其他文档中的关联链接本身不构成工单引用。Code Review Rules 的检查和架构符合性判断归架构审查。架构依据不足时，在回执中记录具体缺项。

## 执行与验证

1. 核对工单的交付目标、范围和完成条件。需求、缺陷和 Review 整改工单须提供[验收计划与方案](sdd-repository-governance.md#验收计划与方案)或可访问引用。定位代码和测试，读取工单引用且本轮适用的依据。架构任务按已确认结论与工单边界实施。新增资产或改变用途时查[工程资产边界](sdd-repository-governance.md#工程资产边界)。工单缺项按[实施交接](delegation.md#实施交接)回报调用者。
2. 读取 [Plan](../assets/plan_template.md)。接续已有任务时先核对原 Plan 的状态和证据。需求实施按 Spec 的用户场景、AC 和已确认优先级拆分，将相关代码、契约、数据约束和验证映射到 Task。引用适用条款并落实到完成条件。其他场景按其上游目标和完成条件拆分。对包含验收计划与方案的工单，按其安排实施和局部自验，关联相应 Task，标明局部自验覆盖及待验事项。用直接依赖表达共用前置和执行顺序，核对目标覆盖、依赖无环、可并行项和各批的局部验证入口。记录足以开工的方案，标出影响方案或顺序的未知项，在据此推进前查证。涉及跨职责决定的取舍在回执中列出可行选项、证据和影响。开工前在当前任务或已有 Plan 中输出 Task 清单。阶段所需确认及实施授权齐备后，按 Plan 直接执行。简单修复可只列一项，写明目标、完成判据及局部检查入口。
3. 按已确认的优先级选择就绪项，核对前置 Task 的结果及实际环境、配置和依赖。任务涉及工程骨架或工具配置时，按实际工具链核对所需配置和忽略规则。开始实施时更新状态。修改同一文件的 Task 串行，改动与共享状态不会冲突时才并行。编写或修复必要的测试代码和自动化脚本。任务约定 TDD 或需要以测试证明待修缺口时，先运行对应测试，确认它因预期缺口失败，再实现并重跑。按上游目标、需求或契约设置断言，探索任务按明确假设、比较目标和指标验证。局部自验以代码单测为主，按工单性质和影响补充必要的定向回归、构建或类型检查。
4. 在 Task 完成或批次交接前核对相应结果、覆盖及版本证据。Task 达到完成条件、局部自验通过、证据齐备且无未解决的失败或阻塞时，标记完成。执行或检查失败时记录失败状态和证据，修复并复验。未满足的前置条件使依赖项标为阻塞，注明恢复条件，其他已就绪且获授权的 Task 继续。代码或验证证据改变前提、改动范围或顺序时，在同一份 Plan 更新受影响的方案、改动位置与依赖，保留已有编号及仍有效的证据。预期结果变化、架构冲突或出现需跨职责决定的取舍时，在回执中记录待确认内容及受影响项。
5. 交付前按目标、约束和最新 Plan 核对实际改动、版本、局部验证入口、证据及覆盖缺口。本轮仅要求实施和局部自验时，Task 完成即交付。需正式留存局部自验时按[文档写入规则](document-writing.md)归并并在 Plan 引用。存在约定的后续验收、集成测试或架构复核时，回执逐项关联局部证据和待验判据，附原验收计划与方案、运行入口和已知准备条件。

缺陷工单须给出原 Issue、要恢复的行为、已验证的原因与证据、影响、边界及修复的验收计划与方案。Plan／Task 关联原编号和归因证据。发现归因反证或收到复验失败证据时，沿原编号记录版本、结果和受影响项。归因被反驳时暂停该修复方向，在回执中说明反证及待取证项；方案需修订时沿同一 Plan／Task 接续，其他已授权且不受影响的任务继续。定向实测证明修复版本的原故障或等价场景已恢复且必要回归通过时，局部证据可满足工单判据。

缺失测试以场景依据及应补覆盖为输入，引用现有 Issue（如有）或本轮验收指南。属于集成批次的测试补充或修正时，按工单指定的测试资产边界编写并局部自验，沿用已确认判据，在回执中提供可运行入口、覆盖和证据，记录被测实现偏差及相关证据。架构整改以原检查项、整改目标、实现范围、须保持的行为及验收计划与方案为输入。Task 引用原编号。实施后将同一 Plan／Task、实际改动、版本、局部自验证据和待验项回传调度方，供其组织架构复核与行为保持验收。目标或行为影响不清、需超出授权范围时，回执列出受影响项、缺口及恢复条件。

例：按已确认的新规则增加空输入校验，补充定向测试并报告局部覆盖。

按[任务回执](task-receipt.md)向任务调用者返回结果。
