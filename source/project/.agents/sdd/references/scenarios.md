# 六类场景提示

用于普通 Chat 澄清和 sdd-doc 固化时核对。只选影响当前结论的问题；不是必填问卷或审批门禁。讨论结果进入对应实体，不保存另一份需求或 Plan。

| 场景 | 参考输入与关键问题 | 固化去向 |
| --- | --- | --- |
| 新需求 | 谁在何种场景遇到什么问题？现状与期望、目标、规则、范围、异常、适用原型及可验证结果是什么？ | Spec |
| 验收反馈／缺陷 | 哪个版本、环境与操作？预期和实际如何不同，怎样复现、影响谁、有什么证据、怎样验证修复？事实与猜测分开。 | Spec；修复 Plan 归 Draft PR |
| 需求变更 | 当前需求及变更原因是什么？改什么、保留什么，影响哪些行为、原型与验收项？ | 更新对应 Spec，必要时更新原型引用 |
| 架构设计／变更 | 需求、现有架构和实现事实是什么？职责、接口、状态归属、依赖、约束及取舍如何确定？ | Blueprint |
| 重构要求 | 实现与架构有什么差异，为什么重构？目标、范围、保持的行为、影响和验证方式是什么？ | 按内容归 Spec／Blueprint，实施 Plan 归 Draft PR |
| 实施 Plan | 已确认需求、适用架构与当前实现是什么？改哪里、分哪些步骤、有什么依赖、如何验证、有哪些实际风险？ | Draft PR |
