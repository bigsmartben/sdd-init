# HTML 原型交付

<a id="prototype-scope"></a>

## 适用范围

需要通过界面操作确认交互与体验时使用 HTML 原型；后端、库、CLI 或维护任务按实际接口、行为或变更内容确认，无此需要时不要求制作 HTML，也不要求填写原型章节。

## 制作、确认与复用

HTML 原型属于测试代码资产，由 coder 编写修复，validator 验证交互与业务状态，documenter 维护引用、确认记录和测试报告。表达已讨论的界面结构、关键交互与业务状态；模拟数据与结果须可辨识，不接入产品业务写接口。

源码由目标项目版本管理，按测试资产组织，以后续直接复用为目标，复用任务指定的现有组件和代码上下文；架构符合性由 Review 判断，明确隔离模拟装配。目录按仓库治理的默认落点或项目映射，托管平台和访问方式按实际项目确定，本资源不设置默认平台或发布脚本；未确定时说明影响并只继续不依赖该决定的内容。

coder 制作候选后，由 validator 检查关键操作和模拟状态，确认预览入口对应源码版本并可访问，给出操作说明让用户反馈。需访问权限时提供取得方式，不把凭证写到 Spec。未能验证用户访问时如实标为待核验。

Spec 使用 [Prototype Reference](../assets/prototype_reference_template.md) 记录入口、源码及固定版本、适用范围和确认情况。已确认版本保留可追溯入口，新候选使用新版本，不静默覆盖；只有 latest 或临时地址不能表示确认版本。预览失效时报告并恢复对应版本访问，不能换成不同内容沿用旧确认。

实现对应需求时，由 coder 按[正式实现与测试实现隔离](architecture-rules.md#正式实现与测试实现隔离)复用选定原型代码，保留必要验证脚本及原型确认版本的追溯关系，按实际实现范围重新验证。

用户操作并确认后才记录已确认。需求文字与原型冲突回到讨论；结构、交互或业务状态变化重新确认。正式产品沿用项目组件库或设计规范，纯样式和像素还原不作为符合性检查。
