# HTML 原型交付

<a id="prototype-scope"></a>

## 适用范围

需要通过界面操作确认交互与体验时使用 HTML 原型；后端、库、CLI 或维护任务按实际接口、行为或变更内容确认，无此需要时不要求制作 HTML，也不要求填写原型章节。

## 制作、确认与复用

中保真 HTML 原型是唯一的中保真 UI 设计产物，按[工程资产边界](sdd-repository-governance.md#工程资产边界)归入测试资产。产品任务的执行者自行编写、运行和迭代候选，实测关键交互及业务状态，并维护候选引用和确认证据。模拟数据与结果须可辨识，原型与产品业务写接口隔离。

源码由目标项目版本管理。以选定代码可迁入正式模块为目标，优先复用任务指定的组件和代码上下文。目录按仓库治理或项目实际映射确定，预览沿用项目入口。发布、访问或正式实现有缺项时，在回执中记录具体缺项及接续条件，继续可执行的范围。

负责原型的执行者使用项目提供的浏览器入口操作拟交付的 HTML，记录所测版本、运行入口、关键交互和业务状态的实际结果。浏览器验证受阻时，在回执中记录失败或未执行范围和恢复条件。给出预览入口、操作说明和实测结果供用户反馈。核对预览与源码版本一致并可访问。需访问权限时提供取得方式，凭证保留在既有凭证系统。未能验证用户访问时标为待核验。

Spec 使用 [Prototype Reference](../assets/prototype_reference_template.md) 记录入口、源码及固定版本、适用范围和确认情况。已确认版本保留可追溯入口，新候选使用新版本，不静默覆盖；只有 latest 或临时地址不能表示确认版本。预览失效时报告并恢复对应版本访问，不能换成不同内容沿用旧确认。

用户操作并确认后记录已确认。需求文字与原型冲突，或结构、交互及业务状态改变时，在回执中列明差异及待确认事项。符合性检查覆盖结构、交互及业务状态。正式产品沿用项目组件库或设计规范。

## 正式实现中的复用

实现对应需求时按[正式实现与测试实现隔离](architecture-rules.md#正式实现与测试实现隔离)复用已确认版本中的选定代码，保留必要验证脚本和版本追溯。在对应需求的点对点验收或获授权的集成测试中，经正式运行入口核对已确认的结构、交互和业务状态。分别记录 HTML 模拟版本与正式候选的场景和结果。
