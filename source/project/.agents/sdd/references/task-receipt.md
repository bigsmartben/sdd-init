# 任务回执

按[调用关系](delegation.md#技能-agent-的启动与接续)向实际调用者返回：

- **执行模式**：Coder 必须标明 `investigate`、`prepare`、`implement`、`fix` 或 `refactor`；其他角色仅在适用时说明模式。
- **状态**：完成、`needs-input`、`blocked` 或 `partial`。缺少必要输入、外部条件或授权时不伪装为完成；有可交付产物但仍有缺口时用 `partial`。
- **实际产物／改动**：实际文件、行为、Task、记录或结论；调查和准备只交付本模式允许的产物。
- **版本与工作树指纹**：实际分支／提交或制品版本、相关未提交改动和可复核指纹；说明其取得方式和覆盖的对象。
- **检查命令／结果**：实际命令、入口、版本与环境、退出状态和关键结果；失败及随后复验分别保留。
- **覆盖判据**：已覆盖和未覆盖的目标、Spec／AC、Issue、CHK 或工单判据，不以局部断言替代缺失场景。
- **待验或失败项**：未执行、失败、阻塞、人工待验和不适用项，说明原证据位置及对结论的影响。
- **缺口承接**：每个缺口的影响、承接者或实际调用者、恢复条件和重新取证要求。

日志和报告留原处并引用；证据暂无可访问载体时附必要内容，不提交完整推理。按[证据与复用](sdd-repository-governance.md#证据与复用)说明版本、环境、工作树、判据及后续变更对证据适用性的影响。局部自验不代表需求验收、集成 Test Gate、架构 Review 或发布通过；只有对应 Gate 的实际执行者可按原判据结论。

简单任务直接给结果，不强制 JSON、重复台账、固定八节或额外总结调用。专业成功不等于主任务完成，Main 按[整体目标](sdd-repository-governance.md#目标验收与停止)判断。
