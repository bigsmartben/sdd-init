# 执行与协作

本规范承接[仓库治理](sdd-repository-governance.md)规定的协同、授权与权威边界。

Main 对齐任务契约、选择流程、分配归属并汇总结果；designer 在实质设计取舍时介入，其候选结论由 Main 带回用户对齐。讨论只形成方案和待确认结论；确认不自动触发文档写入、实施或交付。

| 角色 | 单一职责 | 默认模型 |
|---|---|---|
| sdd-designer | 讨论需求、架构和方案取舍，返回结论，不写正式文档或代码 | gpt-6-astra |
| sdd-documenter | 使用 sdd-doc 归并已确认结论和执行证据，完成每次写入的一致性检查 | gpt-6.1-terra |
| sdd-coder | 使用 sdd-imp 编写和修复实现、测试及自动化脚本，完成定向单测、构建和类型检查等开发局部自验 | gpt-6.1-sol |
| sdd-validator | 执行集成验证、自动化验证（含 UI、浏览器和 computer-use）、架构 Review 及复验，返回证据，不修改代码或正式文档 | gpt-6.1-terra |
| sdd-delivery | 使用 sdd-commit 代理授权的 Git 与 GitHub／GitLab 仓库协作 | gpt-6.1-terra |

实现、自验、集成验证及复核的分工与完成条件遵循[仓库治理](sdd-repository-governance.md#实施和独立审查)。HTML 原型按[原型交付](prototype.md)执行角色交接；正式文档与证据由 documenter 归并，写入本身完成一致性检查，无独立文档 Review。

部署与服务运行由 Main 使用 [sdd-deploy](../../skills/sdd-deploy/SKILL.md)执行；需要实现修复或文档归并时沿用下列交接职责，不新增部署角色。

角色配置位于 `.codex/agents/`。用户指定的模型优先，推理强度按任务复杂度选择，不固定在配置中。高频文档写入只检查本次结论及其关联影响；架构 Review 和需求验收以判断质量与证据完整性为准，不为节省推理省略必要分析。

会话允许委派时，imp、test、review 等有对应专职执行者的复杂任务默认实际调用对应专职 Agent 持续推进；简单局部任务可由 Main 直接完成，部署与 Git 按各自入口的默认职责执行。以完整可交付工作批次委派，明确共享文件归属并保留他人修改，不按单个文件、命令或细碎步骤机械派工；仅独立且有实际收益的工作并行。实施、验收和 Review 的后续工作优先复用原 coder 与 validator：test 修复返回原验收者复验，Review 整改返回原审查者复核；原执行者不可用时说明原因并由具备职责的执行者接续，要求独立审查时保持独立性。

无法委派时如实说明限制，当前执行者在职责和授权内推进可执行工作；没有模型切换能力不宣称已切换。用户要求独立审查而无独立执行者或人工时保留该项阻塞，不将自查称为独立审查。必要的独立复核和证据以质量为准，不为节省推理或 token 省略；避免重复读取、重复推理、重复报告及过细委派造成无价值膨胀。

## 最小交接

Main 发出：本轮目标与完成条件、授权和写入边界、必要来源的路径／条款／版本。已有任务可直接引用，只补本轮差异；未落盘的确认结论与授权须附简短原意，不能只给接收者无法访问的对话引用。任务交接沿用已有记录，说明哪些要求被替代、哪些工作未完成；不新增接管状态、接收确认流程或环境恢复协调。

| 接收角色 | 按需补充的输入 | 返回重点 |
|---|---|---|
| designer | 待决问题、既定约束 | 推荐结论、关键取舍、待确认点 |
| documenter | 确认来源或执行证据、目标正文 | 实际落点、关联同步、未决冲突 |
| coder | 明确上游任务及完成条件、Task／缺陷／Review 检查项编号、代码归属、复现入口；Review 整改提供具体目标和行为保持边界，不交由 coder 解读架构依据或读取 Code Review Rules | 改动位置、局部自验结果、待验证范围 |
| validator | 验证目标与场景、运行版本／环境、操作与数据入口；Review 提供项目 Code Review Rules 与已确认设计的定位，缺失或过时由 Review 提醒用户维护 | 逐项结果、预期与实际差异、证据引用、未测或阻塞 |
| delivery | 授权终点、改动或议题归属、平台／实例与源／目标、已有对象及有效检查引用 | 实际终点、Issue／PR／MR 链接、SHA／远端状态、检查／审批阻塞 |

返回先给结论，只附本轮差异、必要证据定位及未完成项；证据保留版本、范围和可复查的命令或操作入口。完整日志、源码、报告留在原位置，交接不整段复制；证据尚无可访问载体时附最小必要内容，不为交接另建报告。无关字段省略，不强制套表或固定字数，不以压缩丢失失败、授权限制或必要上下文。

同一工作批次的关联证据可合并交接，由 sdd-doc 在必要节点归并；不因单个字段或状态更新反复委派，不将全部记录落盘作为启动已授权后续工作的前提。正式记录仍按各流程完成要求归并，问题状态与批次事实保留各自权威来源。简单任务沿用当前任务或既有载体，保留必备结构，各节仅填写本轮必要事实并精确引用已有依据；无缺陷不建 Issue，复验可在同一报告文件新增明确批次，保留历史。面向用户的呈现按[可视化沟通规范](visual-confirmation.md#呈现与确认)，不以完整模板代替结果摘要。

接收者按引用读取相关正文，缺少关键输入时只索取缺项。Main 复用有效证据，在缺口、失败、矛盾或相关变化时复核受影响部分，不重复执行全套检查或重写各角色报告；仅补充验收事实或无关变化不扩大验证范围。续派只传变化及受影响编号；缺陷和缺失验证代码交 coder，证据缺口由原 validator 补查，文档冲突及证据落盘交 documenter，设计缺口回讨论，不要求所有角色轮转。职责交接不扩大授权或自动触发其他流程。
