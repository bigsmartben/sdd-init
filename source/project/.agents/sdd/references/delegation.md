# 执行与协作

Main 对齐任务契约、选择流程并汇总结果。讨论只形成方案和待确认结论；确认不自动触发文档写入、实施或交付。

| 角色 | 单一职责 | 默认模型 |
|---|---|---|
| sdd-designer | 讨论需求、架构和方案取舍，返回结论，不写正式文档或代码 | gpt-6-astra |
| sdd-documenter | 使用 sdd-doc 归并已确认结论和执行证据，完成每次写入的一致性检查 | gpt-6.1-terra |
| sdd-coder | 使用 sdd-imp 编写和修复实现及测试代码 | gpt-6.1-sol |
| sdd-validator | 执行验证并返回证据，不修改代码或正式文档 | gpt-6.1-terra |
| sdd-delivery | 使用 sdd-commit 执行授权 Git 交付 | gpt-6.1-terra |

验证任务明确区分实施局部自验、需求验收和蓝图与实现的一致性 Review，每次只按所选目标取证。发现代码缺陷交给 coder，文档冲突交给 documenter，设计缺口交回讨论。正式文档和 Status 统一由 documenter 写入；无独立文档 Review。

角色配置位于 `.codex/agents/`。用户指定的模型优先，推理强度按任务复杂度选择，不固定在配置中。高频文档写入只检查本次结论及其关联影响；架构 Review 和需求验收以判断质量与证据完整性为准，不为节省推理省略必要分析。

仅在会话允许委派且分工有实际收益时使用角色。交接目标、必要来源、写入边界和验收条件；共享文件明确归属，保留他人修改。当前执行者可按同样职责边界顺序执行；没有模型切换能力时如实说明限制，不宣称已切换。用户要求独立审查时须由独立执行者或人工完成。

各执行者返回实际差异、命令、结果、快照和未完成项。Main 复用有效证据，仅在失败、矛盾或快照变化时复核受影响部分；职责交接不扩大授权或自动触发其他流程。
