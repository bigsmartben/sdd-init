# 执行与协作

Main 负责对齐任务契约、选择流程、协调执行与汇总证据；实际执行模型按工作类型选择，不按 Skill 名称或角色名称绑定整段任务。项目角色通过 `.codex/agents/*.toml` 注册，见下方“项目角色配置”；Main 仍负责协调，不以角色注册自动扩大委派或执行权限。

## 模型分工

| 工作类型 | 模型 | 职责边界 |
|---|---|---|
| 需求、架构、方案等设计工作 | `gpt-6-astra` | 需求分析、架构与接口设计、方案取舍及待确认的设计结论 |
| 编码工作 | `gpt-6.1-sol` | 业务、工具及测试代码的编写、修改、重构与缺陷修复 |
| 文档落盘、测试、验证、集成、交付与 Git 工作 | `gpt-6.1-terra` | 已确认结论的文档归并与落盘、测试执行、架构符合性检查、结果复核、集成验证、提交、分支、push、PR/MR 与 merge 等交付操作 |

上述为用户确认的项目模型分工；terry 已确认指 `gpt-6.1-terra`。推理强度由执行者按任务复杂度、风险和模型支持自行决定，不为角色固定强度；项目配置不固定角色或子 Agent 的推理强度；调度者在启动时按任务选择，未指定时沿用运行环境的继承或默认规则。用户针对当前任务明确指定其他模型或强度时，以该指示为准。

同一任务包含多类工作时分别按表选择：设计结论由设计模型产出，代码由编码模型实现，文档落盘、验证与交付由 terra 执行；发现代码缺陷回到编码工作，涉及需求或架构决定则回到设计工作。Main 维护统一任务契约和状态写入归属；局部自验与完整验收仍按各流程的范围执行，不因换模型扩大验证或写入权限。

文档落盘包括 Blueprint、Spec、Status、任务记录及治理规范的写入、归并和引用维护，统一使用 `gpt-6.1-terra`；astra 负责设计结论，terra 按确认来源落盘，不新增设计决定。实施或审查产生的状态事实仍由原执行者提供，文档写入按此分工执行，无需另建重复文档流程。

Main 当前实际模型符合当前工作类型时可直接执行；需要其他模型时，仅在当前会话允许委派或提供模型切换能力的前提下选择匹配执行者。运行环境不支持指定模型或切换时，报告限制与受影响工作，不静默替换模型，不声称已切换或已按指定模型执行。规则落盘本身不等于运行时模型已切换。

## 项目角色配置

角色定义位于项目 `.codex/agents/`，每个 TOML 包含 `name`、`description`、`model` 和 `developer_instructions`，不设置 `model_reasoning_effort`。角色模型由 TOML 固定；推理强度由调度者按任务支持情况选择，不以角色文件锁定。无需在 `.codex/config.toml` 中添加逐角色注册表；该文件保留 Agent 开关和并发上限。

| 角色 | 项目配置 | 对应职责 |
|---|---|---|
| `sdd-designer` | [sdd-designer.toml](../../../.codex/agents/sdd-designer.toml) | astra：需求、架构、方案设计，返回设计结论 |
| `sdd-coder` | [sdd-coder.toml](../../../.codex/agents/sdd-coder.toml) | sol：业务、工具及测试代码编写与修复 |
| `sdd-documenter` | [sdd-documenter.toml](../../../.codex/agents/sdd-documenter.toml) | terra：sdd-doc、正式文档与 Status 落盘 |
| `sdd-validator` | [sdd-validator.toml](../../../.codex/agents/sdd-validator.toml) | terra：测试、架构检查、验证、集成与证据复核 |
| `sdd-delivery` | [sdd-delivery.toml](../../../.codex/agents/sdd-delivery.toml) | terra：Git 与交付操作 |

角色继承父会话的权限、提供方和工具边界，配置不覆盖主会话模型。已运行会话的角色可见性须以实际加载结果为准；文件存在、格式正确不代表已用指定模型完成任务。配置格式依据 [OpenAI 官方自定义 Agent 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)。

## 执行与交接

长程任务仅在独立分工有实际收益且当前会话允许委派时选择可用执行者；模型遵循上表，推理强度按任务决定。可以并行独立实施任务或独立检查；共享代码或 Status 写入须顺序协调。模型分工不自动授权新增会话、委派、外部调用或扩大任务范围。

只传目标、必要来源、写入边界和验收条件，复用已有适合的执行者，不复制完整历史，不递归委派。Main 核对关键差异和真实证据，缺口、矛盾、失败或过期时才深入复验。各执行者返回状态事实与证据，由 terra 按明确写入归属更新 Status，不为落盘增加重复流程。

保留 AC/ARC、跨 Spec、当前快照和授权边界。Main 自查不能称为独立审查；用户要求独立审查时须由独立执行者或人工完成，不支持时报告未完成。普通工作不以线程 ID 或模型元数据检查为前置条件。
