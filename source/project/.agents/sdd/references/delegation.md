# 执行与协作

跨流程接续和阻塞处理见[职责与交接](sdd-repository-governance.md#职责与交接)。

designer 在实质设计取舍时介入，候选结论由 Main 带回用户对齐。

| 角色 | 单一职责 | 默认模型 |
|---|---|---|
| sdd-designer | 讨论需求、架构和方案取舍，返回结论，不写正式文档或代码 | gpt-6-astra |
| sdd-documenter | 归并已确认结论和执行证据，完成每次写入的一致性检查 | gpt-6.1-terra |
| sdd-coder | 按 sdd-imp 编写和修复实现、测试及自动化脚本，完成定向单测、构建和类型检查等开发局部自验 | gpt-6.1-sol |
| sdd-validator | 按任务执行用户功能集成测试（含适用的 UI 自动化、浏览器和 computer-use）、Bug 归因检查、定向复验或架构 Review，返回证据 | gpt-6.1-terra |
| sdd-delivery | 使用 sdd-deliver 代理授权的 Git 与 GitHub／GitLab 仓库协作 | gpt-6.1-terra |

实现、自验、集成验证及复核的分工与完成条件遵循[仓库治理](sdd-repository-governance.md#实施和独立审查)。HTML 原型按[原型交付](prototype.md)执行角色交接；正式文档与证据由 documenter 归并，写入本身完成一致性检查，无独立文档 Review。

部署与 Git 交付默认由 Main 执行，Git 交付可交给 sdd-delivery。Main 负责对齐待选的交付路径，并按 Git 回执接续已指定的部署。

角色定义位于用户级共享资源中，项目 `.codex/config.toml` 用相对路径引用。用户指定的模型和推理强度优先；否则 Main 按子任务自身复杂度独立选择推理强度，在启动调用中显式传入，不直接继承主任务强度，也不在角色配置中固定。独立判断的结果可以与 Main 相同。使用 `collaboration.spawn_agent` 时，以 `fork_turns="none"` 配合 `reasoning_effort`，并通过 `message` 传递必要上下文；启动接口不支持显式设置时如实说明限制，不宣称设置成功。高频文档写入只检查本次结论及其关联影响；架构 Review 和集成测试以判断质量与证据完整性为准，不为节省推理省略必要分析。

## 委派与独立性

会话允许委派时，imp、test、review 等有对应专职执行者的复杂任务默认实际调用对应专职 Agent 持续推进；简单局部任务可由 Main 直接完成。以完整可交付工作批次委派，明确共享文件归属并保留他人修改，不按单个文件、命令或细碎步骤机械派工；仅独立且有实际收益的工作并行。实施、集成测试和 Review 的后续工作优先复用原 coder 与 validator。已明确范围的集成补验返回原测试执行者，Review 整改返回原审查者复核；原执行者不可用时说明原因并由具备职责的执行者接续，要求独立审查时保持独立性。

无法委派时如实说明限制，当前执行者在职责和授权内推进可执行工作；没有模型切换能力不宣称已切换。用户要求独立审查而无独立执行者或人工时保留该项阻塞，不将自查称为独立审查。必要的独立复核和证据以质量为准，不为节省推理或 token 省略；避免重复读取、重复推理、重复报告及过细委派造成无价值膨胀。

## 文档交接

需要正式落盘时，Main 将已确认结论或真实执行证据连同写入范围交给 `sdd-documenter`，按[最小交接](#最小交接)提供目标正文及必要来源。其他子代理将需要归并的材料交回 Main 接续。用户可直接说“请委派 `sdd-documenter`，将已确认的结论写回 Spec”。纯讨论留在当前会话。无法委派时，Main 可按[文档写入规则](document-writing.md)承接已授权的写入和检查。

## 最小交接

Main 发出：本轮目标与完成条件、授权和写入边界、必要来源的路径／条款／版本。已有任务可直接引用，只补本轮差异；未落盘的确认结论与授权须附简短原意，不能只给接收者无法访问的对话引用。任务交接沿用已有记录，说明哪些要求被替代、哪些工作未完成；不新增接管状态、接收确认流程或环境恢复协调。

| 接收角色 | 按需补充的输入 | 返回重点 |
|---|---|---|
| designer | 待决问题、既定约束 | 推荐结论、关键取舍、待确认点 |
| documenter | 确认来源或执行证据、目标正文 | 实际落点、关联同步、未决冲突 |
| coder | 上游定义的目标、范围、通过判据及可执行验收方案或引用、已有编号和必要代码上下文。需求引用 Spec／AC，Bug 沿用原 Issue，Review 整改沿用原检查项的复核方案 | 实际改动、版本、局部证据与已覆盖判据、仍待验证的判据及可用运行入口。Bug 归因反证带原编号退回 |
| validator | 集成测试提供明确的范围、场景与判据、目标版本和环境、上游验收文档或已有指南、已有入口及有效证据。归因检查提供候选原因与可区分的预测；单独局部复验提供原 Issue、修复版本和验收方案。Review 提供规则与已确认设计的定位，整改复核沿用原检查项的方案。混合工单分别引用各自的判据与执行者 | 逐项结果、预期与实际差异、证据引用、未测或阻塞。集成测试交付本轮验收文档或链接。问题交接沿用原编号 |
| delivery | 授权终点、改动或议题归属、平台／实例与源／目标、已有对象及有效检查引用 | 实际终点、Issue／PR／MR 链接、SHA／远端状态、检查／审批阻塞 |

返回先给结论，只附本轮差异、必要证据定位及未完成项；证据保留版本、范围和可复查的命令或操作入口。完整日志、源码、报告留在原位置，交接不整段复制；证据尚无可访问载体时附最小必要内容，不为交接另建报告。无关字段省略，不强制套表或固定字数，不以压缩丢失失败、授权限制或必要上下文。

同一工作批次的关联证据可合并交接，由 sdd-documenter 在必要节点归并；不因单个字段或状态更新反复委派，不将全部记录落盘作为启动已授权后续工作的前提。正式记录仍按各流程完成要求归并，问题状态与批次事实保留各自权威来源。简单任务沿用当前任务或既有载体，保留必备结构，各节仅填写本轮必要事实并精确引用已有依据；无问题不建 Issue，复验可在同一报告文件新增明确批次，保留历史。面向用户的交付遵循[对应流程](sdd-repository-governance.md#skill-场景与对象分工)的输出要求。

接收者按引用读取相关正文，缺少关键输入时只索取缺项。Main 复用有效证据，在缺口、失败、矛盾或相关变化时复核受影响部分，不重复执行全套检查或重写各角色报告；仅补充验收事实或无关变化不扩大验证范围。续派只传变化及受影响编号。Bug 按[职责与交接](sdd-repository-governance.md#职责与交接)推进；缺失验证代码交 coder，验收证据缺口由原 validator 补查，文档冲突及证据落盘交 documenter，设计缺口回讨论。不要求所有角色轮转，交接不扩大授权。
