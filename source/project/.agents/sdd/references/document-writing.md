# 文档写入规则

每次 sdd-doc 写入执行本规则，检查范围覆盖结论涉及的正文及其关联影响。

1. **定位与取证**：读取目标正文，检索同义条款、上下位约定和直接引用。以对话中已确认的结论或用户指定来源为依据；需求与蓝图按各自职责提供约束，不设彼此全面覆盖的排序。
2. **原位归并**：相同语义保留唯一正文，其他位置引用；删除被明确替代、失效或重复的表述。不同前提、对象、例外和验收条件分别保留，不为去重删减有效要求。不另建竞争正文或追加变更说明。
3. **关联同步**：更新受影响条款，避免只改局部造成矛盾；保留稳定编号。入口新增、移动或替代时更新索引和直接引用。下位条款不得扩大、削弱或改写上位约定。
4. **写后核对**：读回实际文件，对照源结论和 diff 核对完整性、归属、条件及可执行前提；检查标题层级、编号、术语、表格、链接、锚点、编码和格式。机械检查不能证明语义正确。
5. **处理缺口**：未确认、来源不清或互相冲突的内容不写成有效决定。新的设计取舍、不可执行的上位要求或无法消歧的问题集中报告位置、影响和待决事项，交回讨论；不自行补方案或删除要求。
6. **记录事实**：Status 和报告只写执行者提供的结果、覆盖范围及快照；缺失、过期或冲突的证据标为未验证或阻塞。设计确认不证明实现完成，局部自验不证明验收通过，不改低 AC、ARC 或 Gate 来消除问题。

完成时报告实际落点、关键归并及未解决事项。检查与写入是同一任务，无独立文档 Review；不修改产品或测试代码。

## 按对象读取

- 新建或调整蓝图结构时读取[蓝图模板](../assets/blueprint.md)；接口契约结构需要补齐时读取[契约模板](../assets/contract.md)。只组织已确认内容，不为填模板补设计。
- 编写能力需求时按项目索引定位权威正文，需要结构参考时读取[需求模板](../assets/spec.md)。
- 编写测试计划时读取[测试计划模板](../assets/test-plan.md)，编写验收报告时读取[验收报告模板](../assets/acceptance.md)。模板规定文档内容，sdd-doc 负责依据已确认结论和真实证据写入、归并及一致性检查；不自行决定测试范围、数据选择或通过标准。
- 计划、报告和 Status 的内容归属按[测试范围约束](governance.md#测试范围约束)核对；缺少人工反馈时保留待确认及已有机器验证事实，不代替用户确认。
- README 与索引只维护导航；接口与总时序按各自职责表达，不强制固定图形或章节。
- 本次写入涉及观测约束时，读取[观测基线](observability-baseline.md)的适用条款。
