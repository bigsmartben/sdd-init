# 可观测性架构规范

目标仓库依据已确认的 Blueprint、契约及实际运行路径，将适用约束映射为项目 Code Review Rules。Review 按本轮变更及其影响范围检查项目规则。

## 职责与隔离

业务负责执行和权威业务状态，通过明确接口报告事实。观测负责日志、指标和链路的采集、关联、存储、导出及分析。日志记录事实，指标表达统计，链路表达跨调用关联与先后。评测消费观测数据和授权测试资产。

业务规则、状态、流程与计费以业务接口和权威数据为依据，禁止依赖观测数据、工具或评测结果。观测可记录业务接口提供的事实或快照，禁止拥有或修改权威业务状态、改变业务语义或驱动业务决策。

观测采集须非阻塞，观测与业务的资源和生命周期须隔离。业务不得等待观测写入、导出或评测。观测不得改动业务输入输出、消耗或关闭业务仍需的流和资源，重试不得重放业务。观测故障、超时、不可用及缓冲饱和不得导致业务失败、反压或结果变化。沿实际调用链和故障路径取证。技术流控及进程生命周期遵循[运行控制职责](architecture-rules.md#业务与运维可靠性职责分离)。

## 数据保存与日志契约

项目按用途和授权明确必记事实、禁存内容及保留范围，并约束实际采集、缓冲、重试与归档路径。日志排除凭证和 API Key，调试级别不得改变必记或禁存要求。业务和测试资产仅按授权用途保存。例如，观测禁止保存原始音频时，各写入路径须拒收原始音频及其等价编码。

日志契约明确必记事件、触发条件、必需字段、事件身份与类型、版本化结构及实际阶段。生产方与消费方按契约解释格式、编码、字段、结果和未知值，跨语言时检查各端兼容性。使用链路时明确 trace/span，重试关联同一事实。敏感字段按契约脱敏，保留实际结果语义。

## 采集、持久化与故障处理

明确事实接入点、采集及导出接口、传输边界和错误处理。按项目契约区分采集、队列受理、传输确认与保存完成，明确失败、缺失及未知的含义。项目要求持久化时，以契约规定的完成判据和回执为准，通过实际回读验证。按保存政策核对存储、轮转触发、保留和清理。

按项目策略处理缓冲容量、饱和、超时、退出、重试和恢复，独立暴露观测故障及缺失证据。禁止静默丢弃、将失败记为成功或依靠暂停、取消、拒绝业务来保证日志完整。持久化失败时分别验证业务能否继续、记录是否完整。
