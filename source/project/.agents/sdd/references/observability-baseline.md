# SDD 强制架构基线：运维与可观测

> 本仓库现行强制基线，作为架构 Review 的输入；基线与项目条款及实现的关联由审查证据记录，不作为 Blueprint 写入要求。

## 职责与隔离（SDD-OBS-01）

日志记录事实，指标表达统计，链路表达跨调用关联与先后；评测消费日志、指标及授权测试资产，不另立采集类别。业务负责执行与权威状态，通过明确接入点报告事实；观测负责格式化、存储、轮转、采集导出、统计与展示，不指定库、事件总线或进程。

观测可记录业务接口提供的事实或快照，保存受 SDD-OBS-02 约束；不得拥有或修改权威业务状态、改变业务语义或驱动业务决策。业务不得依赖观测数据、工具或评测结果实现功能，包括状态、流程推进与计费，须使用业务接口和权威数据。

非侵入要求适用于观测采集、导出、分析与评测；技术流控及进程生命周期见[运行控制职责](architecture-rules.md#业务与运维可靠性职责分离)。业务不得等待观测写入、导出或评测；观测异常、超时、不可用和缓冲饱和不得导致业务失败、反压或结果变化。观测不得对业务产生副作用，包括修改业务输入输出及状态、消费或关闭业务仍需的流和资源，或因观测重试重放业务。采集须非阻塞并隔离资源与生命周期，异步调用本身不证明隔离。

持久化与非阻塞同时成立，不得靠暂停、取消或拒绝业务保证日志完整。观测故障须暴露独立状态、错误及缺失证据，按项目策略缓冲恢复；无法保存时判记录要求未满足，不静默丢弃或伪装成功，不承诺无限故障无损。业务继续与记录完整分别取证。

## 日志、指标与媒体保存边界（SDD-OBS-02）

必要文字输入输出、执行及工具事实、状态和用量常态记录并持久化，以唯一事实记录（SSOT）供查询、观测和评测派生读取。Debug 只是日志级别，可按级别筛选；它不是独立观测功能、采集开关或媒体保存授权，不因级别设置停记、拒写或清空必要文字事实。流式、取消和中断保留实际部分内容、身份、顺序及缺失事实；生成、发送与呈现分开，缺失不补造，凭证和 API Key 排除在日志之外。

观测日志、指标、链路载荷、队列和归档不得保存原始音视频字节，包括 PCM、编码数据、base64 及其他等价表示；可以记录合法元数据、状态、统计和资产标识，不复制音视频内容。声纹测试、唤醒词等明确业务或测试目的需要的原始音频，由相应业务／测试能力独立管理资产；该例外不使资产成为观测日志，也不授权常规会话录音。原始视频没有已授权保存例外；未明确的其他例外不得推定。正常业务瞬时处理、传输和播放不属于本保存禁令。不得以 Debug 关闭证明媒体拒收，也不得将资产存在当作观测保存授权。

<a id="有限资源下的项目策略"></a>

文字记录以精确持久化回执确认，不以控制台、内存、队列或发送代替；失败、缺失和未知须可识别。有限资源策略按下方日志实现规范明确，故障隔离遵循 SDD-OBS-01。

## 跨语言日志契约（SDD-OBS-03）

各语言、客户端与服务端共用唯一、版本化且机器可解析的日志契约，格式、编码及字段要求见下表。实现库和存储介质可因宿主而异，不降低内容与持久化要求。禁止用成功代替未知、生成代替呈现或媒体引用代替资产落地证据。

## 日志实现规范

项目唯一日志契约须将 SDD-OBS-01/02/03 落实为以下可检查内容；参数、载荷和技术机制由项目确认，未知项不得由示例默认值补定。

| 环节 | 契约与实现要求 |
|---|---|
| 事件与结构 | 将 SDD-OBS-02 的必要文字事实具体化为必记事件清单，逐项明确触发条件与必需字段；定义事件身份、类型、实际发生阶段及版本化结构；重试关联同一事实，阶段与缺失语义遵循 SDD-OBS-02/03 |
| 字段与关联 | 定义输出格式、编码、字段类型、时间／单位、级别／事件语义、来源／程序版本、会话／请求／调用、阶段／顺序、文字或合法资产标识、结果／错误、完整性及未知值语义；使用链路时明确 trace/span，关联不代表成功 |
| 级别与脱敏 | 明确敏感字段及脱敏规则，不改变实际结果语义；凭证排除及级别边界遵循 SDD-OBS-02 |
| 采集与传输 | 明确事实接入点、采集与导出接口、编码、传输边界及错误处理；采集、队列受理、传输确认和持久化回执分别判定 |
| 缓冲与失败 | 明确缓冲、容量、饱和、超时、退出、重试、恢复及缺失暴露策略，遵循 SDD-OBS-01 |
| 持久化与生命周期 | 明确存储与回执、轮转触发、保留和清理策略及失败处理；通过实际回读和故障证据判断完整性 |

事件 Schema、多语言示例及框架适配可辅助实现，不能替代项目契约或基线证据。
