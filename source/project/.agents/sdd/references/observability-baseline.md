# 运维与可观测参考

> 保留的观测设计参考；仅在目标项目已确认适用时采用，不因安装 SDD 自动生效，不预置项目 ARC、选型或检查门禁。具体要求以项目 Issue 和 Blueprint 为准。以下条款供适用项目讨论与引用。

## 职责与隔离（SDD-OBS-01）

运维与可观测领域负责系统运行事实的采集、记录、持久化、关联、查询、诊断、度量与评测，为开发排障、运行维护和验收提供证据。日志是该领域的基础能力。
业务领域负责业务执行及权威业务状态，提供必要事实和明确接入点；日志格式化、存储、轮转、采集导出、统计和展示由运维与可观测领域承担。业务可通过统一接口报告事实；不要求指定日志库、事件总线或独立进程。
观测不得持有业务状态、改变业务语义或直接驱动业务决策；业务不得依赖观测计算或评测结果推进。职责隔离始终适用；文字记录常态适用，高开销采集遵循下述 Debug 边界。

运维与可观测不得阻塞业务执行，不得对业务产生副作用。业务推进不得等待日志写入、媒体归档、观测导出或评测完成；观测异常、超时、不可用及缓冲饱和不得传播为业务失败、反压业务链路或改变业务执行结果。不得修改业务输入/输出及状态，不得消费或关闭业务仍需使用的流和资源，不得因观测重试而重放业务操作。必要事实采集须采用不阻塞业务的接入方式，并隔离观测任务的资源与生命周期；具体机制由项目选择，不以异步调用本身作为已满足隔离的证据。
持久化要求与业务非阻塞要求同时成立。观测故障通过独立状态、错误及缺失证据显式暴露，按项目策略缓冲和恢复，不靠暂停、取消或拒绝业务来保证日志完整；无法完整保存时如实判定记录要求未满足，不能静默丢弃、伪装保存成功或宣称无限故障下仍保证无损。

## Debug 采集边界与原始交互持久化（SDD-OBS-02）

参考约定：文字类日志常态适用，必须持久化并以唯一权威事实（SSOT）供查询、观测和评测派生读取；Debug 仅控制媒体等高开销采集。文字输入输出、执行及工具事实、状态和用量不因 Debug 关闭而停记、拒绝写入或清空。各入口不得独立复制同一事实后凭时间或文字猜测关联。

原始音视频、媒体采样及高开销诊断默认关闭，仅明确 Debug 场景在授权范围内开启；打开页面、开发构建和异常不自动授权。已保存文字事实与媒体授权分别管理，刷新/重启后文字可读取，Debug 不自动续用。文字记录不得包含凭证或 API Key。流式、取消和中断保留实际部分内容、身份、顺序及缺失事实，缺失历史不补造；生成、发送及呈现分开记录。媒体开启后必须保存实际取得的原始内容，转写或摘要不替代原始媒体。

仅控制台、内存或待发送队列不算持久化；写入失败须可识别，不阻塞业务。存储、容量及失败恢复按项目契约执行。文字 SSOT 可以有派生投影，但投影不是第二权威。

### 有限资源下的项目策略

项目在所属架构正文明确缓冲容量、存储限额、保留与轮转、饱和处理、恢复条件、缺失标记和资源生命周期；尚未确认的机制与参数列为待决策，不由模板设默认值或用实现现状代替确认。有限资源和故障策略不能放宽 Debug 授权范围内的原始记录要求；无法完整保存时保留缺失事实与未满足结论。

业务隔离与记录完整性分别给证据和结论：业务继续执行不证明记录完整，记录失败也不授权阻塞业务。日志格式一致性仍单独按 SDD-OBS-03 核对；局部满足不提升整体基线结果。

## 跨语言日志契约（SDD-OBS-03）

各语言、客户端与服务端文字日志以及 Debug 高开销观测遵循项目唯一、版本化的日志契约：输出格式与编码、字段类型、时间与单位、级别/事件语义、来源/程序版本、会话/请求/调用关联、阶段/顺序、内容或媒体引用、结果/错误、完整性和未知值语义。不得各语言各定一套。
项目必须明确机器可解析的统一输出格式；实现库与存储介质可因宿主而异，不能降低内容及持久化要求。禁止用成功代替未知、用生成完成证明实际呈现，或以媒体引用存在证明文件已经落地。

## 项目采用与验证

按实际需求在 Blueprint 记录已确认的适用条款与取舍。局部自验、部署准备和人工验收分别报告，不自动进入整改循环。未确认策略保持待决，不以样例实现或安装成功推定项目已满足。
