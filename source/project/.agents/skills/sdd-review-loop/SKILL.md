# 架构一致性 Review

前置：sdd-doc 已保证本轮蓝图及关联文档一致，审查依据明确。发现文档冲突时暂停受影响结论，交回 sdd-doc；需要新设计取舍时交回讨论。

1. 确定目标能力、代码快照及相关跨模块关系。从 Blueprint、适用 ARC 和[观测基线](../../sdd/references/observability-baseline.md)确定检查范围。
2. 对照源码和调用链检查职责、状态所有权、依赖、接口、数据流及异常时序。可执行约束使用相应检查，语义判断提供具体实现证据；不能只检查目录或已列出的 ARC 而遗漏适用约束。
3. 输出逐项符合、偏差或未验证结论，注明依据、位置、覆盖范围和快照。跨能力关系须实际检查，不能从单项通过推导组合通过。
4. 实现偏差交给 sdd-imp 修复，随后复核受影响项。全部适用项在同一快照通过才可报告 Review Gate PASS；失败、缺失或阻塞如实报告。

本流程只审查实现，不修改代码、设计或正式文档；证据交给 sdd-doc 落盘。需求行为验收由 sdd-test-loop 承担。需要用户判断时按[项目职责](../../governance/repository.md)沿场景时序展示证据。独立审查按[执行协作](../../sdd/references/delegation.md)安排，自查不得称为独立审查。

例：蓝图规定只有服务层写订单状态，发现界面层直接写库。引用蓝图条款和实际调用链报告偏差，交给 sdd-imp；不修改蓝图使实现合规。
