# 上游任务交付与局部自验

本 Skill 是统一的代码执行入口。按明确的上游工单和必要代码上下文实施，也承接明确的缺失测试及已授权探索任务。疑似缺陷先交 [sdd-bugfix](../sdd-bugfix/SKILL.md) 评估归因。架构变更工单给出已确认决定及可执行目标。架构判断、偏差整改目标及复核归 sdd-review-code。

HTML 原型属于测试代码，制作或复用原型时读取[原型规则](../../sdd/references/prototype.md)。coder 负责代码，交互与业务状态验证交给 validator；引用、确认记录与测试报告交给 sdd-doc。

1. 核对上游工单的交付目标、范围、通过判据及可执行验收方案或引用。需求工单可引用 Spec、AC 或契约中的可执行说明；架构整改引用原检查项的复核方案。需澄清需求或补齐需求验收依据时，将缺项交回 [sdd-spec](../sdd-spec/SKILL.md)。定位相关代码和测试，读取工单引用且本轮适用的依据。按明确目标实施架构任务并保持工单边界，Blueprint 和 Code Review Rules 由 Review 按需核对。制定验证范围时读取[实施和独立审查](../../sdd/references/sdd-repository-governance.md#实施和独立审查)。新增资产或改变用途时查[工程资产边界](../../sdd/references/sdd-repository-governance.md#工程资产边界)。输入不足时交对应上游补齐，记录受影响项及恢复条件，继续其他已就绪且获授权的事项。
2. 读取 [Plan](../../sdd/assets/plan_template.md)。接续已有任务时先核对原 Plan 的状态和证据。需求实施按 Spec 的用户场景、AC 和已确认优先级拆分，将相关代码、契约、数据约束和验证映射到 Task。引用适用条款并落实到完成条件。其他场景按其上游目标和完成条件拆分。用直接依赖表达共用前置和执行顺序，核对目标覆盖、依赖无环、可并行项和各批的局部验证入口。记录足以开工的方案，标出影响方案或顺序的未知项，在据此推进前查证。需确认的实质取舍附可行选项、证据和影响。开工前在当前任务或已有 Plan 中输出 Task 清单，随后在授权内直接执行。简单修复可只列一项，写明目标、完成判据及局部检查入口。
3. 按已确认的优先级选择就绪项，核对前置 Task 的结果及实际环境、配置和依赖。任务涉及工程骨架或工具配置时，按实际工具链核对所需配置和忽略规则。开始实施时更新状态。修改同一文件的 Task 串行，改动与共享状态不会冲突时才并行。编写或修复必要的测试代码和自动化脚本。任务约定 TDD 或需要以测试证明待修缺口时，先运行对应测试，确认它因预期缺口失败，再实现并重跑。按上游目标、需求或契约设置断言，探索任务按明确假设、比较目标和指标验证。局部自验以代码单测为主，按工单性质和影响补充必要的定向回归、构建或类型检查。
4. 在 Task 完成或批次交接前核对相应结果、覆盖及版本证据。Task 达到完成条件、局部自验通过、证据齐备且无未解决的失败或阻塞时，标记完成。执行或检查失败时记录失败状态和证据，修复并复验。未满足的前置条件使依赖项标为阻塞，注明恢复条件，其他已就绪且获授权的 Task 继续。代码或验证证据改变前提、改动范围或顺序时，在同一份 Plan 更新受影响的方案、改动位置与依赖，保留已有编号及仍有效的证据。问题、预期结果变化或出现需要确认的实质设计取舍时，交回 Main 对齐受影响项。
5. 交付前将实际改动和验证覆盖对照上游目标、适用约束和最新 Plan。交付实际改动、版本、局部验证入口与证据、覆盖缺口和阻塞。本轮仅要求实施和局部自验时，可在 Task 完成后结束。有约定的用户验收或架构复核时，在 Plan 逐项关联局部证据和待验判据，按各自方案交接，并附上游方案引用、运行入口和已知准备条件。用户验收按上游方案实际取证，需真实组件协同的明确范围交 [sdd-test-loop](../sdd-test-loop/SKILL.md)，架构整改交原审查者复核。需要正式记录时，交 sdd-doc 归并 Test Report，Plan／Status 引用报告。Main 核对本轮目标及剩余验收项。

来自 sdd-bugfix 的工单须给出原 Issue、要恢复的行为、已验证的原因与证据、影响、边界及修复后的通过判据。Plan／Task 关联原编号和归因证据。发现反证时暂停该项，带原编号及新证据退回 sdd-bugfix 重新归因；其他已授权且不受影响的任务继续。定向检查实际证明修复版本的原故障或等价场景已恢复且必要回归通过时，局部证据可满足工单判据。交回证据及仍待验证的判据，由 sdd-doc 按[职责与交接](../../sdd/references/sdd-repository-governance.md#职责与交接)更新原 Issue。

来自 sdd-test-loop 的缺失测试以 Issue、场景依据及应补覆盖为输入，在已有授权内编写或修复验证代码。Task 关联原 Issue，返回实际改动、版本、局部自验证据及待验证范围，由验收执行者核验处理结果。

来自 sdd-review-code 的整改在 Task 中关联原检查项编号，依据明确整改目标、实现范围、须保持的行为及原检查项的复核方案实施。目标或行为影响不清、需超出交接范围时，暂停该项并返回 Review。完成后返回实际改动、版本及局部自验证据，由 Review 复核关闭。

需要委派或交接时读取[执行协作](../../sdd/references/delegation.md)。

例：按已确认的新规则增加空输入校验，补充定向测试并报告局部覆盖。
