# sdd-imp — 单 Spec 实施工作流

## 场景、职责与作用对象

场景：按一个已确认 Spec 实现能力、修复偏差或继续授权内的实施迭代。
职责：按模型分工完成实现、局部自验、修复和状态记录，由 Main 维护实施闭环与统一状态归属，提供本轮 AC/ARC 的实现覆盖与当前快照证据。
作用对象：读取 Spec、Blueprint 及相关实现；写入授权代码、测试和对应 Status。跨 Spec 做必要影响分析，仅在本轮局部接口确有需要时补充交互检查，不据此扩大写入或测试范围，不自行改写需求或架构契约。
完成依据：本轮实现、局部自验、适用架构约束和快照证据有效且无阻塞。完整业务流程与系统整体效果的验收不作为实施完成的前提；独立 Review/Test Gate 与 Git 交付不是默认子流程。

任务包含已确认需求的实施或修复时，Agent 自主选择本 Skill，并定位适用的 `specs/<capability>/spec.md`。定位对应 Status、Blueprint 及相关源码/测试；跨 Spec 做必要影响分析，不据此扩大写入范围。遵循 [实体治理](../../sdd/references/governance.md) 和 [执行约定](../../sdd/references/delegation.md)。

## 执行选择

- 范围清楚、已获实施授权、修改局部或步骤连续依赖，且 Main 的实际模型符合当前工作类型时，可由 Main 直接完成该部分；跨工作类型按[模型分工](../../sdd/references/delegation.md#模型分工)选择执行者。一句话对齐目标、范围和验收即可，不为使用 Skill 额外创建计划或 Agent。
- 有实质技术取舍、复杂依赖或重要风险时按需规划，明确方案、边界和验证方式。已有授权内的常规拆分自主完成；仅关键歧义、范围/契约变化或未获授权动作需要用户决定。用户明确要求先审计划时，遵守该要求。
- 原生 Plan 按需且受客户端支持约束，不是实现前置条件；不可用时可在当前对话规划。Goal 仅在用户明确要求建立 Goal，或更高优先级指令要求时使用；调用本 Skill 本身不构成创建 Goal 的要求。无需因工具不可用增加确认点，不虚称已切换模式或创建 Goal，不额外生成 plan.md/tasks.md。
- 仅在独立执行确有收益且当前会话允许委派时分配独立实施任务。代码量大、跨模块或复杂度高本身不触发委派；共享大量上下文、Main 只能串行等待时通常直接执行。

## Main 负责实施闭环与状态归属

当前执行者是 Main，或按任务分配且模型符合当前工作类型的执行者。Main 协调迭代起点、编码、局部验证、修复与对应 Status 的维护，包括必要的 `govern.py start/record/finish`；各执行者返回实际证据，明确唯一状态写入归属；Status 及其他文档由 terra 按确认事实落盘，无需另建文档流程，也不要求编码与验证由同一模型执行。

在授权的代码/测试及对应 Status 范围内完成改动。局部自验及 AC/ARC 覆盖遵循[测试范围约束](../../sdd/references/governance.md#测试范围约束)；既有验收契约冲突按该约束处理，未解决时不得声明本轮完成。对照本轮 AC、适用 ARC，默认运行与改动直接相关的单元测试，按受影响范围执行必要的类型检查、构建或架构边界静态检查。仅当单测无法证明本轮局部接口交互时，说明原因并补充最小范围的契约或集成测试。相关自验通过且无未解决疑点后停止，不扩大或重复测试；已有可信且仍有效的结果不重复运行。

禁止本流程执行完整业务流程验证、系统整体效果验证及全量业务回归，不得以 AC/ARC 覆盖、跨 Spec 影响或项目专项门禁为由触发。此类验证由 Agent 在任务契约与已有授权范围内选择 `sdd-test-loop` 或专项验收承担，不作为 imp 完成的默认前提。证据须注明实际局部覆盖和待验收范围，不得把单测或局部集成通过表述为完整链路、组合行为或系统效果已验证。

局部验证失败在范围内修复并复验受影响部分。不得自行修改 Blueprint/Spec、扩大授权或伪造证据。契约缺口、范围变化或无法消解的阻塞交 Main 处理，Main 已是执行者时直接向用户说明。

满足完成条件后由当前执行者运行 `python .agents/sdd/scripts/govern.py --root . finish --name <capability>`；实施自验证据缺失、失败、过期或存在阻塞时保留真实状态和恢复点，不写 COMPLETED。机械工具不替代语义验证；多 Spec 影响只核对本轮受影响的局部接口及同一最新快照证据，不据此开展跨能力组合验收。COMPLETED 表示本轮实施完成，不表示完整业务或系统验收通过。

## 委派与结果核对

委派时只传目标、Spec/Blueprint/Status 路径、必要结论、授权文件范围和验收条件，明确 Status 写入归属；不复制完整历史或先替实施执行者做完整实施分析。模型遵循[执行约定的模型分工](../../sdd/references/delegation.md#模型分工)，推理强度由执行者按任务决定。复用适合的执行者；编码整改回原编码执行者，验证回验证执行者；必要交接只传相关变更、证据和状态归属；文档落盘交由 terra，不重复建立文档流程。并行仅用于职责、代码及 Status 写入范围明确隔离的任务。

实施执行者返回关键改动、AC/ARC 实现覆盖、局部验证范围、验证命令及结果/报告位置、快照、Status 路径、待验收范围和未完成项。Main 核对授权范围、关键差异、证据完整性及快照时效后报告；不默认重读全部源码、重复推导方案或重跑已有效通过的验证。仅在发现证据缺口、矛盾、失败、快照变化或关键风险未覆盖时深入检查和复验相关局部；结果核对仍受上述验证边界约束，不能以减少重复为由忽略已知问题。

Agent 根据任务目标、风险与已有授权自主选择是否接续 `$sdd-review-loop`、`$sdd-test-loop` 或 `sdd-commit`，无需用户另行输入指令；接续时明确实际范围和完成依据。实施自验和 Main 结果核对不等于独立审查；未开展的 Gate 保持 UNVERIFIED，不作为实施完成的额外前提。已要求的独立审查必须由独立审查者完成，修复后仍由其复核。交付只在任务包含相应 Git 动作授权时执行。
