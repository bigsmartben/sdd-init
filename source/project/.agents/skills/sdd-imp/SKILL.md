# 实施与局部自验

1. 从已确认需求或复现步骤确定本次应改变的行为，定位相关代码、测试以及直接约束本改动的接口和架构条款。沿用现有决定；需要改变职责、状态所有权或外部契约时，说明冲突并交回设计判断。
2. 在授权范围内实现或修复。用能区分修改前后行为的定向测试验证结果，按受影响范围补充构建或类型检查。跨模块接口只有通过局部集成才能验证时，补对应检查。失败则修复并复验，已有证据仍有效时直接复用。
3. 交付关键改动、验证结果、未覆盖范围和阻塞。需要登记 Status 时，将当前快照与证据交给 sdd-doc。实现与局部验证完成即可结束本轮实施。

需要写入文档时，由 `sdd-doc` 一并完成内容与格式一致性检查。架构符合性审查归 `sdd-review-loop`，完整需求行为验收归 `sdd-test-loop`。架构审查和需求验收按各自任务范围执行。遇到已知偏差应如实报告；不得以局部自验代替独立审查或系统验收。

涉及观测行为的改动须落实[观测基线](../../sdd/references/observability-baseline.md)中的直接约束。确定验证范围时读取[共享规则](../../sdd/references/governance.md#测试范围约束)，需要角色及证据交接时读取[执行协作](../../sdd/references/delegation.md)。

例：修复空输入处理，补充并运行空输入的定向测试；报告局部覆盖，不自动启动完整业务验收或架构 Review。
