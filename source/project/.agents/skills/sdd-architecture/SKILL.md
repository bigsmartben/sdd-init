# 架构蓝图设计与演化

负责仓库级系统设计。正式交付经用户确认、内部一致且足以指导研发的 Blueprint，以及适用的架构决定和验证依据。只讨论按[需求与架构讨论](../../sdd/references/sdd-repository-governance.md#需求与架构讨论)交付。专项评估按约定提供方案、证据及待决项。

## 触发与依据

用户明确发起本轮架构任务时使用，由本 Skill 组织阶段内工作。其他阶段发现的信号作为架构输入。

| 场景 | 本轮关注点 |
| --- | --- |
| 新项目建立整体架构 | 从已确认产品目标、范围和约束确定系统边界及关键决定 |
| 已有仓库补建蓝图 | 区分可取证的现状、已确认的设计和候选目标设计 |
| 规模、性能、可靠性、部署形态或技术生命周期变化 | 比较演化路径及对系统约束的影响 |
| 需求触及模块职责、依赖方向、状态权威或关键契约 | 依据已确认需求设计受影响的跨模块关系与约束 |
| 运行、测试或审查提出系统性风险 | 从证据定位风险、影响与决定需求 |
| 架构迁移或退役 | 确定目标、过渡状态、兼容、数据处置和恢复条件 |

从项目索引定位已有 Blueprint、契约、ADR、Spec 和可用证据，按问题读取适用部分。以实际版本和观测条件标注实现、部署和运行事实。缺少决策依据时提出待决问题。

需要用户确认时，技能 Agent 将拟决定内容及证据交 Main，并按用户反馈续做。

## 本轮闭环

分析深度由设计问题及风险决定，不以交付模板的字段逐项限制分析，也不将分析涉及的所有内容转化为交付项。

1. 按[意图对齐](../../sdd/references/visual-confirmation.md#意图对齐)提出本轮架构问题、目标、范围、交付物和完成条件，确认其中新增或变化的内容。沿用已确认的产品需求及设计。保留相关现状证据、约束、缺项和受影响决定。待定的业务依据交回 Main，受影响的设计保持候选。
2. 比较可行方案及适用条件。按影响设计系统边界、模块职责、依赖方向、状态权威与关键不变量，明确关键交互、契约、异常传播和恢复责任。涉及运行时，明确部署拓扑、环境隔离、存储与数据边界、可靠性及可观测性。涉及演化时，说明受影响的模块和调用方、兼容约束、过渡状态、切换与回退条件。把成本、性能、可靠性等取舍对应到已确认的目标。
3. 用现有证据或相称的可行性实验验证影响决策的关键假设。明确观察点、通过判据、条件、实际结果与局限。实验超出已有授权时先确认所需授权，包括外部资源、费用、真实数据或不可逆影响。实验代码和配置按[工程资产边界](../../sdd/references/sdd-repository-governance.md#工程资产边界)隔离，实际结果按需引用 [Test Report](../../sdd/assets/test_report_template.md)。证据推翻关键假设时回到方案比较，修订并验证受影响的部分。
4. 按完整设计问题或决策批次提交方案及证据供用户确认，覆盖新增或变化的模块边界、状态权威、依赖方向、关键选型及成本、可靠性、性能等实质取舍。证据与已确认决定或业务依据与技术约束出现实质冲突时，重新确认受影响决定。常规调查、授权内实验、表达形式、文档归并和一致性修正持续执行。待决事项只影响相关决定及其依赖。
5. 获授权后按[文档写入规则](../../sdd/references/document-writing.md)原位归并已确认内容。沿用项目 Blueprint，按 [Blueprint 模板](../../sdd/assets/blueprint_template.md)规定的结构与内容归并已确认的高层设计结论。项目已有 ADR、[Technical Research and Selection Report](../../sdd/assets/research_template.md)、[Scenario Sequence](../../sdd/assets/sequence_template.md)、[Interface Contract](../../sdd/assets/contract_template.md) 及验证报告按本轮约定和适用产物要求维护；参考或分析这些内容不自动要求新增对应文档。核对职责、依赖、状态权威、契约、过渡状态及直接引用，按需同步索引，保留稳定编号。写后检查针对设计内部一致性。

按设计问题迭代，简单任务可合并步骤。回执给出已确认结论、权威章节、关键验证及证据、剩余风险。完成判断依据本轮约定、蓝图模板及适用的写后检查，不因采用某种分析方法而额外要求对应报告或完整分析记录。必要决定已确认、约定验证完成且权威正文已归并并通过一致性检查后，报告正式交付完成。仍待决或未验证的事项注明影响和恢复条件，按受影响范围报告完成状态。

## 执行安排与阶段边界

本 Skill 按[委派与独立性](../../sdd/references/delegation.md#委派与独立性)选择执行者，回收实际结果用于本轮架构判断。

| 何时安排 | 专业工作及给定依据 | 回收结果 |
| --- | --- | --- |
| 需要系统性设计或技术取舍 | 架构分析与设计；给定待决问题、已确认约束、影响范围和现状证据 | 可归并方案、取舍依据、受影响决定和待决项 |
| 关键假设需要实验代码 | 限定实验目标、写入范围、观察点、通过判据和隔离条件 | 实验入口、实际改动、环境、版本、结果和限制 |
| 设计判断需要运行或环境证据 | 给定目标环境、版本、只读取证范围和观察点 | 可追溯的部署、依赖或运行事实及覆盖缺口 |
| 需要独立核对正式文档的一致性 | 按[文档交接](../../sdd/references/delegation.md#文档交接)指定只读范围、权威条款与疑点 | 冲突或引用问题、证据和建议，由获授权的写入者处理 |

业务需求定义、正式产品代码改造、实际架构遵循 Review、部署运行操作由 Main 按[阶段授权与推进](../../sdd/references/sdd-repository-governance.md#阶段授权与推进)安排。蓝图已链接 Review 矩阵时，本轮子系统、模块、组件及其职责、依赖、契约或适用规范变化，须在回执列明变化、受影响矩阵入口和依据，按[矩阵维护契约](../../sdd/references/sdd-repository-governance.md#目标仓库的-code-review-rules)交 Main 组织重构技能同步并确认。本 Skill 不直接调用同层技能或改写矩阵；回执分别说明设计交付与矩阵同步状态。其余相关问题、影响、依据和接续条件同样交回 Main。
