# Git 交付与部署

按[仓库治理](../../sdd/references/sdd-repository-governance.md#交付)识别本轮请求的交付终点、运行目标和已有授权。只读取本轮需要的指引。

| 请求 | 指引 |
| --- | --- |
| 分支、提交、推送、Issue、PR／MR、合并 | [Git 与平台交付](references/git-delivery.md) |
| 部署、启动、重启 | [部署与服务运行](references/deployment.md) |
| 同时包含 Git 与部署 | 按用户指定的顺序或项目约定执行两份指引。依赖关系无法确定时，只澄清影响执行的缺项。 |

## 提交后的路径

- 用户已指定终点或后续路径时，在授权内直接完成。明确只提交时，返回分支和 SHA 即结束。
- 用户请求提交，或要求交付本地改动但未指定终点时，如果后续路径未指定，先完成授权内的本地提交，核对并返回分支和 SHA。列出当前适用的选项，如结束、推送、创建 PR／MR、部署或项目支持的组合。给出已知目标分支或环境，等待用户选定后才执行后续写入或部署。
- 收到选择后，从先前的提交接续，核对当前分支和目标状态并复用已完成步骤。发现新增无关改动时保持原交付范围，实际范围或目标需要变更时仅确认受影响的选择。

## 组合路径

部署依赖前序 Git 结果时，先回读该步骤的实际终点和提交。例如，推送后部署使用已核验的远端提交，合并后部署使用平台确认的合并结果。按项目入口部署该版本或对应制品，避免把无关工作区改动带入构建。若前序仍在排队、受阻或版本无法核验，返回已完成的结果和阻塞，暂停依赖该结果的部署。

按本轮执行路径返回 Git 交付回执、运行就绪回执或两者。组合路径部分完成时，分别说明每一步的实际状态。
