# 发布与运维

## 适用场景与输入

用户明确请求仓库交付、构建与流水线、制品或版本发布、部署及服务运行、排障、流量调整、回滚、备份恢复或退役时进入。独立操作按自身终点结束，已授权的组合操作按实际依赖接续。按[场景、输入与终点](../../sdd/references/delivery.md#场景输入与终点)选择专项指引和核验项。

接收主任务（Main）交接的用户目标、授权终点、对象、环境、版本或确定方式、读写与恢复边界和已有确认。按需从可访问的工单、运行指南、实际配置、恢复策略和证据补齐输入。依据实际版本、环境及覆盖判断来源是否适用。

## 本轮闭环

1. 核对输入和授权，先从本地或已有资料识别目标环境与自动触发链，再按权限探测实际状态。生产实时查询也须先落实人工确认。
2. 按[执行前确认与部署评估](../../sdd/references/delivery.md#执行前确认与部署评估)补齐当前步骤的前置条件。正式发布按[正式发布依据](../../sdd/references/release-evidence.md)核对实际候选、制品来源及适用架构复核和集成通过证据。独立运维按自身前置条件执行。
3. 按[执行与复验](../../sdd/references/delivery.md#执行与复验)完成已授权步骤并回读实际终点。组合路径沿实际 Git 结果、对应制品、运行版本及就绪证据接续。部署后的切流以就绪和适用冒烟结果为前置，写入后验证实际流量。
4. 失败、超时或结果不明时先回读，再诊断并在授权内修复、重试或恢复并复验。前置缺失或仍受阻时仅暂停受影响步骤及其依赖，回报影响与恢复条件。

## 交接与人工确认

按[交付与运维交接](../../sdd/references/delegation.md#交付与运维交接)向合格角色交办专业工单，接收实测回执并核对覆盖和完成条件。阶段内可直接承接，按项目要求保持核验独立性。角色向本 Skill 回报操作结果、待确认事项及接续条件。

启动时沿用有效确认。目标待定、权限缺失或影响实质变化时，将受影响项和依据交 Main。部署类动作执行或触发前，由 Main 向用户说明影响评估。生产操作由 Main 在执行或间接触发前取得用户确认。Main 把适用的确认和告知结果交回本 Skill。已授权的非生产部署在告知且其余前置满足后接续。命令、顺序、诊断和授权内重试由执行者决定。

请求提交或交付本地改动时按[提交后的路径](../../sdd/references/delivery.md#提交后的路径)处理。仅提交时以分支和 SHA 结束。后续路径未定时先完成范围内提交，由 Main 带回 SHA 和适用选项请用户选择，选定后沿用原提交接续。

## 阶段回执

向 Main 交付实际终点、版本与环境、操作回执及证据入口、未完成项、恢复效果和接续条件。需要正式记录时按[结果与证据](../../sdd/references/delivery.md#结果与证据)归并。发现应用缺陷时，可在满足前置条件后先按授权恢复服务，再带版本、影响和实测证据交回 Main。发布证据缺口、产品代码修复、全产品集成测试、需求或整体架构变更由 Main 按[阶段授权与推进](../../sdd/references/sdd-repository-governance.md#阶段授权与推进)协调。本 Skill 不调用其他工作流 Skill，不以其执行作为前置，也不自行推进其他阶段。
