# 发布与运维

## 适用场景与输入

用户明确请求建立或调整交付与运维工作流，或执行仓库交付、构建与流水线、制品或版本发布、部署及服务运行、排障、流量调整、回滚、备份恢复或退役时进入。独立操作按自身终点结束，已授权的组合操作按实际依赖接续。按[场景、输入与终点](../../sdd/references/delivery.md#场景输入与终点)确定本轮完成条件。

接收主 Agent（Main）交接的用户目标、授权终点、对象、环境、版本或确定方式、读写与恢复边界和已有确认。按需从可访问的工单、运行指南、实际配置、恢复策略和证据补齐输入。依据实际版本、环境及覆盖判断来源是否适用。

## 场景识别与委派

由加载本 Skill 的 Agent 按[场景识别与工作流](../../sdd/references/delivery.md#场景识别与工作流)识别个人／团队协作约定、可组合的 CI／CD／Ops／DevOps 任务，以及本轮是配置工作流还是执行既有流程。沿用有效决定，不因协作模式自行增加或取消评审、审批与发布门禁。

按[交付与运维交接](../../sdd/references/delegation.md#交付与运维交接)将完整场景任务委托给 `sdd-devops`，给定目标、上下文、约束、授权终点和验收条件，不替角色预排命令或拆成逐步派单。角色自主选择、建立或调整适用工作流，并完成配置／执行与复验。角色不可用时按[委派与独立性](../../sdd/references/delegation.md#委派与独立性)处理，不把创建独立技能 Agent 作为前置。

技能只组织平台无关的场景与任务交接；具体平台事件、云端执行器、权限和流水线配置归目标项目，不在技能中固化整条交付链路。

## 本轮闭环

依据本轮完成条件核对角色回执、实际版本与适用证据。失败或存在缺口时，由原角色在授权范围内修正并复验，直至达到终点或明确阻塞及恢复条件，不重复角色内部的实施过程。仅完成配置、已触发或排队不能代替要求的运行结果；若终点只是提交变更请求，则交付请求状态，后续由已配置的自动化接管，不扩展为等待全部云端交付。

## 交接与人工确认

按[执行前确认与部署评估](../../sdd/references/delivery.md#执行前确认与部署评估)，在需要告知评估或取得确认时，将受影响步骤、依据和影响交 Main。Main 回交适用的告知或确认结果后，技能 Agent 核对前置条件并接续原步骤。

请求提交或交付本地改动时按[提交后的路径](../../sdd/references/delivery.md#提交后的路径)处理。需要用户选择时，将已完成的提交和选项交 Main，按用户决定续做。

## 阶段回执

按[结果与证据](../../sdd/references/delivery.md#结果与证据)向 Main 交付阶段回执及适用记录。发布证据缺口、产品代码修复、全产品集成测试、需求或整体架构变更由 Main 按[阶段授权与推进](../../sdd/references/sdd-repository-governance.md#阶段授权与推进)协调。
