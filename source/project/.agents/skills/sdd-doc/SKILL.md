# SDD 文档实体落盘

## 场景、职责与作用对象

场景：把已确认的架构/需求结论整理落盘，或单独整理已有执行证据。
职责：定位唯一权威实体，原位归并内容，维护术语、编号、引用和证据字段。
作用对象：写入授权的 Blueprint、Spec、Status；读取确认来源及必要模板。Blueprint 管架构，Spec 管需求，Status 管事实与证据，不相互替代。
完成依据：已确认内容准确落盘、引用一致、未决项如实保留。纯讨论和新设计决策不在本 Skill 内；实施/审查中的状态事实由原执行者提供，文档写入按模型分工使用 terra，无需额外启动重复文档流程。

任务包含已确认结论落盘或文档治理时，Agent 自主选择本 Skill，文档执行模型统一使用 `gpt-6.1-terra`；Main 负责契约和来源核对，实际模型符合分工时可直接执行。需求、架构与方案设计仍按 [模型分工](../../sdd/references/delegation.md#模型分工)由 astra 产出结论；推理强度按任务自行决定。

任务输入：用户确认的源结论及其来源、目标实体/能力、写入范围；Status 还须提供执行者的结果、覆盖范围、快照与可复查证据。来源可以是当前对话、指定的其他对话或文档；内容无法读取时说明缺失，不能从标题猜测。

当前执行者阅读 [实体治理](../../sdd/references/governance.md) 和对应模板：
- Blueprint：`../../sdd/assets/blueprint.md`。
- Spec：`../../sdd/assets/spec.md`。
- Status：`../../sdd/assets/status.md`。

编写测试与验收内容时遵循[测试范围约束](../../sdd/references/governance.md#测试范围约束)；确认来源或既有 AC 与其冲突时报告冲突，等待获授权的文档调整，不直接复制为新增验收项或自行降低业务要求。

定位既有 SSOT；同能力同语义归并，保留不同条件与验收；维护编号、术语、引用和跨实体一致性。按模板进行原位更新或在创建意图明确且无既有权威时创建。不得重审内容合理性、补充未确认设计、改代码或发布远端变更。

Status 使用 `../../sdd/scripts/govern.py` 的机械校验与状态命令，结论来自实际执行者。记录 PASS/COMPLETED 前检查证据齐全且对应当前快照；工具不能证明语义正确。缺事实或有冲突时仅指出缺口，不自行判断通过。

落盘后读回核对；返回文件路径、实际变更、引用/格式检查和未解决冲突。无需为已授权的正常文档写入增加确认点。文档执行者按上述模型分工完成落盘；模型选择、切换与委派遵循执行约定的运行环境边界，不为落盘增加重复流程。

## 运维与可观测强制基线

必读[强制基线](../../sdd/references/observability-baseline.md)，核对本轮范围的 SDD-OBS-01/02/03 与项目 ARC、需求及规范的映射。该基线对所有 SDD 项目生效；不能因项目漏引用或只列为候选而跳过，冲突与缺项明确记录，不通过修改契约伪装通过。流程选择遵循任务契约，保持本 Skill 的写入与验证边界。

原位补齐基线引用和稳定项目 ARC 映射，替换与已确认基线冲突的旧范围，保持唯一正文；实际项目未决策略如实列出，不编造落地方式或验证结果。
