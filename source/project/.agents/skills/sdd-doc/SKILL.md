# SDD 文档固化

根据明确的自然语言写入意图选择本 Skill，无需精确口令。普通讨论或仅说“认可”“对”不触发写入；若同时要求更新则按要求执行。“落地”结合上下文判断，确实不清楚是固化还是实施才澄清。

读取[协作约定](../../sdd/references/governance.md)，定位用户确认的结论、来源与目标实体。来源可为当前对话、指定讨论或文件；无法读取时说明缺口，不从标题猜测。沿用用户选择的模型和推理强度，不强制切换或委派。

- 需求写入 Issue，架构写入 Blueprint，实施 Plan 写入 Draft PR；原位归并，保留条件、范围和既有编号，跨实体引用，不复制需求或新增 plan.md。
- 按需采用[Issue](../../sdd/assets/issue.md)、[Blueprint](../../sdd/assets/blueprint.md)、[Draft PR](../../sdd/assets/draft-pr.md)模板及[六类场景提示](../../sdd/references/scenarios.md)。模板不是填表门禁，不为填满字段补造业务规则、组件库或架构。
- 已有清楚的结论和写入授权直接使用，不再逐项确认。发现实质结论缺口时暂停相关内容并指出待讨论问题，继续已明确部分。
- 远端写入须属于用户指定的固化目标与范围；写文档不自动授权修改产品代码、部署产品、提交或合并。

## HTML 原型文档

用户要求制作或更新原型时，先核对已讨论的结构、关键交互和业务状态。用原型专用 HTML/CSS/JS 和可辨识的模拟数据制作候选，源码纳入目标项目版本管理，隔离产品源码、组件、接口和运行配置；不直接复用产品组件或连接真实业务写接口。

遵循[原型交付说明](../../sdd/references/prototype.md)，使用[引用模板](../../sdd/assets/prototype-reference.md)记录候选入口、源码版本、适用范围和确认情况。目录、托管平台和访问方式沿用项目已确定方案；未确定时澄清该部分，可先整理原型内容与候选说明，不自行部署或引入通用发布平台。

验证候选的关键操作与模拟状态可运行、入口可访问且对应源码版本，交给用户操作反馈。用户确认后按授权在 Issue 固化引用；未确认保持候选，后续候选不能覆盖已确认版本。原型确认不代表产品验收。需求与原型冲突先讨论，结构、交互或业务状态变化需重新确认；正式界面沿用项目设计规范，不要求像素还原。

## 交付

写入后读回核对内容、链接、编码及目标版本。报告实际写入位置、变化、未决问题与原型确认状态。进度和证据只记录实际事实；固化完成、方案完成、实现完成、验收通过分别表述。
