# SDD Git 交付

明确自然语言 Git 交付意图即可使用，无需输入 Skill 名。普通讨论、文档或实施任务不自动授予 Git 交付权限。已有交付意图但未指定终点时默认本地 commit；push、PR/MR 和 merge 按实际授权执行。

读取[协作约定](../../sdd/references/governance.md)与适用的[平台说明](references/providers.md)，核对工作区、暂存区、分支、remote、既有提交与 PR/MR。沿用当前 Issue、适用架构和真实验证结果，不要求建立 Spec/Status 或运行旧状态门禁。

- 识别任务差异，保留无关文件和预暂存内容；不以整仓 add、reset、clean 或 stash 掩盖归属问题。
- 根据任务范围做必要检查，准备清晰提交；范围明确的本地操作自主完成，不逐项询问提交信息或文件。合理分支选择沿用现有授权，不额外建立审批机制。
- 已授权的远端目标与动作不重复确认。需要范围外动作时先将差异、提交、目标仓库与分支、PR 草稿或合并对象准备为可审阅结果，再澄清该部分。
- Draft PR 承载实施 Plan 与实际结果，引用 Issue 和适用 Blueprint，不复制需求或新增 plan.md。复用已有 PR；普通交付不自动退出 Draft、合并或关闭 Issue。
- 不把未完成内容改成完成来满足提交条件；发现代码或契约问题回到相应工作，不在交付中吞并无关修复。
- 失败或结果不确定时先读实际状态，避免重复 commit、push、创建或合并。强推、改写历史、删除与绕过保护须属于明确范围。

核验本地 SHA、远端分支、PR/MR URL 与源／目标及实际合并状态。队列或自动合并等待不算已合并。报告达到的终点、检查结果、未完成与风险；交付不代表部署或用户人工验收通过。
