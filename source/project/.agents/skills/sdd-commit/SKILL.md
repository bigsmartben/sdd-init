# Git 与平台交付

进入流程前按[交付](../../sdd/references/sdd-repository-governance.md#交付)核对任务是否包含 Git 交付。输入为交付意图、改动或议题范围及已有授权。进入流程后，未指定交付终点时只执行授权范围内的本地提交。

1. 从用户意图和既有任务约定确定交付终点、范围及源／目标。涉及平台时读取[平台适配与远端操作](references/git-remote.md)，从实际 remote、对象链接及仓库元数据识别 GitHub 或 GitLab（含企业／自托管），选择已有连接工具、CLI 或 API；先自行查询可获取的信息，只询问无法消歧或获取的必要输入。
2. 涉及本地代码交付时读取工作区、暂存区、分支和相关提交，明确归属；保留无关修改及预暂存内容，不将其混入本次提交。归属不明时澄清，不用整仓 add、reset、clean 或 stash 掩盖问题。核对本次交付要求的有效证据，准备提交分组和信息，不自动追加架构 Review 或完整验收。只做 Issue 或处理指定既有 PR／MR 时无需先提交代码，不附带工作区变更。
3. 按下表自主完成到达终点的必要步骤，复用本任务已有分支及平台对象。新建用于远端交付的分支前及每次 push 前，按[远端同步检查](references/git-remote.md#远端同步检查)刷新实际远端状态，分别比较远端同名分支和目标分支；新分支无 upstream 也须检查目标基线。落后或分叉先安全同步、完成受影响验证再推送，不凭本地 main、旧 tracking 或一次 push 成功判定基线最新。无新改动则跳过 commit，继续尚未完成的授权远端步骤。失败或结果不确定时先查实际状态，避免重复动作；认证、权限或持续失败时返回阻塞及最小恢复动作。
4. 回读实际终点：本地及远端 SHA、源／目标、Issue 或 PR／MR 链接与状态、适用检查结果。合并前重新核对最新提交、检查及审批，受保护规则约束；已排队或启用自动合并仍需继续查询，不能作为已合并回执。

| 用户指定终点 | 自主完成的必要操作与停止点 |
|---|---|
| 本地提交 | 明确范围的暂存与普通 commit；返回本地 SHA |
| 创建分支 | 按指定本地／远端范围、起点及项目命名约定创建或复用任务分支；用于远端交付时先获取最新目标基线，明确指定固定起点则保留该约定；不附带 commit、其他分支推送或 PR／MR |
| 推送 | 确定任务分支，获取并比较远端同名分支及最新目标基线，安全整合后提交授权差异、执行受影响检查并推送到指定 remote；不自动创建 PR／MR |
| 创建／更新 Issue | 查重、整理协作摘要和权威正文引用、创建或更新本任务 Issue；返回链接，不自动提交或关闭议题 |
| 提交／更新 PR／MR | 准备任务分支、commit、push，查重并创建或更新 PR／MR，填写变更、验证及关联引用；返回请求链接与检查状态，停在请求阶段 |
| 合并／交付到目标分支 | 自主完成必要的分支、提交、推送及 PR／MR 步骤，按仓库允许的策略与检查／审批规则合并；返回合并状态和目标提交 |

按终点授权整段必要操作，不为分支命名、提交信息、push 或平台按钮逐项确认。需要新增外部操作授权时，先准备可审阅的仓库、范围、源／目标及拟执行结果，按[分段确认](../../sdd/references/visual-confirmation.md#呈现与确认)聚焦该缺口。等待或工具的自动确认参数不是授权。amend/rebase、强推、删除、绕过保护、创建远端仓库或修改权限不包含在普通交付授权中。当前分支不适合承载改动时先解决分支归属；合并冲突需改代码时交 sdd-imp。

远端 Issue 与 PR／MR 只承载协作摘要、关联及交付事实，需求正文仍归 Spec、验证事实归报告、问题处理事实归独立 Issue；只按用户要求或项目既有约定建 Issue，不为每次提交额外创建。独立问题记录中的缺陷 Issue 不自动等同平台 Issue；需要同步时关联独立记录、原编号与报告，关闭遵循实际复验结论及任务授权。需要角色交接时读取[执行协作](../../sdd/references/delegation.md)。代码整改交给 sdd-imp，正式文档或 Status 更新交给 sdd-doc。

输出：实际达到的终点、平台对象链接、SHA／分支、检查或审批状态及阻塞；区分已推送、请求已创建、等待检查／审批、排队／自动合并及已合并。

例：用户要求“把本次修复发 MR 到 develop”。识别 GitLab 实例及项目，准备或复用任务分支，只提交本次修复，推送并创建或更新目标为 develop 的 MR，返回链接及检查状态；无需用户逐项创建分支或点提交按钮，不继续合并。
