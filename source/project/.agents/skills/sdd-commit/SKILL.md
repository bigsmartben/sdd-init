# sdd-commit — GitHub / GitLab 交付工作流

## 场景、职责与作用对象

场景：将明确范围的工作交付到用户指定的 Git 终点。
职责：核对改动归属与必要证据，准备提交及远端动作，按已有授权执行并核验回执。
作用对象：工作区/暂存区差异、提交、分支、远端及 PR/MR；读取相关 Spec/Status 和验证证据，不通过修改需求或伪造状态满足交付条件。
完成依据：实际达到本地 commit、push、PR/MR 或 merge 等指定终点；未指定时默认本地 commit。范围外代码整改、架构/需求改写和独立 Loop 不属于交付职责，远端操作仍遵守原授权边界。

任务包含 Git 交付意图时，Agent 自主选择本 Skill，无需用户输入 `$sdd-commit`；名字中的 commit 泛指交付流程。按已授权的终点执行（本地提交、push、PR/MR 或 merge）；已有交付意图但没有终点时，默认完成本地 commit，准备后续方案，不默认发布或合并。普通文档或实施任务不因本 Skill 可自动选择而取得 Git 交付授权。

默认 Main 执行；仅按 [执行约定](../../sdd/references/delegation.md) 的条件按任务分工。

遵循[实体治理](../../sdd/references/governance.md)，涉及测试、验收及证据核对时按其中的[测试范围约束](../../sdd/references/governance.md#测试范围约束)执行。

## 先完成可自主执行的准备

- 读取工作区、暂存区、分支、remotes、相关提交及平台状态，识别 GitHub/GitLab 与企业/自托管主机；优先使用已连接且能力完整的工具，其次已安装并认证的 `gh` / `glab`。读取 [平台操作说明](references/providers.md) 中匹配的部分。
- 从当前任务契约与 diff 确定提交范围。已有明确范围不重复问；混合改动中无法判断归属的部分单独澄清。保留无关文件及预暂存内容，不用整仓 add、reset、clean 或 stash 掩盖范围问题。
- 对完成的 SDD 迭代核对 Status、当前证据与适用验收。只因缺陷真实存在、证据过期或必要决策缺失而停止；不强制补跑任务契约未要求的两个独立 Loop。普通文档/工具改动无需伪造一个完成的 Spec。
- 在授权范围内自主选择合理的提交分组和信息，运行必要检查并完成本地 commit；不为普通 commit、提交信息、读取 diff、暂存明确归属的文件逐项询问。不得把未完成状态写成完成来满足提交条件。若当前分支不能承载改动，先准备分支方案并取得创建授权，不能为减少确认先误提交到目标分支。
- 已有相关提交、PR/MR 时先核实并复用；没有新改动则报告无须提交。每次操作失败或返回不确定结果，先读取实际状态，避免重复 commit、push、创建 PR/MR 或 merge。

## 确认边界与减少打断

| 动作 | 授权要求 |
|---|---|
| 只读盘点、必要检查、范围明确的暂存与普通本地 commit | 已授权交付任务范围内自主完成 |
| 创建分支（含 worktree 中新建分支） | 明确分支名、起点及用途后确认 |
| push | 明确 remote/仓库、源/目标分支、待推送提交及推送方式后确认 |
| 创建或更新 PR/MR | 完成标题/正文草稿，明确源/目标、draft 状态及接收仓库后确认 |
| merge、入队或开启自动合并 | 基于具体 PR/MR、最新 head SHA、目标分支、检查/审批和合并策略确认 |

一次呈现当前已经具体化、可审阅的分支＋push＋PR/MR 计划，可以由用户一次批准明确列出的动作；不要把它拆成重复问答。尚未具体化的后续动作不包含在授权中。merge 通常在 PR/MR 与必要检查就绪后确认；已获得针对实际对象和 head 的明确 merge 授权时不重复问。工具的 `--yes` 或自动化参数不是用户确认。

保存对话中的授权上下文；动作、远端目标、提交范围、head、base 或合并策略发生实质变化时，只重新确认变化部分。普通 commit 不额外确认；amend/rebase、强推、删除分支/文件、绕过保护或管理员合并不包含在普通 commit 的授权内。用户未要求清理时不清理任何文件或分支。

实际变更必须先准备到可审阅再请求确认。首次创建分支前可准备工作区 diff 和 PR/MR 草稿；后续 push/PR 只有在实际提交范围与已批准计划一致时继续，否则更新计划。等待或缺少回复不构成批准。

## 完成条件

每个已执行动作读取回执和平台状态：本地 SHA、远端分支 SHA、PR/MR URL 与源/目标、最终 merge 状态。队列/自动合并已启用只能报告等待，不能报告已合并。审查通过但尚未合并也不等于交付完成。

报告已完成动作、验证、后续待确认动作及阻塞；按实际终点判断完成。请求确认失败时保留已有成果。需要代码整改时交回 Main 在已授权范围处理，不得在交付中擅自重写设计或吞并无关工作。需要维护实体文档时由当前执行者根据已验证事实直接记录。
