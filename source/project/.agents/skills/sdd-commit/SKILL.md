# Git 交付

输入：交付意图、改动范围和已有授权。普通讨论、文档写入或实施不自动触发交付。

1. 读取工作区、暂存区、分支和相关提交，明确归属；保留无关修改及预暂存内容。归属不明时澄清，不用整仓 add、reset、clean 或 stash 掩盖问题。
2. 核对本次交付要求的有效证据，准备提交分组和信息。不自动追加架构 Review 或完整验收，不把未完成状态改成通过。
3. 按下表执行至指定终点，失败或结果不确定时先查实际状态，避免重复动作。没有新改动则报告无需提交。
4. 回读本地 SHA；涉及远端时回读远端 SHA、PR/MR 的源与目标及最终状态。排队或自动合并仍待完成时不得报告已合并。

| 动作 | 授权边界 |
|---|---|
| 检查、明确范围的暂存与普通本地 commit | 在已授权交付范围内自主完成 |
| 新分支、push、创建或更新 PR/MR | 准备可审阅方案，明确仓库、起点、源/目标、提交范围及推送方式；已有对应授权则直接执行，否则确认 |
| merge、入队或自动合并 | 明确 PR/MR、最新 head、目标分支、检查及合并策略，按对应授权执行 |

授权沿用，仅实质变化部分重新确认；等待或工具的自动确认参数不是授权。amend/rebase、强推、删除、绕过保护不包含在普通提交授权中。当前分支不适合承载改动时先解决分支归属，不误提交。

涉及远端时读取[平台操作](references/providers.md)中对应平台部分；需要角色交接时读取[执行协作](../../sdd/references/delegation.md)。代码整改交给 sdd-imp，正式文档或 Status 更新交给 sdd-doc。

输出：实际达到的终点、回执、验证及阻塞。

例：用户只要求提交本次修复，工作区还有无关文档修改。只提交明确属于修复的差异，保留无关内容，返回本地 SHA，不 push 或创建 PR。
