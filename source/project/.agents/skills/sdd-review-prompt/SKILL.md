# 提示词 Review

识别会稀释关键指令、造成歧义或增加无关读取的内容。默认只审查，按实际授权修订和复验。规则表与任务 DAG 留在审查回执。

1. **建立审查基线。** 确定审查对象、版本和调用场景。沿实际入口核对指令的权威来源、加载条件和优先级，只读会影响当前场景的章节。以已确认行为作预期；发现原版偏差时单列，依据冲突或不足时标明待决范围。
2. **提取规则表。** 每条记录标识、来源位置、适用条件、负责方、预期动作或禁止项、授权、例外、完成或 Gate 判据，按适用项填写。前后版本映射到同一规则，核对删除、合并或迁移后，规则在决策时仍可取得且含义明确。遇到条件重叠，核对实际优先级。
3. **建立场景任务 DAG。** 节点记录可观察的读取、决策、操作、交接或取证，边记录必要的先决条件。标明分支触发条件、禁止路径和完成证据；重试按本次尝试展开。独立步骤可重排或并行。比较关键分支、依赖、结果与副作用。
4. **归并发现。** 按影响列出位置、规则或节点、触发场景、后果和最小修订建议。合并前核对作用域、条件、优先级和动作等效，且所有适用路径仍可获得规则。删除无效内容前，检查它是否为任何场景提供独有的判断依据、动作约束或取证要求。修订时直接写目标和完成条件，常规步骤用短指令，容易误判的分支才使用 Given／When／Then。
5. **复核场景。** 按审查范围覆盖正常路径、易混分支、未授权动作、适用例外和 Gate。单版对照已确认预期，有候选版时用相同输入、权限、工具、模型和配置对跑，从等价状态开始。记录实际读取、关键动作或拒绝、产物与副作用。需要判断稳定性时，用相同配置复跑关键场景并记录差异。有外部写入的场景使用授权范围内的隔离环境或替身。

回执给出规则表、各受影响场景的任务 DAG、发现和逐场景结论，可引用既有证据。规则、依赖或实际行为偏离已确认预期时标记失败。只有适用规则与必要依赖全部保留、约定场景的实际关键行为均符合预期，才判定行为验证通过。仅有静态对照、缺少基线或无法运行时，记录已完成的检查、未验证范围及缺少的证据。Token 与读取量可作为辅助数据。
