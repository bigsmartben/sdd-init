# SDD 验收准备

按[仓库治理](../../governance/repository.md)沿用场景矩阵，展示集成版本、实际结果、差异与未验证路径。

按明确自然语言意图选择本 Skill，无需用户输入名称。读取[协作约定](../../sdd/references/governance.md)，沿用已有版本、环境与操作授权。

1. 定位 Issue 的验收条件、适用 Blueprint、PR 和指定版本，以及目标环境、部署方式和访问条件。缺少版本或环境等实质信息时仅澄清受影响部分；可先整理已有验收步骤。不得自行选择生产环境。
2. 检查目标工作区和部署现状，保护未提交改动。拉取指定代码并核对实际 commit；分支或标签同时记录解析后的 SHA。使用项目既有部署流程，按授权处理环境；依赖、配置、数据和访问权限不足时如实报告，不用模拟服务冒充真实环境。
3. 部署后检查进程、健康状态和用户入口可访问性。记录版本、环境、入口、检查时间和结果；自己可访问不证明用户可访问。失败时记录部署日志和恢复点，不自动修产品代码，也不以部署名义改需求或架构。
4. 按[操作文档模板](../../sdd/assets/acceptance.md)提供前置条件、测试数据、操作步骤与预期结果。按任务需要覆盖结构、交互和业务状态；纯视觉样式及像素还原不作为符合性要求。
5. 交由用户人工操作并反馈。分别报告环境准备、可访问性检查和人工验收状态；未收到反馈时保持待验收，不能以部署成功、自动检查或原型确认代替人工通过。

反馈记录版本、环境、复现步骤、预期与实际、证据及用户结论，区分事实和猜测。缺陷、重构或需求变化回到普通讨论，按实际需要固化到 Issue／Blueprint／Draft PR。修复需要明确实施意图，由 sdd-imp 承担；本 Skill 不自动启动修复循环、提交、合并或关闭 Issue。
