# 面向用户功能的集成测试

本轮已有明确的用户功能验收范围时进入。sdd-imp 按工单维护 Plan／Task、实施和局部自验，交付实际版本、运行入口、已知准备条件及证据。本轮仅要求实施和局部自验时，Task 完成即可结束；约定的用户验收按上游方案实际取证。可用定向局部检查完成的单独复验按[职责与交接](../../sdd/references/sdd-repository-governance.md#职责与交接)执行。本流程负责集成测试准备和执行。实现和测试代码的修改由 sdd-imp 承接。

## 人工确认与待验

- **首次实测前是唯一的常规确认点。** 集中核对验收产品范围、目标版本、测试环境和主要用户路径。沿用启动指令及已有确认中明确的内容，只把未明确的部分集中交 Main 按[意图对齐](../../sdd/references/visual-confirmation.md#意图对齐)确认。四项均明确时，完成常规准备即可实测。
- **执行中只对齐受影响事项。** 验收范围变化、拟改测其他版本或环境、业务判据需补齐、调整或消除冲突，或需要补充操作授权时，将具体影响交 Main 对齐。暂停受影响项及其依赖，继续其他已授权且就绪的场景。判据明确而实测不符时，按原判据记录失败和证据。
- **按需获取人工验收反馈。** 准备复跑指南时，标出确需用户实际操作或主观判断的场景，说明操作步骤和所需反馈。在 Test Report 中单列人工待验、实际反馈及其对 Test Gate 的影响。必要反馈尚缺时，记录待验状态与恢复条件。

## 本轮闭环

1. **确定验收范围。** 先定位工单提供的验收文档；从项目索引补查已确认的 Spec／AC、适用契约、原型和已有 Quickstart。按[测试范围约束](../../sdd/references/sdd-repository-governance.md#测试范围约束)明确本轮用户场景、判据、目标版本、环境和需要真实运行的组件，复用有效交付信息。验收依据缺失时按[人工确认与待验](#人工确认与待验)处理受影响项。
2. **准备本轮验收文档。** 复用上游文档的场景、步骤和判据，结合本轮范围按 [Quickstart](../../sdd/assets/quickstart_template.md) 补齐实际版本、环境、真实入口、起始数据、关键观察点及必要的复位方法。直接发起集成验收且没有上游工单时，依据已确认的场景／AC 和适用契约复用或准备可执行指南。可自行推导常规数据、边界值和执行顺序，验收标准沿用已确认依据。需要正式落盘时，把本轮使用的文档交 sdd-documenter 归并。本轮交付提供验收文档或其可访问链接，供用户按步骤复跑。
3. **执行集成测试。** 核对[实测前确认](#人工确认与待验)、实际运行版本及相关未提交修改，在指定环境从用户实际使用的操作或调用入口验证真实组件协同、关键过程和用户可观察结果。纳入本轮的用户可感知非功能指标按已确认的测量条件、统计口径和阈值取证。覆盖本轮要求的组合行为、异常与恢复，模拟结果仅用于其实际覆盖。UI 验收限于中保真，核对信息结构、页面布局、操作路径、交互反馈和业务状态，排除纯视觉样式和像素还原检查。按版本、环境、组件和判据核对已有证据，只补未覆盖项。变更后按实现、接口、数据和环境的实际影响确定补验范围。需要独立验证时按[执行协作](../../sdd/references/delegation.md)核对。
4. **记录结果。** 沿用场景／AC 编号，逐项记录通过、失败、未测或阻塞及原因。将实际版本、环境、数据、观察结果和证据交 sdd-documenter 归并 [Test Report](../../sdd/assets/test_report_template.md)，Status／Plan 引用报告。指定版本和环境下，范围内全部适用功能点及本轮判据均满足，且必要证据和必需的人工验收反馈齐备时，Test Gate 才可判为 PASS。复验另记批次，保留历史结论。
5. **交接问题。** 需要跟踪的问题按 [Issue](../../sdd/assets/issue_template.md) 记录场景依据、复现条件、预期与实际差异、影响、版本及证据，已有 Issue 沿用原编号。疑似实现缺陷在授权内交 [sdd-bugfix](../sdd-bugfix/SKILL.md) 验证归因，缺失的测试代码带 Issue、适用场景、应补覆盖及验收说明引用交 [sdd-imp](../sdd-imp/SKILL.md)，证据缺口由本流程补查，文档矛盾交 sdd-documenter，需求缺口交回讨论。只验收时按授权记录发现和待办，未测或阻塞的项记录缺口及恢复条件。已登记的非代码问题处理后，将结果交回本轮验收执行者按原 Issue 核验。核验通过后，由文档维护者根据证据更新原 Issue 为已核验关闭。

Bug 原故障纳入本轮集成验收范围时，按原 Issue 的判据在修复版本复验原场景或可证明等价的场景。仅纳入相关回归时，在修复版本验证本轮范围内的回归项。故障仍在或有回归时，带原编号及新证据返回归因或实施阶段。原场景、必要回归及所需人工确认均满足时，提供该 Issue 的关单依据，由 sdd-documenter 更新原记录。关单依据和整轮 Test Gate 分别按各自覆盖判断。
