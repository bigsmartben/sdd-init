# 需求验收

1. 从项目索引定位目标需求、AC、边界、质量目标及已确认的测试计划，核对验收环境、代码快照、数据和判断点。缺少测试范围、数据选择或标准等实质决定时交回讨论；计划由 sdd-doc 按[测试计划模板](../../sdd/assets/test-plan.md)固化，不在执行时自行补定。按[测试范围约束](../../sdd/references/governance.md#测试范围约束)执行。
2. 运行能证明目标行为的测试，核对前提、触发及可观察结果。多个能力同时验收时，检查相关组合行为、异常恢复和跨模块交互，不能从单项通过推导组合通过。
3. 沿用计划场景 ID 和判断点，输出实际结果与预期差异、证据、环境、数据、快照和未测项，供 sdd-doc 按[验收报告模板](../../sdd/assets/acceptance.md)整理。Agent 提供证据与操作指引，用户只需查看、操作、判断或反馈；所需人工确认与机器执行结果分别记录，无反馈时不代替用户确认。缺陷及缺失测试交给 sdd-imp；需求缺口交回讨论，文档矛盾交给 sdd-doc。
4. 整改后复验受影响场景。全部目标 AC 和相关组合行为在同一快照通过才可报告 Test Gate PASS；不可执行或证据不足时如实报告阻塞或未验证。

本流程负责验收与复验，不修改实现、测试代码、需求或正式文档。验收证据由 sdd-doc 落盘，实际结果只在报告维护，不回填计划或在 Status 复制矩阵；架构一致性由 sdd-review-loop 检查。按[项目职责](../../governance/repository.md)对照同一场景展示结果；需要声明独立性时按[执行协作](../../sdd/references/delegation.md)判断。

例：AC 要求取消后不再提交订单，实际取消后仍发出请求。记录操作、实际请求和失败证据，交给 sdd-imp 修复；未测的退款场景不标通过。
