# 部署与服务运行

进入流程前按[交付](../../sdd/references/sdd-repository-governance.md#交付)核对任务是否包含运行请求。输入为目标项目、运行意图、版本及可选环境。未指定环境默认 dev。仅在必要信息无法取得或目标有歧义时澄清。

1. **探测与定位**：读取项目 AGENTS、运行指南及环境配置，遵循[环境架构规范](../../sdd/references/architecture-rules.md#环境架构规范)。落地前检测本地操作系统、可用工具与运行时、连接上下文、既有服务、端口和依赖；远程部署另核对目标环境。确定部署入口、版本和就绪判据，不以本地状态代替远端状态。
2. **准备环境**：沿用项目明确的部署规范；dev 优先 Docker Compose，复用已有 Compose 配置与项目标识，缺少时按项目需求补齐。其他环境按实际条件选择，不绑定平台发行版、操作系统路径、个人仓库或集成／CI 拓扑。自主安装、配置和修复所需工具、依赖、网络与存储；路径按实际宿主和运行时解析并验证挂载。共享依赖兼容才复用，项目数据与凭据保持隔离，不随服务重启清除持久化数据或改动其他项目资源。凭据使用环境既有管理方式，不写入仓库或日志；新增运维资产或改变其用途时查[工程资产边界](../../sdd/references/sdd-repository-governance.md#工程资产边界)。
3. **部署与运行**：按下表执行，复用服务标识、部署位置和端口，遵循既定副本与更新策略。冲突先查归属，不通过新开实例、随机端口或另一套环境绕过；仅处理目标服务，保留其他项目实例。
4. **就绪与恢复**：核对运行版本、实例／副本、端口、健康状态及必要依赖，由既定服务管理机制持续运行。失败查状态与日志，自主修复；超时或结果不明先查询再重试，按项目策略恢复。持续失败且无新修复依据时返回阻塞与恢复条件。就绪检查不替代业务验收，后者由 sdd-test-loop 承担。

| 请求与现状 | 执行行为 |
|---|---|
| 首次部署或更新 | 必要构建与部署；已有服务更新并重启，无实例则启动 |
| 启动已部署服务 | 已停止则启动；目标版本已健康运行则复用 |
| 重启服务 | 通过既有管理入口重启；无实例则按部署配置启动 |
| 重复请求 | 回读版本与状态，继续未完成动作，避免重复创建服务 |

需要交接时读取[执行协作](../../sdd/references/delegation.md)。实现缺陷交 sdd-imp，正式文档归并交 sdd-doc，任务包含 Git 交付时交 sdd-commit。

输出：目标环境与位置、运行版本、服务标识和就绪状态、访问及日志入口、环境修复摘要与剩余阻塞。
