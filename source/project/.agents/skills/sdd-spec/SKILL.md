# 需求规格与实施交接

用于新需求和需求变更。只讨论时返回候选结论和待决项。已确认行为出现实现偏差时，交 [sdd-bugfix](../sdd-bugfix/SKILL.md) 评估归因。

1. **对齐需求。** 从项目索引定位能力 Spec、相关 AC 和适用的契约或已确认原型。明确用户目标、交付范围、须保持的行为及可观察结果。从用户操作或调用入口说明适用场景的前置条件、操作步骤和可观察通过判据，覆盖相关异常和边界。用户可感知非功能指标沿用已确认的测量条件、统计口径和阈值。已有确认直接沿用，新增或变化按[意图对齐](../../sdd/references/visual-confirmation.md#意图对齐)呈现并请求确认。
2. **形成工单。** 将已确认的新内容交 [sdd-documenter](../../sdd/references/delegation.md#文档交接) 按 [Spec](../../sdd/assets/spec_template.md) 原位归并，保留稳定编号。已有条款足够时直接引用。以本轮适用的 Spec／AC 及必要契约作为工单依据，补充本轮范围、须保持的行为及完成判据，沿用原规格载体。需要派单时，随工单提供用户验收文档或可访问引用：复用已有可执行说明；缺少时按已确认依据和 [Quickstart](../../sdd/assets/quickstart_template.md) 组织场景／AC、前置条件、操作步骤和可观察预期。按已知信息注明目标环境与入口，实际运行版本和环境可在集成验收时补齐。正式落盘由 sdd-documenter 按需归并。
3. **接续实施。** 只写规格或明确暂缓实施时，按用户限定的终点返回。工单及其可访问、可执行的验收说明就绪后，在同一任务中直接进入 [sdd-imp](../sdd-imp/SKILL.md)，按[执行协作](../../sdd/references/delegation.md)交接。方案、Plan／Task、代码修改和局部自验归 sdd-imp。确认、判据或验收说明不足时，只保留受影响项及依赖待定，其他已就绪工单继续。
