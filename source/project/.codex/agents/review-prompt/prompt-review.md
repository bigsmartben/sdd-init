# 提示词审查与优化

本文件是 review-prompt 的配套规则，与角色配置一起携带；文中受审仓库的路径与组织方式按实际输入确定。

## 目标与范围

审查仓库中的 AGENTS.md、自定义 Skill、角色、业务提示词及其候选版本。按实际入口、配置和引用确定加载关系，补读影响判断的共享指令、模板及装配逻辑。仓库专项规则作为本轮依据，不预设工作流的角色或层级。读取范围与获授权的修改范围分别记录。

优化目标是在满足同一目标与验证契约的前提下，降低端到端执行时间和实际 token 开销。本文成本及成本预算均指 token 消耗，执行时间作为独立效率指标。Review Rules 用于定位问题并产生优化候选；成本收益由实际对照执行判定。提示词长度和 Plan 一致性不作为采纳标准。

## 提取目标与验证

优化前从当前提示词及已确认依据提取可检查的执行规则，按以下两段组织共同评价契约：

| 段落 | 必须明确的内容 |
|---|---|
| 目标 | 输入、适用条件、预期结果、交付物、必要约束及授权边界 |
| 验证 | 成功判据、检查依据与方法、必要证据，以及失败或缺证时的处理 |

每项注明原文或确认来源。已有规则直接提取，可由已确认依据确定的缺项直接补齐；歧义、冲突及涉及新增预期、职责或授权的部分列为待决交调用者，保留受影响项，其余继续。该提取描述执行契约，不要求模型内部思维过程。

提示词已有完整语义但未按标题分段时，仅整理评审表示，保留基线原文。本轮要求显式分段或已有依据足以补齐契约时，在写入授权内直接处理。契约提取、静态审查和明确结论的归并不另设确认节点；实验前共同契约须明确。

## Review Rules

按实际对象、有效上下文和场景判断适用性。每个发现给出规则编号、位置、触发场景、依据、影响及建议；无法确认的行为影响标为待验假设。

| 编号 | 类别与适用范围 | 问题成立依据 | 保留要求 |
|---|---|---|---|
| PR-01 | 契约完整：所有受审提示词 | 目标或验证缺失、不可判定，或验证不足以证明目标达成 | 已确认目标、可观察结果、验收条件及来源 |
| PR-02 | 执行可行：包含操作、工具、引用或交接的要求 | 必要条件、工具、权限、规则加载或引用不可用，且缺少相应缺口处理 | 实际能力与权限边界、有效引用、失败和恢复路径 |
| PR-03 | 语义一致：存在多条要求、多个入口或宿主规则 | 相同条件下指令冲突、歧义、作用域错误、职责或授权越界；须指出实际生效依据 | 优先级、适用条件、独有例外及职责交接 |
| PR-04 | 必要性与成本：重复内容、反向约束、元指令及固定流程 | 同一有效上下文重复同一要求而无独有用途；空泛强调、无依据的禁止或固定步骤造成可说明的歧义或额外工作 | 必要禁止、独立入口所需提醒、宿主未覆盖的约束；不凭否定词数量或元指令标签判错 |
| PR-05 | 改写保持：删除、合并、迁移或替换候选 | 候选丢失共同契约中的目标、约束、例外或验证；迁移后决策时不可达；以弱化判据制造收益 | 逐项说明语义保留或承接位置；修复基线错误以已确认预期为准 |

## 优化策略与核对节点

按发现选择最小改动：重复内容归并到适当正文；空泛要求改成条件、动作和结果；否定枚举可改成选择规则，保留必要限制；条件缺失先补齐依据；职责错位调整归属并同步引用。规则归属与加载方式由受审仓库决定。静态可确认的冗余或冲突与待验证的效率假设分别记录。

| 核对节点 | 检查内容 |
|---|---|
| 审查就绪 | 对象、版本、入口、授权和目标／验证契约可定位；缺口影响范围明确 |
| 问题成立 | 发现可追溯到规则、场景及依据，区分事实与假设 |
| 改写完整 | 授权内生成候选，核对语义承接、引用及独立入口，保留基线和候选 |
| 交付可信 | 静态、装配与行为证据分别报告，采纳结论符合下述评价模型 |

上述节点是执行者自检，可按任务合并。只审查止于发现与建议，只比较保留输入文件；已授权优化且结论清晰、有依据时，保留改前基线后直接修订、核对并落地，无须先做 A/B 或逐项请求确认。静态优化可独立交付，效率收益仍须实测证明。

### A/B 实验前唯一确认节点

需要执行 A/B 时，先经实际调用者向用户集中同步本次实验方案，取得明确确认后才启动受测运行、付费评估或实验专用资源。角色可在已有授权内完成静态准备和直接优化；对照实验不是优化落地的前置条件。实验前确认是本流程唯一的用户确认节点，不在契约提取、候选改写或结果交付时重复设置审批。

| 同步项 | 必须呈现的内容 |
|---|---|
| 目标与版本 | 对照问题、共同目标／验证契约、A／B 标识，是否已直接优化及待证明的收益 |
| 用例 | 输入、预期结果和验证方法，正常、边界、异常与恢复覆盖，排除项及理由 |
| 规模 | 基线及候选数量、用例数、每例每版重复次数、总执行次数、并发度、模型与工具环境；评估、子 Agent 与允许重试纳入计划 |
| 成本预算 | 本次实验总 token 估算范围及硬上限，包含两版执行、评估、子 Agent 和重试；说明估算来源、缓存假设及不确定性，不能用提示词字数伪装实际 token |
| 执行时间 | 预计端到端墙钟时间，作为独立效率指标呈现 |
| 停止与采纳 | 预算或时间上限、失败和重试终止条件、正常波动口径、效率取舍优先级，以及候选应用的既有写入授权 |

记录确认内容、来源和适用版本。用户未确认、拒绝或暂缓时止于方案及已完成的静态优化，不启动实验。已有确认完整覆盖上述内容时直接沿用。执行中跟踪 token 预算，预算耗尽、预计超限或规模、用例、版本、模型和 token 统计口径实质变化时暂停受影响实验；需要调整则回到同一节点更新方案并取得确认。无法可靠估计或约束成本时先报告缺口，不以无限重试或未知开销启动实验。

## 验证与评价模型

### 基线与实验前提

- 默认以优化开始时实际生效的当前版本为 A，候选为 B。冻结受审源码、引用、装配配置及范围内的未提交修改，记录版本或哈希与实际加载证据；Git HEAD 不自动等于生效版本。用户指定基线时记录来源及适用性。
- 需要补齐或纠正共同契约时保留原版 A0，依据已确认预期修正后的合格版本为 A，再生成 B。区分 A0 到 A 的规则修正与 A 到 B 的效率优化；基线不符合已确认预期时，不以保持其错误行为作为通过条件。直接落地优化后仍保留改前版本，按实验方案绑定 A／B，不把已改写版本误当作原基线。
- A、B 使用相同任务输入、模型配置、工具能力、权限和等价初始环境。按同一契约选择正常场景及改动涉及的边界、异常、授权和恢复场景，每次执行前复位影响结果的状态。受测执行者只接收任务所需材料，评价者的评分说明另行保管。
- 按[实验前确认](#ab-实验前唯一确认节点)覆盖的规模、用例和预算，在隔离环境内实际运行；关键场景重复并交错运行，记录全部尝试及失败。按确认的判据、重复安排和波动口径判断；没有足够证据区分差异时保持待验，不根据一次偶然结果判优。

### 结果准入与成本口径

结果等价指交付物及实际效果满足同一契约，必要约束、授权、验证与失败处理得到保持，且没有未授权副作用。回复措辞、Plan、工具顺序和实现路径可以不同。计划或指令装配成功只证明相应范围，不代替实际结果。

| 指标 | 口径 |
|---|---|
| 结果 | 逐场景记录成功、失败、未测与阻塞及实际产物、状态和证据；比较成功率及重复运行差异 |
| 执行时间 | 从接收任务到约定交付的端到端墙钟时间，包含工具等待、重试、委派与验证；并行子任务耗时不重复累加。人工等待、环境故障等外部影响单列并保持比较口径一致 |
| Token | 整轮实际输入、输出及可取得的推理 token，包含子 Agent、重试和验证调用；注明提供方字段含义，缓存命中单列，已计入输入或输出的缓存／推理量不再次累加 |

同时列出逐次值与汇总，避免只选择成功或最快的尝试。提示词字符数不替代实际 token；无法取得的遥测标未测及原因。比较成本包含运行时按需加载的引用内容。审查、候选生成和实验准备的 token 消耗与受测任务执行消耗分开报告。

### 采纳与交付

在结果满足共同契约、稳定性未退化且差异可由证据支持的前提下：

| 对照结果 | 处理 |
|---|---|
| 更快且 token 更少，或一项更优而另一项相当 | 推荐候选；应用仍按本轮写入授权 |
| 时间与 token 一优一劣 | 按实验前确定的优先级或预算取舍；未覆盖的取舍交付差异并保留基线，不自动替换或追加实验 |
| 两项相当、均退化，或差异不足以排除正常波动 | 无效率替换依据，保留基线或按需补验 |
| 结果不等价、必要约束丢失或关键证据缺失 | 不凭成本优势采纳；记录问题、未验范围及恢复条件 |

回执引用共同契约、基线与候选标识、规则发现、改动及承接位置、逐场景结果、时间与 token 证据、采纳依据及未验事项。有实验时附用户确认、实际规模、预算消耗与停止原因；静态直接优化与实验结论分别说明。报告默认随回执交付，文件仅写入工单授权的位置；只完成静态优化时不宣称效率改善。
