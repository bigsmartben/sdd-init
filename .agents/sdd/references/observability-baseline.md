# 运维与可观测架构原则

> 目标仓库依据已确认的 Blueprint 和契约落实适用原则。Review 按[适用性判据](sdd-repository-governance.md#观测基线落实与审查)检查项目规则与实际数据路径。

## 职责与隔离（SDD-OBS-01）

日志记录事实，指标表达统计，链路表达跨调用关联与先后；评测消费日志、指标及授权测试资产，不另立采集类别。业务负责执行与权威状态，通过明确接入点报告事实；观测负责格式化、存储、轮转、采集导出、统计与展示，不指定库、事件总线或进程。

观测可记录业务接口提供的事实或快照，保存受 SDD-OBS-02 约束；不得拥有或修改权威业务状态、改变业务语义或驱动业务决策。业务不得依赖观测数据、工具或评测结果实现功能，包括状态、流程推进与计费，须使用业务接口和权威数据。

非侵入要求适用于观测采集、导出、分析与评测；技术流控及进程生命周期见[运行控制职责](architecture-rules.md#业务与运维可靠性职责分离)。业务不得等待观测写入、导出或评测；观测异常、超时、不可用和缓冲饱和不得导致业务失败、反压或结果变化。观测不得对业务产生副作用，包括修改业务输入输出及状态、消费或关闭业务仍需的流和资源，或因观测重试重放业务。采集须非阻塞并隔离资源与生命周期，异步调用本身不证明隔离。

项目要求持久化时，写入仍须与业务隔离，不得靠暂停、取消或拒绝业务保证日志完整。观测故障须暴露独立状态、错误及缺失证据，按项目策略缓冲恢复；无法保存时判记录要求未满足，不静默丢弃或伪装成功，不承诺无限故障无损。业务继续与记录完整分别取证。

<a id="debug-采集边界与原始交互持久化sdd-obs-02"></a>

## 日志、指标与媒体保存边界（SDD-OBS-02）

项目按数据用途与授权确定必记事实、禁存内容及保留范围。调试级别不得改变已确认的必记或禁存要求。记录应区分实际发生的阶段、结果与缺失，凭证和 API Key 排除在日志之外。

保存边界覆盖实际采集、缓冲、重试与归档路径。业务或测试资产按各自用途与授权管理。例如，项目契约若禁止观测保存原始音频，须检查各写入路径能否拒收音频及其等价编码；测试资产的保存授权仅适用于约定用途。

<a id="有限资源下的项目策略"></a>

项目要求持久化时，按契约规定的完成判据取证，区分采集、受理与保存完成；失败、缺失和未知须可识别。

<a id="跨语言日志契约sdd-obs-03"></a>

## 日志契约边界（SDD-OBS-03）

日志生产方与消费方按项目契约解释事实、阶段、结果和未知值。涉及跨语言交互时，按契约核对各端的格式、编码、字段及版本兼容性。

## 日志实现规范

按项目已确认的日志能力及数据路径核对下表中的适用环节；具体字段、参数与机制取自项目契约。

| 环节 | 契约与实现要求 |
|---|---|
| 事件与结构 | 按项目记录要求列出必记事件清单，逐项明确触发条件与必需字段；定义事件身份、类型、实际发生阶段及版本化结构；重试关联同一事实，阶段与缺失语义遵循 SDD-OBS-02/03 |
| 字段与关联 | 按契约核对格式、编码、字段语义及关联标识；使用链路时明确 trace/span，关联不代表成功 |
| 级别与脱敏 | 明确敏感字段及脱敏规则，不改变实际结果语义；凭证排除及级别边界遵循 SDD-OBS-02 |
| 采集与传输 | 明确事实接入点、采集与导出接口、编码、传输边界及错误处理；采集、队列受理、传输确认和持久化回执分别判定 |
| 缓冲与失败 | 明确缓冲、容量、饱和、超时、退出、重试、恢复及缺失暴露策略，遵循 SDD-OBS-01 |
| 持久化与生命周期 | 明确存储与回执、轮转触发、保留和清理策略及失败处理；通过实际回读和故障证据判断完整性 |

事件 Schema、多语言示例及框架适配可辅助实现，不能替代项目契约或基线证据。
