# 取证与质量成本口径

本文件承接 [Spec FR-033／AC-033](../../../../specs/platform-independent-sdd/spec.md#验收条件)。每批以[报告模板](../assets/review-report-template.md)记录范围、源码与依据快照、环境和证据。复用行为证据时引用原批次，检查实际生效的源码及引用、判据、输入和环境有无影响结论的差异，记录适用性理由。

## 评估维度与口径

| 维度 | 记录内容 | 判断依据 |
|---|---|---|
| Review 矩阵 | 各受审对象及 RW 子项的结论、未查项、问题编号与证据 | 采用符合、存在偏差、证据不足、不适用四类结论；发现清单不能代替完整矩阵覆盖。 |
| 提示词 token 量 | 源码总量及入口、技能、角色、共享规则等分项；按任务记录实际加载量 | 固定文件清单、快照、tokenizer 名称及版本，源码按文件去重；实际加载按轨迹统计，重复加载另列。不把全部引用文件视为必然加载，不以字符数替代 token。 |
| 提示词质量 | 清晰性、职责与优先级、完整性、重复与冲突、可执行性、交接与完成判据 | 每项对应具体条款或行为证据，说明影响及整改建议。静态语义结论与行为验证分开；不以篇幅短、关键词齐全或无报错判为优质。 |
| 任务 token 消耗 | review 与 testcase 执行分开记录输入、缓存输入、输出、可取得的推理 token 及总量 | 使用运行时 usage，注明平台字段含义；缓存输入、推理 token 若已包含在输入或输出中，不重复相加。覆盖 Main 及子 Agent，按请求去重，注明重试、整改、复验是否包含。 |
| 任务执行时长 | 两类任务各自的开始、结束、总历时、人工等待及可分离的执行历时 | 同一批次记录时区和时间戳。总历时按墙钟计算；并行 Agent 时长不相加冒充用户等待时长。执行历时扣除可确认的人工等待，仍包含工具及调度等待；无法拆分时标明未测。 |
| 质量与成本综合判断 | 已证明的能力、主要偏差、成本证据缺口、优化优先级 | 有明确的比较目标时，在相同任务范围、用例、模型配置、环境和完成标准下比较，记录样本数及失败批次。缺可比基线只报告本批次数据和限制。 |

提示词源码体积、单次任务实际加载量和运行时累计 token 消耗分别计量。任务记录注明任务类型、批次／用例 ID、源码快照、环境、结果、统计范围和证据，分别记录工单负责人与受测 Agent 的模型及推理配置。静态审查和运行结果的分析归 review，受测用例的实际执行归 testcase。按实际可分离的阶段分别登记并关联同一批次，共享开销只归属一次，无法拆分时注明。

成本记录使用本批可取得的实测，缺少数据填“未测”并说明原因。某类任务未执行时单独记录执行状态及原因，部分计量注明覆盖范围。统计缺口不触发额外实跑或 A/B，也不改变必要的验证范围。估算单列方法；多个批次先保留逐次数据，再给样本数和范围。质量缺口与成本缺口分别判断。
