# SDD 工作流全面评审

仅在用户显式调用本 Skill 或明确请求本仓工作流全面评审时开始。文件变更、阶段完成、普通代码 Review、提示词专项审查及维护本 Skill 均不触发全面评审。审查请求本身不授权修复源码。

## 资源与产物

- 建立覆盖时读[审查判据](references/review-criteria.md)：审查规则、RW-01～RW-12 的全部子项、对象矩阵及设计／Spec 追溯。
- 取证与统计时读[质量成本口径](references/evidence-and-cost.md)，按[Review 报告模板](assets/review-report-template.md)交付。
- 需要解释设计条款时只读引用[白皮书](../../../docs/sdd-workflow-whitepaper.md)的相关章节；产品承诺查 [Spec](../../../specs/platform-independent-sdd/spec.md)。白皮书采用[结构模板](assets/whitepaper-template.md)，不承载版本评审结论；修改已确认设计须有相应决定。

默认在[工作流审查记录目录](../../../docs/test-reports/sdd-workflow/)按批次新增报告与必要证据，保留历史报告及原始证据的原版本语境。该 Skill 和模板仅属本仓，不随项目工作流分发。

## 完整流程

1. **绑定请求与版本。** 沿用有效确认，记录显式启动来源、范围、排除项、授权终点和输出位置。固定受审源码、Spec、白皮书及判据版本、环境和直接引用；快照包含影响结论的已跟踪、未跟踪和缺失文件。默认范围沿白皮书边界；受控演练可按工单使用明确缩小的合成判据，记录映射及未覆盖范围，不推定真实工作流通过。
2. **静态诊断。** 按对象矩阵核对各对象的交付闭环，覆盖全部 RW 子项及跨阶段关系。按[工单拆分与配置](#工单拆分与配置)组织独立审查。先在同一批次记录静态依据、按交付影响排序的发现和待验清单，再在已有授权内推进适用后续阶段。
3. **定向隔离取证。** 先核对已有证据是否仍适用。每个新增实跑场景须关联一个静态无法判定的关键疑点或必要验收结论，并说明选择理由和预期观测。静态证据已足以确认的偏差直接记录。主 Agent 按风险选最小可判定场景，按[工单拆分与配置](#工单拆分与配置)组织执行，参考[行为夹具](../../../tests/fixtures/skill-behavior/README.md)在获授权的独立临时工作区验证实际生效版本。验证角色独立性时仅注册受验角色。不加载或修改用户已安装工作流，受测 Skill 的执行仅用于取证。缺环境、权限或适用证据时标为证据不足，记录恢复条件并继续独立项。仅当任务明确需要判断版本差异、方案优劣或成本变化且已有证据无法回答时做 A/B。
4. **按授权修复与复验。** 沿用明确覆盖修复范围的授权，否则先交付发现、拟改对象、影响和方案供授权。只审查时受审源码、Spec 和白皮书保持只读，修改设计另需相应决定。保存改前版本与证据，记录修复版本及差异。沿原判据、原场景或有依据的等价场景复验，保持约定的实验条件，核对关联对象和受影响路径。失败在授权内修正和复验，范围变化或不可解阻塞仅暂停关联项。保留历次失败和原判据结论，获确认变更判据时记录依据。
5. **按需扩大回归。** 风险、失败或改动使关联路径仍有缺证时，按影响范围补验。需要整版行为结论时按矩阵补齐所需覆盖，必要时执行全面回归。适用证据足够即停止执行。未验范围、影响及恢复条件随结论交付，静态或局部通过不支持整版行为通过。
6. **交付报告。** 主 Agent 在同一批报告补全逐对象和逐 RW 子项覆盖、综合结论、发现与修复复验链、未验范围和质量成本。按口径使用可取得的实测，缺实测填“未测”并写明原因。交付报告路径、实际覆盖、剩余事项和恢复条件，结论限于所绑定的版本与证据。只审查时记录受审文件前后字节核对，止于报告。

## 工单拆分与配置

- 主 Agent 固定版本、共同判据和对象矩阵，负责 Main、共享治理与模板、跨对象及跨阶段的横向核对，尤其是 RW-09～RW-12。主 Agent 决定实跑范围，归并同一事实并关联受影响的对象和子项，维护同一批次报告。
- 按能独立交付的结果派单，每单由同一负责人做到取证和初判。工单互不依赖且预计收益能抵消启动、重复读取和归并成本时，可用子 Agent 并行。短小或强关联的工作合并，运行时不支持并行时由主 Agent 直接执行。
- 工单给出对象与版本、适用判据、必要依据、场景和授权边界。静态工单只读取证，提示词专项可由通用 `review-prompt` 承接。回归及对照工单在获授权的隔离环境内执行。子 Agent 回传工单结果和证据限制，由主 Agent 决定后续派单。

下表为工单负责人的推荐配置。主 Agent 按任务复杂度和运行时能力选择，无法选择时沿用可用配置，记录实际使用的模型及推理强度。

| 工单 | 粒度与产出 | 模型 | 推理强度 |
| --- | --- | --- | --- |
| 静态审查（默认） | 一个 Skill、角色或一组强关联对象一单，覆盖适用 checklist。回传依据位置、事实、影响、建议和必要的行为取证候选。明确的横向专项可按检查项派单，矩阵单元格随所属工单覆盖。 | `gpt-6.1-sol` | `high` |
| 条款与证据整理 | 成批定位条款、提取证据、整理引用。 | `gpt-6.1-terra` | `high` |
| 复杂静态审查 | 追踪跨阶段交接、规则冲突或授权边界。 | `gpt-6.1-sol` | `max` |
| 独立判断 | 关键结论经复核仍有分歧时，针对争议证据给出独立判断。 | `gpt-6-astra` | `medium` |
| 用例回归 | 一个待验证问题或一组共用夹具的场景一单。同一负责人完成准备、执行、取证和初判。 | `gpt-6.1-terra` | `high` |
| A/B 对照 | 一个明确的比较问题一单。同一负责人分别隔离运行 A、B 两侧并给出差异初判，高影响或有争议的结论由主 Agent 复核。 | `gpt-6.1-sol` | `high` |

受测 Agent 优先沿用目标环境或原用例的模型及推理强度。A/B 两侧保持受测模型、推理强度、工具和权限一致，使用可比输入及等价初始状态。
