# 对话结论落盘

输入：已确认结论或真实执行证据、授权写入范围。目标不明时通过项目 docs/index.md 定位权威正文。

1. 整理输入及适用条件，区分高位产品定义、具体需求、设计结论与执行事实，定位对应权威正文。
2. 遵循[文档写入规则](../../sdd/references/document-writing.md)，按变更对象及语义影响读取适用上游，完成归并、关联同步和写后核对；模板只提供输出结构与填写约束，不扩大职责或授权。
3. 根据事实对象分别写入：测试活动按[测试报告模板](../../sdd/assets/test_report_template.md)，问题生命周期按[Issue 模板](../../sdd/assets/issue_template.md)，架构一致性按 [Review 模板](../../sdd/assets/review_template.md)。按相应模板核对结构与填写要求；修复状态取自 imp 返回，关闭取自验收／复核执行者，Gate 取自对应流程执行者，人工确认取自用户反馈。依[权威实体](../../sdd/references/sdd-repository-governance.md#权威实体)维护正文与引用，已有记录沿用，不自动迁移历史。
4. 写后按[文档 CLI](../../sdd/references/doc-check.md)对本次修改及直接受影响的 Markdown 执行机械校验，处理或报告诊断；另行完成语义核对，不用 CLI 通过代替语义判断。
5. 输出实际落点、关键归并、检查范围与结果及待决问题。缺少确认依据时返回讨论，不自行补定。

需要角色交接时读取[执行协作](../../sdd/references/delegation.md)。普通写入不加载实施、验收或交付流程。

例：正文已有“在线请求超时 5 秒，离线任务不受此限”，对话确认在线超时改为 10 秒。原位更新为 10 秒，保留离线例外，同步引用该限制的关联条款，不追加第二份规则。
